# 2026-11-11 시험을 GitHub Actions에서도 돌리기

- PR: #83
- 문서: PRD 해당 없음(개발 환경). ADR-0014 `docs/adr/0014-tests-on-github-actions.md`. 스펙과 계획은 없다(main 세션이 넘긴 글이 범위를 정했다).

## 한 일

- GitHub Actions 워크플로 셋(서버 pytest, 앱 jest와 tsc, 훅 시험)을 더했다. PR과 main push에서, 그 부분이 바뀔 때만 돈다.
- 비공개 파일, 키, GitHub secret 없이 돈다. 먼저 저장소를 새로 클론해(비공개 파일과 `.env` 없음) 네 시험이 도는 것을 맥에서 봤다.
- 서버가 직접 import하는데 목록에 없던 `pydantic`, `httpx2`를 `server/pyproject.toml`에 넣었다.
- 첫 실행이 드러낸 둘을 고쳤다: 서버 준비물에 빠져 있던 ffmpeg, 맥의 도구 위치에 기댄 launchd 설치 스크립트 시험.
- README 맨 위에 시험 상태 배지 셋을 넣었다. ADR-0014를 썼다.

## 바로잡은 것

- **맥에서만 돌려 본 시험이 맥에 기대고 있었다.** 새 클론에서는 비공개 파일과 키만 뺐을 뿐 같은 맥이라, 맥에 깔린 ffmpeg와 그것이 깔린 폴더에 기댄 것은 드러나지 않았다. Actions 첫 실행에서 서버 시험 229개가 ffmpeg가 없어 실패했고, ffmpeg를 깔자 launchd 시험 하나가 실패했다. 서버 준비물을 README에 적고 시험을 고쳤다. 새 환경에서 돌리는 일이 이것을 잡으려는 것이라, ADR-0014 「영향」에 적었다.
- **PR 본문에 경로 거르기를 잘못 적었다.** 「마지막 커밋들이 문서라 PR 화면에는 마지막으로 돈 커밋의 체크만 보인다」고 썼는데, 문서만 고친 커밋에서도 셋이 다 돌았다. PR 이벤트의 경로 거르기는 마지막 push가 아니라 PR 전체의 바뀐 파일로 판단한다. 실행 목록(`gh run list --branch ci/test-workflow`)을 보고 본문을 고쳤다.
- **devlog를 리뷰를 띄운 뒤에 써서 PR에 없었다.** pr-review의 스펙 대조가 「본문은 devlog를 가리키는데 diff에 없다」를 실제 문제로 냈다. `REVIEW.md` 「넘길 것」에 같은 줄이 있지만 그 기준은 코드 축만 받는다. 초안을 리뷰 전에 커밋했으면 나오지 않았다.

## 검증

- 새 클론(비공개 파일과 `.env` 없음)에서: 훅 `node --test 'scripts/**/*.test.mjs'` 54 passed, 서버 `uv run --frozen pytest -q` 1017 passed / 4 skipped, 앱 jest 491 passed, `npx tsc --noEmit` 오류 없음.
- Actions(`ubuntu-slim`): 훅 성공 30초, 앱 성공 1분 35초(캐시 없는 첫 회), 서버는 두 번 실패한 뒤 성공 2분 22초(1018 passed, 5 skipped).
- 맥에서 고친 서버 시험: 1019 passed, 4 skipped.
- 캐시가 든 뒤(커밋 47403ab): 서버 2분 34초, 앱 1분 11초, 훅 25초. uv 캐시는 액션 기본값(`enable-cache: auto`)으로 저장되고 다음 실행에서 복원됐다(`gh cache list`).

## 리뷰

- PR 리뷰(pr-review, Full): 코드 축 리뷰어 다섯이 모두 지적 없음. 스펙 축(PR 본문, 약) 셋: devlog가 diff에 없음(실제 문제, PR 코멘트로 게시, 이 일지를 커밋해 고침), 「uv 캐시」를 파일만으로는 확인 못 함(표현 차이, 실행 기록으로 확인하고 본문에 「액션 기본값」이라 적음), ADR 색인 한 줄이 본문에 없음(표현 차이, 본문에 적음).
- `REVIEW.md`: 고칠 것 없음. 스펙 축은 `REVIEW.md`를 받지 않는 것이 스킬의 설계라, 위 「바로잡은 것」대로 devlog를 먼저 커밋하는 쪽으로 막는다.
