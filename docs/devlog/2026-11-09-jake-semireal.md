# 2026-11-09 제이크를 반실사 그림체로 다시 만들고 앱 그림 바꾸기

- PR: #79
- 문서: PRD의 상황 연습(제이크 추천 화면, 기다리는 얼굴)과 말하는 영상의 바탕 그림. 스펙과 계획은 없다(그림 작업과 고침). 가이드 `docs/guide/ASSET_제미나이로_얼굴_그림_만들기_20261106.md` 「그림체를 바꿔 다시 만들고 앱 그림 바꾸기」와 문제 9~11, `docs/guide/DEVENV_폰을_adb로_시험하기_20261108.md` 「폰의 Tailscale이 꺼져 있었는데 ping은 답이 왔다」.

## 한 일

- 제이크 그림을 라이언, 소희와 같은 반실사 그림체로 다시 만들었다. AI가 만든 그림이고, 그림 파일과 만든 과정은 비공개 폴더와 비공개 메모에 있다. 새 그림을 「온라인 제이크」, 옛 3D 느낌의 그림을 「제이크 애니」라고 부르기로 했다(사용자가 정함).
- 기본 얼굴을 넓혀 무릎 위 그림과 전신 그림, 각각의 512×768판을 만들어 강의 영상 세션에 넘겼다.
- 앱 그림(첫 화면 얼굴, 생각하는 얼굴 둘)을 온라인 제이크로 바꾸기로 했다. 첫 화면 얼굴은 앱 동그라미 자리(`FACE_BOX`)에 맞춰 옮겼고, 생각하는 얼굴은 그 그림을 올려 만든 뒤 같은 네모로 잘랐다. 제이크 애니는 비공개 폴더에 이름을 붙여 보관했다. 앱 그림 파일은 머지 뒤에 바꾼다.
- 같은 이름으로 그림을 바꾸면 폰이 옛 그림을 계속 보여 줄 수 있어, 맥 서버가 `/home`의 그림 주소에 파일 수정 시각을 붙이게 고쳤다(`server/je_server/app.py`).
- 가이드에 겪은 문제를 더했다.

## 바로잡은 것

- **비교 페이지가 그림을 늘려 보여 줬다.** 후보 넷 중 셋이 설명 글 폭만큼 가로로 23% 늘어나 있었고, 사용자는 그것을 보고 얼굴형을 판단했다. flex의 `align-items: stretch` 탓이다. 고쳐 다시 띄웠고, 가이드 문제 9에 「띄운 뒤 그림마다 원래 비율과 보이는 비율을 견준다」를 적었다.
- **눈대중으로 잰 얼굴 길이를 그대로 알렸다.** 격자를 대고 눈대중으로 재, 후보들이 턱이 짧다고 사용자에게 먼저 말했다. 눈동자 사이 거리로 크기를 맞춰 다시 재니 차이는 5% 안이었고, 짧아 보인 것은 앞머리 탓이 컸다. 정정해 알렸고, 가이드 문제 10에 견주는 방법을 적었다. 다음에는 크기를 맞춘 뒤의 값만 알린다.
- **앱 그림을 같은 이름으로 바꾸려 했다.** 폰의 그림 캐시가 주소로만 찾는다는 것을 main 세션이 짚기 전까지 보지 못했다. 서버를 고치고 가이드 문제 11에 적었다.
- **생각하는 얼굴 두 번째를 맞춘 값이 찾는 범위 끝에 걸렸다.** 고개를 기울인 그림을 머리카락 네모로 맞추자 옆으로 24픽셀 밀렸다. 머리 전체의 윤곽으로 다시 재 옮기지 않기로 했다. 가이드에 적었다.
- **폰이 맥에 닿지 않을 때 ping만 보고 연결됐다고 볼 뻔했다.** 폰의 Tailscale이 꺼져 있었는데 ping은 답이 왔다. TCP로 보고 맥의 `tailscale status`에서 찾았다. 폰 시험 가이드에 적었다.

## 검증

- `cd server && uv run pytest -q`: 1017 passed, 4 skipped. 새 시험 셋 중 둘은 구현 전에 「`?v=` 없음」으로 실패하는 것을 봤다.
- 머지 전 폰 기준 화면: 지금 앱에서 상황 추천을 한 번 받아(추천 모델 호출 1회), 기다리는 동안 생각하는 얼굴과 추천 확인 동그라미에 제이크 애니가 나오는 것을 찍었다. 「이걸로 할게요」는 누르지 않고 나왔다. 그전 두 번은 폰의 Tailscale이 꺼져 맥에 닿지 않았다(모델 호출 없음).
- 그림: 마크를 지운 판은 원본과 다른 곳이 마크 둘레 네모 안뿐인지 보고, 밝기를 올려 크게 봤다. 비교 페이지는 그림마다 원래 비율과 보이는 비율이 같은지 봤다.
