## 한 일

- 사용자가 폰에서 써 보고 말한 것을 main 세션이 넘겼다. 진행하다 첫 화면으로 돌아오면 라이언이 「안녕하세요, 라이언입니다」부터 다시 해서 이상하다는 것이다.
- 원인: 화면을 바꾸면 첫 화면이 다시 올라오고, 올라올 때마다 `/home`을 받아 인사를 틀었다.
- 맥 서버: 고정 문구 `ask_again`(「이번에는 어떤 방식으로 대화해 볼까요?」)을 더하고 `/home`으로 내준다.
- 앱: 첫 화면이 열릴 때 `home`을 이미 받아 두었으면 돌아온 것으로 본다. 그때는 `ask_again` 하나만 틀고 화면 글도 그 한 줄이다. 고르는 규칙은 `app/src/flow/homeLines.ts`에 있다.
- pr-review(리뷰어 6명): 코드 축은 0건이었다. 스펙 축은 「표현 차이」 2건이라 고치지 않았다(아래 표).

## 바로잡은 것

- **커밋 제목이 75자라 commit-msg 훅에 막혔다:** 가이드 커밋이다. 제목을 줄여 다시 커밋했다. 그 커밋 뒤에는 `git log`만 있어서 엉뚱한 명령이 돌지는 않았다.
- **빈 모듈로 「실패」를 보려다 오류를 봤다:** 시험부터 쓰고 돌리니 모듈이 없다는 오류가 났다. 이것은 시험이 실패한 것이 아니다. 빈 배열을 돌려주는 함수를 먼저 두고 시험 3개가 실패하는 것을 본 뒤에 구현했다.
- **`REVIEW.md`는 고치지 않았다:** 되풀이된 오탐도, 리뷰가 놓친 것도 없었다.

## 검증

- `cd server && uv run pytest -q` → 208 passed. 새 문구 시험과 `/home` 목록 시험은 고치기 전에 `KeyError: 'ask_again'`로 실패하는 것을 봤다.
- `cd app && npx jest` → 15 suites, 101 passed. `homeLines` 시험 3개는 빈 함수에서 먼저 실패하는 것을 봤다.
- `cd app && npx tsc --noEmit` → 오류 없음.
- 폰(이 브랜치로 만든 APK, 이 worktree의 서버): 에이전트가 adb로 조작하며 확인했다. 화면 글은 `uiautomator dump`로 읽었다. 소리는 `logcat`의 `AudioTrack stop(...) called with N frames delivered`를 소리 파일의 샘플 수에서 앞 2112를 뺀 값과 맞대어 셌다. 인사는 86016 샘플(3.58초), 두 묻는 말은 둘 다 54272 샘플이다. 「오늘은…」과 「이번에는…」은 길이가 같아 소리만으로는 가르지 못하고, 같은 `homeLines` 결과를 쓰는 화면 글로 가렸다.
  - 앱을 새로 띄움: 화면 글은 인사와 「오늘은 어떤 방식으로…」 두 줄이었다. 소리는 83904, 52160 프레임 두 개가 끝까지 나왔다.
  - 상황 정하기에서 뒤로가기로 돌아옴: 화면 글은 「이번에는 어떤 방식으로 대화해 볼까요?」 한 줄이었다. 소리는 52160 프레임 하나였다.
  - 홈 키로 15초 뒤로 보냈다가 다시 엶: 화면은 그대로였고 소리는 나지 않았다.
  - 직접 쓴 상황으로 역할극을 시작하고 「처음으로」, 「그만두기」로 돌아옴: 상황 정하기에서 돌아올 때와 같았다(한 줄, 52160 프레임 하나).
