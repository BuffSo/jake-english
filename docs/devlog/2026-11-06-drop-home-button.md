## 바로잡은 것

- **PR #21을 머지했는지 잘못 알렸다.** 사용자가 「머지해줘」라고 한 뒤 「잠깐만」 하고 머지 명령을 거절했다. 그런데 명령은 이미 실행돼 PR #21이 머지돼 있었다. 상태를 보기 전에 「아직 머지하지 않았다」고 답했고, 바로 다음에 확인하고 바로잡았다. 거절된 명령이라도 바깥 상태를 바꾸는 것이면, 결과를 말하기 전에 실제 상태(`gh pr view`)부터 본다.
- **폰이 잠겼다고 잘못 말했다.** 화면이 꺼진 상태에서 앱 화면을 읽지 못해 「잠금을 풀어 달라」고 했다. 실제로는 화면만 꺼져 있었다. 화면 상태는 `dumpsys power`의 `mWakefulness`로 보고, 잠금 여부는 따로 확인한 뒤에 말한다.

## 검증

- `cd app && npx jest` → 98 passed. 화면을 떠나는 시험 두 개(`askFirst`, `leavesScreen`)를 인자 하나로 먼저 고쳤고, `leavesScreen`이 고치기 전에 실패하는 것을 봤다.
- `cd app && npx tsc --noEmit` → 오류 없음
- 이 브랜치의 릴리스 APK를 폰에 깔았다.
- 리뷰어 하나가 「아래 칸이 생기고 사라지면서 대화 칸 높이가 바뀐다」고 메모했다. 역할극 화면은 단계(`phase`)가 바뀔 때마다 50ms 뒤에 끝까지 스크롤하고, 아래 칸이 생기는 것도 단계가 바뀌는 그 순간이다. 코드로는 맞춰지는 것을 확인했고, 폰 확인 목록에 넣었다.
- pr-review: 코드 축 0건(경계선 0건). 스펙 축은 표현 차이 1건(아래 칸을 버튼이 있을 때만 그리는 것은 요청에 없던 동작)이라 고칠 것이 없었다. PR에는 「걸린 것 없음」으로 게시.
