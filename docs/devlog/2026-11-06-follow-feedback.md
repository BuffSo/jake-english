## 바로잡은 것

- **스펙에 쓴 예를 코드가 지키지 않았다:** 스펙 「평가」 2에 「one thousand의 1,000」을 같게 본다고 적어 놓고, 코드는 99까지만 낱말로 바꿨다. 최종 리뷰의 판단 기록에도 「100 이상은 그대로 둔다」고 적어, 스펙과 기록이 어긋났다. PR을 올리기 직전에 스펙의 예를 하나씩 돌려 보다가 찾았다. 그 뒤로 스펙에 적은 표기 예는 모두 시험(`test_numbers_past_ninety_nine_are_not_differences`)에 넣었다.
- **최종 리뷰가 놓친 입력을 PR 리뷰가 잡았다:** 대사에 적힌 군말, a hundred와 $100, 서수, 더한 낱말을 고친 뒤의 칭찬이다. 셋은 버그 훑기에서, 하나는 스펙 대조에서 나왔다. 최종 리뷰는 표기 맞추기의 「받아쓴 쪽」만 봤다. 「대사 쪽에 같은 것이 있으면?」은 보지 않았다. 가이드 「넓힌 뒤 리뷰에서 찾은 헛짚기」에 원인과 함께 적었다.
- **커밋 제목이 73자라 막혔다:** commit-msg 훅이 막았다. 뒤의 커밋을 `&&`로 이어 두어서 엉뚱한 커밋이 생기지 않았다. PR #15에서 정한 「커밋 뒤 명령은 `&&`로」가 이번에 제 몫을 했다.
- **열린 PR 사이에 main이 움직였다:** PR #16이 앱의 같은 타입 파일을 고쳐 `Issue` 타입 한 줄이 겹쳤다. main을 브랜치에 합쳐 풀고(rebase와 force push는 하지 않음), 합친 뒤 시험을 다시 돌렸다.
- **`REVIEW.md`는 고치지 않았다:** 되풀이된 오탐이 없었다. 리뷰가 놓쳤다가 나중에 드러난 문제도 없었다(최종 리뷰가 놓친 것은 같은 PR의 리뷰가 잡았다).
