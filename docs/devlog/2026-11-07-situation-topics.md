# 2026-11-07 상황 주제 고르기와 미리 써 둔 목록

- PR: #28
- 문서: PRD 「첫 판: 말하기」의 「상황 정하기」와 사용자 이야기 셋. 스펙 `docs/superpowers/specs/2026-11-07-situation-topics-design.md`, 계획 `docs/superpowers/plans/2026-11-07-situation-topics.md`. ADR은 없다(기록에 기본값이 있는 필드 하나를 더해 옛 기록을 그대로 읽는다, 스펙 7).

## 한 일

- 상황 정하기에서 주제를 먼저 고른다: 「외국인 관광객」, 「미국 여행」, 「그 밖의 상황」. 주제가 라이언과 나의 역할을 정하고, 대본과 제이크 추천에 함께 간다.
- 주제 안에서 정하는 길이 셋이다: 「목록에서 고르기」(목록이 있는 주제만), 「제이크에게 추천받기」, 「직접 말하거나 쓰기」.
- 주제마다 3개씩 미리 써 둔 상황 목록을 맥 서버에 뒀다(`server/je_server/topics.py`). 실제 장소, 가게, 메뉴가 들어가고, 사실은 웹에서 확인했다. 앱은 목록 줄의 id만 보내고 설명은 맥이 찾는다.
- 대본의 처음과 끝 사람을 상황에 맞게 바꿨다. 「외국인 관광객」은 늘 라이언이 먼저, 목록의 상황은 적힌 사람이 먼저다. 실제 상호는 쓰고, 출구 번호나 영업시간은 지어내지 않게 했다.
- 역할극 기록에 주제를 남기고, 제이크는 같은 주제의 최근 상황을 피한다. 역할극에서 뒤로를 누르면 상황을 고른 단계로 돌아온다.
- PRD, 스펙, 계획, 구현을 PR 하나로 했다. 사용자가 결과 화면을 빨리 보고 싶다고 해 나누지 않았다.

## 바로잡은 것

- **커밋이 막혔는데 기록이 먼저 적혔다:** 커밋 메시지 검사(첫 줄 72자)에 걸려 커밋이 안 됐는데, 같은 명령에 이어 쓴 작업 완료 기록이 빈 범위로 적혔다. review-practice 카드에서 겪고 「`&&`로 잇는다」고 적었던 일인데 줄바꿈으로 이어 또 겪었다. 기록을 지우고 다시 커밋했다.
- **막힌 커밋의 파일이 다음 커밋에 섞였다:** 가이드 커밋이 같은 이유로 막혔고, 줄바꿈 뒤의 REVIEW.md 커밋이 이미 스테이징된 가이드 파일까지 담았다. push 전이라 그 커밋을 풀어(`reset --soft`) 둘로 다시 나눴다. 커밋 여러 개를 한 명령에 쓸 때는 앞 커밋이 성공해야 다음이 돌게 잇는다. 에이전트 작업 환경의 일이라 메모리에도 남겼다.
- **계약 예시를 고치고 앱 테스트를 보지 않았다:** `contract/roleplay.json`에 `topic`을 더한 서버 커밋 본문에 「앱 테스트 그대로」라고 썼는데, 앱의 계약 테스트(`roleplay example has the keys the app reads`)가 실패하고 있었다. 다음 커밋에서 앱 타입에 `topic`을 더해 고쳤다. `contract/`는 서버와 앱이 같이 읽으니 둘 다 돌린다.
- **최종 리뷰(브랜치 전체)가 짚은 것:** 새 앱이 옛 맥 서버(`topics`가 없는 `/home`)에 붙으면 상황 화면을 그리다 멈췄을 것이다. 카드가 폰 시험 뒤 원래 서버를 되돌리면 생기는 일이다. 「그 밖의 상황」만으로 열리게 고치고 가이드에 남겼다(`docs/guide/APP_Expo_앱_뼈대와_서버_연결_20261105.md`). 제이크의 고정 지시문에 남아 있던 관광객 장면 예시(케이블카)는 리뷰어가 Minor로 봤지만, 미국 여행 추천을 관광객 쪽으로 끌 수 있어 사용자가 이 기능을 원한 이유와 맞서므로 중요로 다시 매겨 뺐다. 주제마다의 예시만 남겼다.
- **PR 리뷰가 짚은 것:** 새 목록 카드를 빨리 두 번 누르면 대본 요청이 두 번 갈 수 있었다. PR #12, #15, #18에 이어 네 번째다. 45점이라 게시되지 않았지만, 가이드의 「같은 실수를 막는 방법」을 어긴 것이라 고쳤다. 단계를 ref에도 바로 적고, 기다리는 동안은 요청 함수가 바로 돌아간다. 리뷰 규칙이 이 문제를 이름으로 부르지 않아 점수가 낮았으므로, `REVIEW.md` 「반드시 지적할 것」에 넣었다. 스펙 축의 표현 차이(PRD에만 있던 쇼핑몰 이야기)는 스펙의 「왜 만드나」에 사용자 말을 더해 맞췄다.

- **폰이 없다고 확인을 미뤘다:** 사용자가 외출한 동안 폰이 꽂혀 있지 않아 화면 확인을 미뤘다. 에뮬레이터는 모두 다른 프로젝트 것이라 쓰지 않았는데, 이 앱 전용 에뮬레이터를 만들면 됐다. 사용자가 짚은 뒤 이 앱 전용 에뮬레이터를 만들었고, 폰이 없을 때는 그것으로 확인하라고 메모리에 남겼다(에이전트 작업 환경의 일이라 가이드가 아니라 메모리).
- **「상황에 맞게」가 실제로는 늘 라이언이었다:** 규칙은 둘 다 끝낼 수 있게 바꿨지만, 실제 대본 다섯 개가 모두 내 끝인사에 라이언이 「You too!」로 답하며 끝났다. 테스트는 가짜 응답이라 이것을 볼 수 없었다. 라이언이 인사만 되받을 거면 그 줄을 빼고 내 대사에서 끝내게 지시문을 고쳤다.
