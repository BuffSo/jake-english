- 연습을 받아 오는 동안 ★는 확인 창을 열지 않는다.

사용자는 계획을 쓴 뒤 「나 잘거야.. 최대한 진행할 수 있는데 까지 진행해」라고 했다. 그 뒤 main 세션이 「머지는 하지 말고, 정할 것은 AI 추천으로 진행한 뒤 PR 본문에 「사용자 확인 필요」로 적고, 폰 시험은 아침으로 미뤄 달라」고 전했다. 그래서 아래의 「사용자 판단」 칸이 대부분 비어 있고, PR 본문에 「사용자 확인 필요」로 적었다.

## 바로잡은 것

- **Bash로 쓴 파일에도 보이지 않는 글자가 그대로 들어갔다:** 메모리에는 「Write 도구가 이스케이프를 풀어 쓴다」만 있었다. 이번에는 Bash의 heredoc(`cat <<'EOF'`)으로 `keepWords.ts`를 쓰다 같은 일이 생겼다. 도구 입력 자체가 이스케이프를 푸는 것이다. 테스트가 통과한 뒤 파일을 검사하다 찾았고, python에서 `chr(92)`로 이스케이프를 만들어 바꿨다. 메모리를 「도구 입력은 모두 그렇다」로 고쳤다.
- **커밋 본문에 확인하기 전의 일을 「확인했다」고 적었다:** 화면에 잇는 커밋 셋의 본문에 「checked on the emulator」를 에뮬레이터를 보기 전에 썼다. 브랜치 리뷰가 짚었다. push 전에 에뮬레이터 확인을 마쳐 사실이 됐지만, 소희의 통역과 라이언의 평가는 보지 못했다(아래 「검증」). 이 일지와 PR 본문이 실제로 본 것만 적는다. 커밋 본문의 「Tested:」 줄에는 이미 돌린 것만 쓴다.
- **계획의 확인 방법이 되지 않는 방법이었다:** 지난 상황 탭을 맥 서버 기록의 `GET /past` 수로 보려 했는데, 서버는 요청 기록(access log)을 끈다. 가이드의 확인 방법을 화면 캡처와 `grep`으로 고쳤다.
- **계획은 할 일 파일을 문서 커밋에 넣으라 했다:** 그 뒤에도 리뷰 수정과 이 일지가 오니 이 일지 커밋으로 옮겼다(PR #32와 같다). PR 리뷰의 스펙 축이 「누락」으로 짚었고, 이 커밋으로 풀린다.
- **스펙과 가이드의 목록이 어긋났다:** 들린 말을 감싼 뒤 스펙 7과 가이드의 「거치는 곳」 목록에 적지 않았다. PR 리뷰의 스펙 축이 짚어 두 목록을 맞췄다.
