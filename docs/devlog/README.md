# devlog

기능 하나(PR 하나)를 끝낼 때 쓰는 작업 일지다. AI가 무엇을 추천했고 사용자가 무엇을 정했는지, 에이전트가 무엇을 잘못해서 무엇을 더했는지 남긴다. 다른 프로젝트를 시작하는 방법을 정할 회고의 재료다. 규칙은 `AGENTS.md` 「작업 일지: devlog」에 있다.

## 파일

- 이름은 `YYYY-MM-DD-<영어-주제>.md`다.
- PR 리뷰로 고친 뒤, 머지 결정을 묻기 전에 같은 PR에 커밋한다.
- 새 일지를 쓰면 아래 「목록」에 한 줄 더한다.

## 양식

```markdown
# YYYY-MM-DD 제목

- PR: #N
- 문서: PRD의 어느 기능인지, 스펙, 계획, ADR (없으면 없다고 쓴다)

## 한 일

## 흐름

| 정할 것 | AI 추천 | 사용자 판단 | 결과 |
|---|---|---|---|

## 바로잡은 것

에이전트가 잘못한 것과, 그것을 막으려고 더한 규칙이나 장치.

## 검증

돌린 명령과 결과.

## 다음
```

## 쓰지 않는 것

- 대화 원문. 요약만 쓴다.
- 바꾼 내용의 나열. 커밋에 있다.
- 되돌리기 어려운 결정. ADR에 쓴다.
- 다음에도 따를 기준과 겪은 문제의 해결. `docs/guide/`에 쓴다.
- 개인 정보, 개인 환경, 참고 앱 이름. 공개된다.
