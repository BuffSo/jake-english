# 2026-11-08 자유 대화와 대화 뒤 고쳐 주기 (PR 1)

- PR: #66
- 문서: PRD 「첫 판: 말하기」의 자유 대화, 「고쳐 주기」, 「평가」의 자유 대화, 「첫 화면」. 스펙 `docs/superpowers/specs/2026-11-08-free-talk-design.md`(PR 1은 「정한 것」 1~8), 계획 `docs/superpowers/plans/2026-11-08-free-talk-pr1.md`. ADR은 없다(스펙 8에 까닭).

## 한 일

- 스펙을 쓰기 전에 지금 구조로 한 차례가 얼마나 걸리는지 쟀다. 첫 문장이 나오는 대로 목소리를 만들면 맥 안 첫 소리가 6.7초에서 3.9초로 준다. 자동 언어 받아쓰기는 맥의 지난 영어 녹음 54개 중 14개를 한국어로 알아들었다.
- 첫 화면에 「자유 대화」 카드(보라)를 더했다. 누르면 라이언이 미리 써 둔 영어 질문을 하고, 내 영어에 라이언이 짧게 답하며 다음 질문을 한다. 첫 문장부터 소리가 난다. 라이언이 말하는 중에 「🎤 말하기」를 누르면 라이언 소리가 멈추고, 듣지 않은 뒷문장은 흐려진다. 다음 답을 만들 때 Claude에 어디서 끊겼는지 알린다.
- 「말하기」는 영어로만 받아쓴다. 한글이 섞여 나오면 한국어로 다시 받아써, 라이언이 영어로 「Could you try that in English? Short is fine.」라고 답한다. 처음에는 같은 뜻의 한국어였다. 사용자가 「자유 대화에서는 라이언은 영어만 해야 하는 게 맞다」고 해 PR 안에서 바꿨다.
- 「대화 끝내기」를 누르면 Claude가 어색했던 곳을 많아야 셋 고르고, 맥이 거른다(12낱말, 한 차례에 하나, 발음 짐작은 소리 설명 목록에 있는 소리만). 「대화 돌아보기」에서 하나씩 설명을 듣고, 고친 문장을 세 줄로 보고 따라 말해 평가를 받는다. 그때의 내 녹음은 눌러야 들린다. 고친 문장은 ☆로 「모아 둔 문장」에 모은다.
- 자유 대화 기록은 역할극 기록에 종류(`kind: "talk"`)를 더해 같은 곳에 둔다. 「지난 상황」, 이어 하기, 복사, 최근 상황에서는 빠진다.

## 바로잡은 것

- **스펙에 버튼 자리를 누가 정했는지 잘못 적었다.** 첫 화면 말하기 버튼을 「사용자가 추천과 달리 골랐다」고 썼는데, main 세션이 바꿔 추천한 것을 사용자가 받아들인 것이었다. main 세션이 짚어 고쳤다.
- **초안의 버튼 순서가 거꾸로였다.** 대화 화면 초안을 「🎤 말하기 | 대화 끝내기」로 그렸다. 사용자가 짚었고, main 세션이 버튼 가이드에 「주된 버튼은 오른쪽」의 까닭(오른손 엄지)을 더했다. 계획은 이미 그 순서였다.
- **고쳐 주기가 맞는 영어를 고쳤다.** 실제 Sonnet으로 지어낸 대화를 돌리니 21번 중 5번이 맞는 문장의 말투만 바꿨다(「I am」→「I'm」). 지시문에 「맞고 자연스러운 문장은 말투만 바꾸지 않는다」를 넣어 14번 중 2번으로 줄었다. 「ate lunch」→「had lunch」 하나는 남아 PR 한계에 적었다. Haiku가 지시문의 틀 글을 그대로 쓴 것을 보고, 소리 짐작 문장에 두 낱말이 다 없으면 버리게 했다.
- **실제 폰에서 첫 화면 세 번째 카드가 잘렸다.** 브라우저 초안과 단위 시험으로는 볼 수 없었다. 스펙에 정해 둔 대로 첫 화면의 라이언 그림을 줄였다.
- **라이언이 말하는 중에 「대화 끝내기」를 누르면 남은 문장이 다시 났다.** 브랜치 최종 리뷰가 찾았다. 끝내기가 차례를 넘기지 않아 늦게 온 소리 이벤트가 대기열에 들어갔다. 「🎤 말하기」처럼 끝내기도 차례를 넘기게 고쳤고, 에뮬레이터에서 첫 문장과 둘째 문장 중에 끝내 확인했다. 계획에도 같은 빈틈이 있었다.
- **계획의 커밋 제목이 72자를 넘었다.** commit-msg 훅이 막아 구현 에이전트들이 줄였다. 계획을 쓸 때 제목 길이를 세지 않았다.
