## 바로잡은 것

- **리뷰 코멘트가 군더더기를 남겼다.** 스펙 축은 점수가 없고 「보고 전량 게시」였다. 그래서 「누락: 없음」, 리뷰어 스스로 「경미하다」, 「오류는 아니다」라고 적은 항목까지 PR에 올라갔다. 첫 줄이 「50점을 넘은 항목이 없습니다」로 시작해, 기준에 못 미친 것을 굳이 올린 것처럼 읽혔다.
  - 더한 장치: pr-review 스킬(전역)에서 스펙 축 리뷰어가 항목마다 판정(`실제 문제` / `표현 차이`)을 붙이고, 실제 문제만 게시한다. 없는 분류는 쓰지 않는다. 코멘트 첫 줄에서 점수 기준 문구를 뺐다.
- **PR 본문을 커밋에 맞추지 않았다.** devlog를 더한 뒤에도 본문 「문서」에 「리뷰 뒤 이 PR에 더한다」가 남았다. 확인할 에이전트를 바꿀 때도 devlog만 고치려 했고, 사용자가 테스트 체크리스트를 짚었다. 다시 읽어 보니 「배경」은 아르곤이 `AGENTS.md`를 읽는다고 적어 「한계」(확인하지 않았다)와 어긋났고, 「요약」은 `REVIEW.md`가 모든 리뷰어에게 간다고 적었지만 스펙 축 리뷰어는 받지 않는다. 네 곳을 지금 상태에 맞췄다. 막는 규칙은 아직 더하지 않았다.
- **`REVIEW.md` 「고치는 방법」 점검:** 코드 축은 오탐이 없어 「넘길 것」에 넣을 것이 없었다. 스펙 축 군더더기는 `REVIEW.md`가 아니라 스킬에서 고칠 일이었다. 스펙 축 리뷰어는 `REVIEW.md`를 받지 않는다.
