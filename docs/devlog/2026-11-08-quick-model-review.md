# 2026-11-08 짧은 말 모델을 견주고 제이크 추천만 Sonnet으로

- PR: #46
- 문서: PRD 「첫 판: 말하기」의 「상황 정하기」(제이크 추천), 「통역」, 「평가」. 계획 `docs/superpowers/plans/2026-11-08-quick-model-review.md`. 고친 스펙은 말하기 스펙 「기다리는 시간과 모델」, 상황 주제 스펙 4, 통역 스펙 「제약」이다. ADR-0004 「영향」에 한 줄을 더했다(새 ADR 없음). 새 가이드 `docs/guide/PROMPT_일마다_모델_견주기_20261108.md`. 할 일 21, 24를 닫았다.

## 한 일

- 짧은 말 모델이 맡던 세 일(소희 통역, 제이크 추천, 라이언 평가)을 지어낸 같은 입력으로 Haiku와 Sonnet에 견줬다. 약 300번 불렀고 0.61달러가 들었다.
- 제이크 추천만 Sonnet으로 바꿨다. 새 설정 `JE_CLAUDE_RECOMMEND`(haiku, sonnet, 기본 sonnet)를 두었다. 통역과 평가는 `JE_CLAUDE_QUICK`(Haiku) 그대로다. 서버 로그의 모델 줄에 추천 모델을 더했다.
- 추천 답에 메시지의 이름표(「주제:」, 「예:」, 「끝말:」)가 따라 나오면 서버가 걷어 낸다(할 일 21, `drop_labels`). 끝 부호에 붙은 이름표도 걷는다.
- 견주기 스크립트를 저장소에 두었다(`server/scripts/compare_quick_models.py`).
- `check_jake_recommend.py`는 추천 모델로 돌고(`--model`), 서버처럼 지어낸 최근 상황 열 개를 함께 보낸다.

## 바로잡은 것

- **견주기 입력이 서버보다 쉬웠다:** 처음에는 지어낸 최근 상황을 둘만 보냈다. Haiku의 이상한 추천은 21번 중 2~3번이었다. 서버 녹음 시험에서 실제 기록(최근 열 개)으로 받은 넷 중 둘은 지시문 말투를 그대로 말했다. 지어낸 최근 상황을 열 개로 늘려 다시 견주니 Haiku는 7번이었다. 앞 카드의 추천 스크립트는 최근 상황을 하나도 보내지 않아, 실제 서버에서만 나온 「끝말:」 따라 쓰기를 한 번도 보지 못했었다. 견주기 입력은 서버가 그 일에 보내는 메시지를 코드에서 읽고 그대로 만들자는 것을 가이드에 적었다.
- **모델 탓으로 볼 뻔했다:** 녹음 시험에서 라이언이 대사에 없는 낱말을 짚었다. `--keep`으로 남긴 복사본을 열어 보니, PR #44 뒤 목록 상황의 복사본은 새 대본을 써서 녹음이 간 대사가 스크립트가 찍은 원본 대사와 달랐다. 맥과 Haiku는 바르게 짚었다. 모델 탓으로 보기 전에 모델에 간 입력을 먼저 보자는 것을 가이드에 적었다. 스크립트 고치기는 원래 폴더 `docs/todo/20261108_25_todo_try_recordings_copy_line.md`로 남겼다.
- **커밋 하나가 혼자서는 돌지 않았고 시험 수가 틀렸다:** 견주기 스크립트 커밋이 다음 커밋에서 생기는 `check_jake_recommend.RECENT`를 썼다. 두 커밋 모두에 마지막에 돌린 시험 수(460)를 적었는데, 앞 커밋의 트리는 457이었다. 마지막 리뷰가 찾았다. push 전이라 두 커밋의 순서를 바꾸고, 각 커밋의 트리로 다시 돌려 수를 고쳤다(457, 460). 커밋에 적는 수는 그 커밋의 트리에서 돌린 값이어야 한다.
- **마지막 리뷰(Opus 한 명)가 찾은 것:**
  - 상황 주제 스펙에 더한 이름표 줄이 끝말 줄과 그 아래 줄들 사이에 끼어, 끝말 규칙이 이름표 아래로 보였다.
  - 옛 가이드가 `check_jake_recommend.py`의 비용을 Haiku 값(0.3센트)으로 적고 있었다. 기본이 Sonnet이 되어 6.5센트다.
  - 이름표가 끝 부호에 붙으면(「…봤어요.끝말:」) 걷지 못해 제이크가 「끝말」을 말할 수 있었다. 처음 실패하는 시험을 보고 고쳤다.
  - README가 스크립트가 이름표를 본다고 적었고, 견주기 스크립트 설명이 추천도 번갈아 묻는다고 적었다. 둘 다 실제와 달라 문장을 고쳤다.
- `REVIEW.md`: 고치지 않았다. PR 리뷰의 스펙 축이 「devlog가 아직 없다」를 게시했다. 코드 축에는 이것이 「넘길 것」에 있지만, 스펙 축은 스킬 설계상 `REVIEW.md`를 받지 않는다. 이번에는 할 일 파일의 상태 줄이 devlog 경로를 먼저 적어 걸렸다. 다음부터 할 일의 상태 줄에는 아직 없는 devlog 경로를 적지 않는다.

## 검증

- `cd server && uv run pytest -q` → 469 passed(PR #45를 합친 뒤). 새 시험은 모두 먼저 실패하는 것을 봤다.
- `node --test 'scripts/**/*.test.mjs'` → 54 pass
- 견주기(실제 모델, 지어낸 입력): 약 300번, $0.61.

  | 일 | 품질 | 기다림(중앙값) | 한 번 값 Haiku → Sonnet |
  |---|---|---|---|
  | 소희 통역(12줄 × 2) | 비슷. Sonnet은 관용 표현 둘이 더 자연스럽고, 없는 말을 두 번 더했고, 사이즈 하나를 잘못 바꿨다 | 0.96초 → 1.2초 | $0.00009 → $0.0019 |
  | 제이크 추천(3주제 × 7 × 3바퀴) | 이상한 문장 Haiku 12/63, Sonnet 2/63. 최근 상황 열 개에서 Haiku 7/21, Sonnet 0/21 | 1.3초 → 1.8초 | $0.00015 → $0.0028 |
  | 라이언 평가(12경우 × 3) | 규칙 검사 둘 다 0/36, 말도 거의 같다 | 첫 문장 0.86초 → 1.26초 | $0.0003 → $0.0061 |

- 바꾼 뒤 실제 Sonnet: `uv run python scripts/check_jake_recommend.py` → 스물한 번 모두 끝말을 모델이 지켰다(MISSED 0). 이름표 0번, 같은 끝말 연달아 0번. $0.0683.
- worktree 서버(`127.0.0.1:8797`, 녹음을 뺀 데이터 복사본): 로그 `claude models: writer claude-sonnet-5-5, quick claude-haiku-5-5, recommend claude-sonnet-5-5`. `POST /recommend`를 주제 셋에서 두 번씩 보냈고, 제이크 목소리까지 5.5~9.6초 걸렸다. 학습자 목소리로 만든 녹음(대사 그대로)은 따라 말한 것으로 받아 Haiku 평가가 왔다(첫 글자 1.3초). 끝나고 서버를 끄고 복사본과 녹음을 지웠다.
- 마지막 리뷰(브랜치 전체, Opus 한 명): 꼭 고칠 것은 없었다. Important 둘과 올린 하나를 고쳤고, 작은 것 여섯은 할 일 28로 남겼다.
- PR 리뷰(pr-review, Full, 리뷰어 여섯): 코드 축은 통과 0건, 경계선 1건이었다(25점, `QUICKS` 위 주석에 새 설정이 없음, 할 일 28에 있다). 스펙 축은 「실제 문제」 1건(devlog 없음, 이 파일로 닫음)과 「표현 차이」 1건(PR 본문에 적음)이었다.
- 앱 화면은 바뀌지 않아 폰과 에뮬레이터는 쓰지 않았다.
