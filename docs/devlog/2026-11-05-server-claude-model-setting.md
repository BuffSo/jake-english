- 문서: PRD 「첫 판: 말하기」 / 스펙 `docs/superpowers/specs/2026-11-05-speaking-practice-design.md` 「기다리는 시간과 모델」(새 스펙 없이 절 하나를 더함) / 계획 없음 / ADR 없음(ADR-0004는 그대로)

## 한 일

- 사용자가 폰에서 목소리를 시험하는 동안 토큰을 아끼려고 모든 호출을 Haiku 5.5로 돌리기로 했다. 모델이 코드에 박혀 있어서 `server/.env`의 `JE_CLAUDE_WRITER`(haiku, sonnet, opus)와 `JE_CLAUDE_QUICK`(haiku, sonnet)로 고르게 했다.
- 값이 없으면 지금과 같다(글쓰기 Sonnet, 짧은 말 Haiku). 머지만으로는 동작이 바뀌지 않는다.
- 없는 값이면 서버가 시작할 때 멈추고, 서버 로그에 고른 모델이 찍힌다.
- main 세션이 일을 정해 오르카로 이 worktree 세션을 띄웠다. 같은 시간에 역할극 반복 연습 카드가 스펙을 쓰고 있어, `claude.py`는 모델 표만 더하고 다른 부분은 건드리지 않았다.

## 바로잡은 것

- **넘긴 글과 코드가 달랐다:** 넘긴 글은 피드백(녹음 평가 글)이 Sonnet을 쓴다고 했지만, 코드와 스펙은 Haiku(짧은 말)였다. 코드대로 짧은 말에 넣고 README와 `.env.example`에 맡는 일을 적었다.
- **기본값을 두 곳에 썼다:** `Settings` 필드와 `load_settings`에 `"sonnet"`, `"haiku"`를 따로 썼다. 리뷰의 스펙 대조가 잡았고 `DEFAULT_WRITER`, `DEFAULT_QUICK` 상수로 모았다.
- **처음 실패한 시험이 import 오류였다:** 새 시험 파일이 통째로 import 오류로 실패해, 각 시험이 제 이유로 실패하는지는 보지 못했다. 구현 뒤 설정 검사와 모델 넘기기를 일부러 빼서 해당 시험 2개가 실패하는 것을 확인했다.
- `REVIEW.md`는 고치지 않았다. 「Sonnet의 `between_tools`는 생각하는 단계를 끈 것이 아니다」는 지적이 오탐이었지만 처음 나온 것이라 「넘길 것」에 넣지 않았다. 다시 나오면 넣는다.
