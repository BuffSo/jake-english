# 녹음마다 강세 값을 남겨 두기 설계

> PRD 기능: 열린 질문 1 「강세를 평가할 수 있는가」의 「녹음이 쌓이면 다시 시험한다」(`docs/PRD.md`).
> 앞선 문서: `docs/guide/PRONUNCIATION_녹음으로_강세평가_시험_20261105.md`(이하 「강세 시험 가이드」), 말하기 연습 스펙(`docs/superpowers/specs/2026-11-05-speaking-practice-design.md`) 「하지 않을 것」과 「미룬 것」의 「녹음마다 강세 특징값을 남겨 나중에 다시 시험하기」, 할 일 `docs/todo/20261105_05_todo_log_stress_measurements.md`. 이 문서는 그 문서들을 함께 읽는다는 전제로 쓰고, 거기 있는 것은 되풀이하지 않는다.
> 작성: 2026-11-08 (stress-log 카드)
> 결정: 아래 「정한 것」 1~4는 카드가 main 세션을 거쳐 물었고 사용자가 정했다(2026-11-08). ADR은 쓰지 않는다(아래 1).
> 표시: 「(AI 판단)」은 AI가 정한 것이다. 표시가 없는 결정은 사용자가 정했거나 앞선 문서에 있는 것이다.

## 왜 만드나

2026-11-05 시험에서 녹음만 보고는 강세를 믿고 판정할 수 없었다(강세 시험 가이드). 사용자는 「첫 판은 짚지 않고, 잰 값만 남긴다」로 정했다. 녹음이 쌓이면 같은 방법으로 다시 재서, 짚을 수 있는 범위가 생겼는지 본다. 그 「잰 값 남기기」를 만든다.

이 일은 「강세를 짚을 수 있나」를 판단할 재료를 모으는 개발용이다. 짚을 수 있으면 평가에 넣고 이 일은 필요 없어진다. 짚을 수 없으면 그만둔다(사용자, main 세션 경유).

MFA 정렬은 한 번 부르는 데 30초쯤(대부분 모델 불러오기, 2026-11-08 지어낸 녹음 둘로 잼) 걸려 녹음 직후에는 쓸 수 없다. 그래서 몰아서 잰다.

## 목표

1. 손으로 돌리는 스크립트 하나가 아직 재지 않은 녹음을 몰아 재서, 녹음마다 값을 맥의 앱 데이터 폴더에 남긴다. 다시 돌리면 그 사이에 쌓인 녹음만 잰다.
2. 남기는 값: 낱말과 음절 단위의 판정과 수치(세기, 음높이, 길이), 사전 강세, 대사에 표시한 강세, MFA가 소리를 보고 고른 발음.
3. 쌓인 값으로 강세 시험 가이드의 숫자 표와 같은 모양의 표를 다시 낸다. 대사에 표시한 강세와 맞는 비율도 낸다.
4. 도는 동안 맥이 무거워지지 않는다.
5. 지금까지 쌓인 녹음을 이번에 한 번 잰다.

## 하지 않을 것

- **저절로 돌리기:** launchd 작업이나 서버 안에서 도는 일을 만들지 않는다(아래 「정한 것」 1).
- **강세를 사용자에게 짚기, 앱에 보이기:** 첫 판은 짚지 않는다(PRD 열린 질문 1). 앱 화면과 서버 응답은 바뀌지 않는다.
- **맥 서버 코드의 동작 바꾸기:** 재는 스크립트는 서버와 따로 돈다. 서버 프로세스, API, 기록 모양은 그대로다(AI 판단). 서버의 표기 맞추기(`compare.words`)와 사전(`cmu`)은 가져다 쓴다.
- **기존 기록과 녹음 고치기:** `roleplay.json`과 `rec/`의 녹음은 읽기만 한다. 잰 값은 따로 둔다.
- **맥 밖으로 보내기:** Claude도 부르지 않는다. 녹음, 녹음의 사본, 짧은 구간마다의 값(음높이와 세기의 곡선)은 맥 밖으로 나가지 않는다(ADR-0004).
- **짧은 구간 값 남기기:** 모음 구간마다 모은 값(가장 센 세기, 가장 높은 음높이, 가운데 음높이, 길이)만 남긴다. 곡선은 재는 동안 메모리에만 있다(AI 판단).
- **판정 방법 고치기:** 강세 시험 가이드 「다시 시험할 때」의 「해 볼 만한 것」(화자별 음높이 범위, 본보기 소리와 비교, 학습한 분류기)은 이 일이 아니다. 남긴 값으로 나중에 시험한다.
- **한국어로 말한 녹음 재기:** 받아쓴 글에 한글이 있으면 재지 않는다(AI 판단). 영어 사전과 영어 모델로는 잴 수 없다.
- **자유 대화를 따로 다루기:** 같이 도는 free-talk 카드가 자유 대화의 기록을 만든다. 그 기록도 시도에 들린 말과 녹음(`rec/{idx}-{n}.m4a`)이 있으면 「다르게 말한 영어」로 잰다. 표에서 따로 나누는 것은 그 카드가 머지된 뒤 기록 모양을 보고 정한다(AI 판단).

## 실패로 볼 것

- **맥이 무거워진다:** 재는 동안 받아쓰기나 목소리가 늦어진다.
- **기록이 바뀐다:** `roleplay.json`이나 녹음 파일이 바뀌거나 지워진다.
- **녹음 사본이 남는다:** 재려고 만든 WAV 사본이나 MFA 작업 폴더가 재고 난 뒤에도 남는다.
- **공개 파일에 사용자 말이 들어간다:** 표를 내는 스크립트의 출력, 가이드, 커밋에 들린 말이나 대사 원문이 들어간다. 출력은 개수와 비율만이다.

## 정한 것

### 1. 언제 도나: 손으로 돌리는 스크립트

- `cd server && uv run python scripts/measure_stress.py`로 돌린다. 아직 재지 않은 녹음만 재므로 몇 번을 돌려도 된다.
- 녹음은 맥에서 지우지 않아(ADR-0011, 말하기 연습 스펙 「녹음과 기록」) 나중에 몰아 재도 결과가 같다. 그래서 저절로 돌릴 까닭이 없다.
- ADR은 쓰지 않는다. 맥 설정을 바꾸지 않고, 개발용 스크립트와 따로 둔 값 폴더라 되돌리기 쉽다.
- 흐름: 카드는 처음에 매일 새벽 launchd 작업(ADR로 남김)을 추천했다. main 세션이 개발용인지 서비스용인지 물어 개발용으로 보고 손 스크립트를 추천했고, 사용자가 받아들였다.

### 2. 지난 녹음

- 지금까지 쌓인 녹음을 이번에 한 번 잰다. 2026-11-08 맥에는 녹음 73개가 있다(한국어로 말한 것 포함).

### 3. 무겁지 않게

- MFA와 소리 특징 재기는 낮은 우선순위(`taskpolicy -b`, macOS의 백그라운드 등급으로 CPU와 디스크를 낮춤)로 돌리고, MFA는 작업 하나(`-j 1`)로 돌린다.
- 앱을 쓰는 중인지 보는 장치는 간단히 둔다(AI 판단): 시작할 때 최근 10분 안에 바뀐 기록 파일(`roleplay.json`이나 녹음)이 있으면 그렇다고 알리고 멈춘다. `--now`를 붙이면 그래도 돈다.

### 4. 음높이와 세기는 Praat(parselmouth)로

- 2026-11-05 시험과 같은 도구라 강세 시험 가이드의 숫자와 바로 견줄 수 있다. 지금 맥에 없어 기존 MFA 환경에 pip로 `praat-parselmouth`를 깐다(사용자 승인). 저장소의 파이썬 의존성(`server/pyproject.toml`)은 바뀌지 않는다.

## 어떻게 재나 (AI 판단)

강세 시험 가이드 「무엇으로 쟀나」의 둘째 방법(MFA 모음 구간)을 그대로 따른다.

1. **고르기:** 앱 데이터 폴더의 역할극마다 시도(`Attempt`)를 본다. 녹음 `rec/{idx}-{n}.m4a`가 있고, 잰 값 파일이 아직 없고, 들린 말에 한글이 없고 영어 낱말이 있는 시도만 잰다. 대사를 따라 말한 것, 대사와 다르게 말한 영어, 반복 연습과 섀도잉이 모두 들어간다. 시도가 없는 녹음(소리가 없어 버린 것)은 재지 않는다.
2. **정렬할 글:** 들린 말(`Attempt.heard`)을 서버의 표기 맞추기(`compare.words`)로 낱말로 바꾼 것. 숫자는 낱말로 바뀐다(가이드 「겪은 문제와 해결」). 대사가 아니라 들린 말로 정렬하는 것은, 빠뜨리거나 바꿔 말한 낱말을 MFA가 소리에 억지로 맞추지 않게 하려는 것이다.
3. **정렬:** 녹음을 16kHz 모노 WAV로 바꿔 MFA 3.4.3(`english_us_arpa`)으로 한 번에 정렬한다. WAV 사본과 MFA 작업 폴더는 앱 데이터 폴더의 `tmp/` 아래에 두고, 다 재면 지운다. 실패해도 지운다.
4. **소리 특징:** 모음 구간마다 가장 센 세기(dB), 가장 높은 음높이와 가운데 음높이(100Hz 기준 반음), 길이(초)를 잰다. Praat 기본값(음높이 75~600Hz)으로 잰다. 음높이가 잡히지 않은 모음은 값이 비어 있다.
5. **낱말 강세 판정:** 낱말 안에서 세 특징을 합친 점수(세기 3dB, 음높이 2반음, 길이 40ms를 같은 무게로 셈)가 가장 큰 음절이 센 음절이다. 1위와 2위의 점수 차이가 확실도다. 낱말 안에 음높이가 빈 모음이 있으면 그 낱말은 음높이를 빼고 센다.
6. **문장 강세 점수:** 낱말마다 사전에서 센 음절(MFA가 고른 발음의 1, 없으면 모음 하나뿐인 낱말의 그 모음)의 세 특징을 녹음 안에서 표준화해 더한다.
7. **사전 강세:** CMUdict에서 MFA가 고른 발음과 모음 수가 같은 발음들의 1차 강세 자리. 자리가 하나로 정해지는지, 2차 강세가 있는지도 남긴다.
8. **대사에 표시한 강세:** 그 시도가 맞대는 대사(섀도잉은 라이언 대사, 나머지는 학습자 대사)에 세 줄 표시(`ScriptLine.three`)가 있으면, 들린 낱말과 세 줄의 낱말을 순서대로 맞대어(같은 글자끼리) 센 음절(`s`), 약한 음절(`w`), 뜻 때문에 힘준 낱말(`emph`)을 붙인다. 맞대지 못한 낱말은 비운다.
9. **사전에 없는 낱말:** MFA 사전에 없는 낱말(MFA가 소리를 붙이지 못한 것)은 음절 값을 비운다. MFA의 글자-소리 모델을 새로 받지 않는다(새로 까는 것이라).
10. **정렬이 믿을 만한지:** MFA가 녹음마다 내는 정렬 점수(`alignment_analysis.csv`의 소리 로그 가능도, 소리 길이 벗어남)를 함께 남긴다. 다르게 말한 차례에는 한국어를 영어로 옮겨 적은 들린 말이 섞여 있을 수 있다(선생님 답 스펙 2). 그런 녹음은 영어 소리가 아니라 정렬이 나쁘게 나온다. 기준값은 쌓인 값을 보고 정한다.

## 남기는 곳과 모양 (AI 판단)

- 앱 데이터 폴더의 `stress/{역할극 ID}/{idx}-{n}.json`. 녹음 하나에 파일 하나다. 파일이 있으면 잰 것으로 보고 다시 재지 않는다. 정렬에 실패한 녹음도 실패를 적은 파일을 남겨 다시 재지 않는다. 방법을 바꿔 다시 재려면 `stress/`를 지우고 돌린다.
- 기존 `roleplays/`와 섞지 않는다. 이 일을 그만두면 `stress/`만 지우면 된다.
- 파일에 든 것: 형식 번호, 역할극 ID, 줄, 시도 번호, 시도 종류, 따라 말했는지, 녹음한 때, 잰 때, 도구와 판(MFA, 모델, Praat), 상태(잼, 정렬 실패), 정렬 점수, 낱말마다(글자, 시작과 끝, 내용어인지, MFA가 고른 발음, 사전 강세, 대사 표시, 음절마다의 값, 판정, 확실도, 문장 강세 점수).
- 낱말 글자가 들어가므로 역할극 기록과 같이 저장소 밖 맥에만 둔다(`AGENTS.md` 「공개 저장소」).
- 파일은 임시 파일에 쓴 뒤 바꿔 넣는다(`Store._write`와 같다).

## 표 다시 내기 (AI 판단)

- `cd server && uv run python scripts/stress_report.py`가 `stress/`의 값을 모아 마크다운 표를 찍는다. `--since YYYY-MM-DD`로 기간을 고른다.
- 찍는 것(강세 시험 가이드 「결과」와 같은 줄):
  - 잰 녹음 수, 정렬 실패 수, 낱말 수
  - 낱말 강세가 사전과 맞은 비율과 늘 첫 음절이라고 찍기. 사전 강세가 하나로 정해지는 두 음절 이상 낱말만. 2차 강세가 없는 낱말만, 확실도 위 25%만도 낸다.
  - 낱말 강세가 대사에 표시한 강세와 맞은 비율(표시와 음절 수가 같은 낱말만)
  - 문장 강세 AUC(내용어가 기능어보다 센가, 0.5가 찍기)
  - 기능어 약형: for, a, to, of, the마다 MFA가 약형을 고른 수
  - 위 표는 「대사를 따라 말한 것」으로 낸다. 강세 시험 가이드도 대본을 읽은 녹음으로 쟀다. 「다르게 말한 영어」는 따로 낸다. 한국어를 옮겨 적은 들린 말이 섞여 있을 수 있어서다(위 「어떻게 재나」 10).
- 들린 말, 대사, 낱말 글자는 찍지 않는다. 기능어 다섯은 정해 둔 낱말이라 이름을 찍는다. 그래서 출력을 그대로 공개 가이드에 옮길 수 있다.

## 어디에 쓰나

- 맥의 설정: `server/.env`에 `JE_MFA_ENV`(MFA 환경 폴더)를 둔다. 기본값은 없다(개인 폴더라 저장소에 쓰지 않는다). `server/.env.example`에 자리를 더한다. 앱 데이터 폴더는 서버와 같은 `JE_DATA_DIR`을 읽는다.
- 스크립트의 출력은 개수와 걸린 시간만이다. 들린 말과 녹음 경로는 찍지 않는다(`REVIEW.md` 「녹음 처리」).

## 확인 방법

- 단위 시험(`cd server && uv run pytest`): 판정과 점수, 낱말 맞대기, 고르기(잰 것, 한국어, 녹음 없음 건너뛰기), 바쁨 판단, 파일 쓰기, 표 셈(맞은 비율, AUC, 약형).
- 끝에서 끝까지: 학습자 목소리로 지어낸 녹음(`docs/guide/DEVENV_폰없이_녹음_시험하기_20261108.md`)과 지어낸 기록으로 만든 시험 데이터 폴더에서 재기와 표를 돌린다. 통과 기준은 값 파일이 녹음마다 생기고, 낱말과 모음 구간이 녹음 길이 안에 있고, `tmp/`에 사본이 남지 않고, 다시 돌리면 아무것도 재지 않는 것이다. 강세를 바꿔 읽은 지어낸 문장으로 판정이 바뀌는지도 보지만 결과로 적을 뿐 통과 기준이 아니다. 판정을 믿을 수 없다는 것이 강세 시험 가이드의 결론이고, 음성 합성이 강세를 시킨 대로 옮기는지도 모른다(AI 판단).
- 실제 기록 사본: 맥의 앱 데이터 폴더를 복사해 그 사본으로 먼저 돌린다(`JE_DATA_DIR`). 원래 기록과 녹음이 바뀌지 않았는지(재기 전과 뒤의 체크섬), 사본의 `tmp/`에 WAV가 남지 않았는지 본다. 이 표를 강세 시험 가이드에 숫자만 더한다.
- 실제 앱 데이터 폴더: 리뷰를 마친 코드로 한 번 돌려 지난 녹음을 잰다(목표 5). 같은 확인(체크섬, `tmp/`)을 한다.

## 빌더에게 맡기는 것

- 파일 안의 키 이름과 형식 번호.
- 내용어와 기능어를 가르는 낱말 목록(관사, 전치사, 대명사, 조동사, 접속사 같은 닫힌 낱말).
- 녹음 몇 개씩 MFA에 넘길지.
- 서버 쪽(uv 환경)과 MFA 환경 쪽에 일을 어떻게 나눌지. MFA 환경에는 pip로 깐 parselmouth만 더한다.
