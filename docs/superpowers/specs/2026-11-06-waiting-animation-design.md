# 기다리는 동안 생각하는 얼굴 설계

> PRD 기능: 「첫 판: 말하기」의 상황 정하기와 상황 역할극에서 기다리는 때(`docs/PRD.md`). 얼굴 그림을 두는 곳은 PRD 「첫 화면: 라이언이 묻는다」와 열린 질문 8을 따른다.
> 작성: 2026-11-06 (superpowers brainstorming, waiting-animation 카드)
> 표시: 「(AI 판단)」은 사용자가 말한 것이 아니라 AI가 정한 것이다. 사용자는 얼굴과 기다림마다 누구를 보여 줄지를 정한 뒤, 나머지는 AI 추천대로 하라고 맡겼다(2026-11-06). 표시가 없는 결정은 사용자가 정했거나 PRD에 있는 것이다.

## 왜 만드나

2026-11-06 사용자가 폰에서 써 보고 말했다. Claude가 대본이나 추천을 만드는 동안 도는 표시(모래시계처럼 도는 것)가 나오는데 별로다. 그 대신 제이크가 고민하는 표정, 생각하는 표정이 움직이면 좋겠다.

기다리는 몇 초 동안 화면이 「멈춘 기계」가 아니라 「누가 내 일을 하고 있다」로 보이게 하는 것이 목적이다. 앱에는 이미 라이언(선생님)과 제이크(진행자) 두 인물이 있다(PRD 「목소리와 역할」). 기다림도 그 인물이 맡는다.

## 목표

1. 지금 도는 표시가 나오는 기다림 여섯 곳에서 도는 표시 대신 생각하는 얼굴이 움직인다.
2. 그 일을 하는 사람의 얼굴이 나온다. 제이크가 상황을 고르는 동안에는 제이크, 나머지는 라이언이다.
3. 새로 설치하는 것이 없다.
4. 그림을 못 받아도 앱은 멈추지 않고, 기다린다는 것은 여전히 보인다.

## 하지 않을 것

- 동영상(제미나이 영상, 입 모양 맞추기). 영상 재생 도구를 새로 설치해야 하고, 영상 중간에 얼굴이 달라질 수 있다. 라이언이 말하는 영상은 PRD 열린 질문 8에서 따로 정한다.
- 움직임 파일 형식(Lottie 같은 것)이나 새 패키지.
- 기다리는 시간 자체를 줄이는 것.
- 그림을 저장소에 넣는 것(PRD 열린 질문 8).
- 첫 화면의 라이언 정면 그림과 상황 화면의 듣는 얼굴을 바꾸는 것. 기다리는 동안만 바뀐다.
  - 2026-11-06 폰 시험 뒤, 상황 화면에서 제이크의 추천이 두 버튼을 기다리는 동안은 제이크 얼굴로 바꿨다(말하기 연습 스펙 「상황 정하기」 3).

## 정한 것

### 1. 제이크의 얼굴

- 라이언처럼 AI가 만든 반실사 그림이다. 실사형 3D와 사진 사이의 그림체로, 라이언 그림과 같은 크기(572×1024 PNG), 같은 밝은 회색 배경이다.
- 만든 방법과 고른 과정은 비공개 메모에 있다(공개 저장소 규칙). 기본 얼굴은 비공개 폴더의 `jake-front.png`다.

### 2. 기다림마다 누구 얼굴인가

화면 글에 이름이 나오는 사람의 얼굴이다. 이름이 없으면 라이언이다. 라이언이 선생님이고 대본, 듣기, 평가를 맡기 때문이다.

| 화면 | 기다리는 글 | 얼굴 |
|---|---|---|
| 상황 화면 | 제이크가 상황을 고르고 있어요 | 제이크 |
| 상황 화면 | 라이언이 대본을 만들고 있어요 | 라이언 |
| 상황 화면 | 받아쓰고 있어요 | 라이언 |
| 역할극 화면 | (다음) 대사를 준비하고 있어요 | 라이언 |
| 역할극 화면 | 라이언이 듣고 있어요 | 라이언 |
| 끝 화면 | 마무리하고 있어요 | 라이언 |

### 3. 움직이는 방법 (AI 판단, 사용자가 추천을 맡김)

- 사람마다 생각하는 표정 그림 두 장을 만든다. 기본 얼굴에서 표정만 바꾸고 구도는 그대로 둔다. 두 그림이 겹쳐 바뀔 때 얼굴 위치가 튀지 않게 하기 위해서다. 기본 얼굴은 제이크가 `jake-front.png`, 라이언이 `ryan-front.png`(정면)다.
- 그림은 이 작업에서 AI가 제미나이 이미지 편집으로 만든다(사용자가 쓰는 구독이라 따로 드는 돈이 없다). 같은 사람의 두 그림은 얼굴 위치가 조금 어긋날 수 있어서, 맥에서 크기와 위치를 맞춘 뒤 자른다(아래 5).
  - 1번: 눈을 위로 굴리고 입을 다문 채 생각하는 얼굴
  - 2번: 검지를 턱에 대고 고개를 살짝 기울인 얼굴
- 두 그림을 동그라미 안에서 천천히 번갈아 보여 준다. 한 장을 1.8초 보여 주고, 0.6초 동안 다음 장으로 겹쳐 바꾼다(크로스페이드).
- 글 아래에 점 세 개가 차례로 밝아졌다 흐려진다(한 바퀴 1.2초). 그림을 못 받았을 때도 이 점이 기다린다는 것을 보여 준다.
- React Native에 들어 있는 `Animated`만 쓴다. 투명도만 바꾸므로 네이티브 드라이버로 돈다.

### 4. 화면에 놓는 자리 (AI 판단)

- **상황 화면:** 위쪽에 이미 라이언의 큰 동그라미(듣는 얼굴, 160)가 있다. 기다리는 동안에는 그 동그라미가 그 자리에서 생각하는 얼굴로 바뀐다. 얼굴이 두 개 나오지 않게 하기 위해서다. 아래 기다리는 글에는 점 세 개만 붙는다. 기다림이 끝나면 다시 듣는 얼굴이다. 제이크의 추천을 기다린 끝이면 제이크 얼굴이다(2026-11-06, 말하기 연습 스펙 「상황 정하기」 3).
- **역할극 화면과 끝 화면:** 얼굴이 따로 없으므로, 도는 표시가 있던 자리에 작은 동그라미(96)와 글, 점 세 개가 나온다. 역할극 화면은 말풍선 사이라 크게 두지 않는다.

### 5. 그림 파일과 서버 (AI 판단)

- 새 그림 네 장: `jake-thinking-1.png`, `jake-thinking-2.png`, `ryan-thinking-1.png`, `ryan-thinking-2.png`. 비공개 폴더 `docs/private/assets/`에 두고, 서버가 `JE_ASSETS_DIR`로 읽는다.
- 서버의 `ASSETS` 목록에 네 이름을 더한다. 목록에 없는 이름은 지금처럼 404다.
- 서버의 `/home` 답의 `images`에 `thinking`을 더한다: `{"jake": [두 경로], "ryan": [두 경로]}`. 앱은 지금처럼 경로를 서버에서 받는다. 앱 코드에 그림 이름을 박지 않는다.
- 앱은 `/home` 답을 받은 뒤 생각하는 얼굴 경로를 앱 전체에 나눠 준다(React context). 역할극 화면과 끝 화면은 지금 `home`을 받지 않기 때문이다.
- 생각하는 얼굴 그림은 얼굴만 담은 정사각형(512×512 PNG)이다. 제미나이가 만든 세로 그림에서 같은 사람의 두 장의 얼굴 위치를 맞춘 뒤 맥에서 잘라 만든다. 그래서 앱은 그림 전체를 동그라미에 채우기만 하고, 그림 안의 얼굴 자리를 따로 알 필요가 없다. 라이언의 듣는 얼굴처럼 앱에 얼굴 네모 값을 두지 않는다.

### 6. 그림이 없을 때 (AI 판단)

- `/home`을 아직 못 받았거나 경로가 비어 있으면 얼굴 없이 글과 점 세 개만 나온다. 도는 표시는 다시 쓰지 않는다. 상황 화면은 이때 위쪽 듣는 얼굴을 그대로 둔다.
- 그림을 받다가 실패하면(서버에 파일이 없어 404, 연결 끊김) 동그라미는 배경색만 남고 글과 점은 그대로다. 오류 문구는 띄우지 않는다. 기다림의 본래 일(대본, 평가)과는 상관없는 실패이기 때문이다.

### 7. PRD (AI 판단)

PRD 「첫 화면」은 라이언의 얼굴이 처음 인사와 원하는 것을 물을 때만 나온다고 적는다. 이제 기다리는 동안에도 생각하는 얼굴이 나오므로, 같은 PR에서 PRD를 고친다.

## 확인 방법

- **서버 시험(pytest):** `/home`이 `images.thinking`에 두 사람의 경로 두 개씩을 돌려준다. 새 이름 네 개는 `/assets/`에서 내주고, 목록에 없는 이름은 여전히 404다.
- **앱 시험(jest):** 기다리는 글에서 얼굴을 고르는 규칙(위 표), `/home` 답에서 사람별 그림 경로를 꺼내는 것, 그림 경로가 없을 때 얼굴 없이 가는 것. `tsc`로 타입을 본다.
- **폰:** 여섯 기다림에서 얼굴이 표대로 나오는지, 두 그림이 튀지 않고 바뀌는지, 상황 화면에서 기다림이 끝나면 듣는 얼굴로 돌아오는지, 그림을 못 받을 때(서버를 옛 코드로 띄운 상태) 점만 나오는지.
