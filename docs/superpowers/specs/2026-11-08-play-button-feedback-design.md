# 듣기 버튼이 바로 반응하고 녹음이 늦게 들리지 않게 설계

> PRD 기능: 「첫 판: 말하기」의 「사용자 차례(역할극)」, 「역할극 뒤 연습과 주고받은 말 보기」, 「통역」(`docs/PRD.md`).
> 앞선 스펙: `docs/superpowers/specs/2026-11-08-three-line-listen-design.md`(이하 「듣기 스펙」), `docs/superpowers/specs/2026-11-05-speaking-practice-design.md`의 「녹음과 기록」, `docs/superpowers/specs/2026-11-07-review-practice-design.md`(처음 녹음). 이 문서는 그 스펙들을 함께 읽는다는 전제로 쓰고, 거기 있는 것은 되풀이하지 않는다.
> 작성: 2026-11-08 (superpowers brainstorming, record-feedback 카드의 다음 PR)
> 결정: 사용자가 main 세션을 거쳐 정했다(2026-11-08). 글자는 그대로 두고 🔊가 울리게 한다. 모양은 HTML 초안 셋 중 A(쿵쿵)다. 녹음은 폰에 두지 않고, 맥이 듣기용 사본을 만들어 첫 말소리 0.2초 앞부터 튼다(AI 추천을 사용자가 받아들임). 나머지(어느 버튼, 다시 누르면 멈춤 같은 것)는 사용자가 맡겨 AI가 정했다.
> 표시: 「(AI 판단)」은 AI가 정한 것이다. 「(AI 추천을 사용자가 받아들임)」은 AI가 추천하고 사용자가 받아들인 것이다. 표시가 없는 결정은 사용자가 정했거나 앞선 스펙에 있는 것이다.

## 왜 만드나

2026-11-08 사용자가 폰에서 「🔊 내 녹음」을 눌렀는데 아무 반응이 없다가 늦게 녹음 소리가 들렸다. 사용자: 「내 녹음 누르면 플레이되고 있다는 표시가 나와야 할 듯」.

- main 세션은 처음에 누르면 「불러오는 중…」, 소리가 나는 동안 「■ 멈추기」로 글자를 바꾸자고 추천했다. 사용자는 「UI가 너무 복잡하게 변화하는 것 같다」며 이렇게 정했다: 「내 녹음 표시는 그대로 하고, 이게 스피커 꽝꽝 울리는 것처럼 표현해 주면 더 좋을 것 같은데, 나머지는 이에 맞게 알아서」.
- **잰 것(2026-11-08, 사용자의 폰, 집 망):** 「🔊 내 녹음」을 누르고 소리가 시작되기까지 0.11초, 0.14초, 0.26초였다. 맥에 있는 최근 녹음 20개는 첫 소리까지 0.42~2.10초(가운데 0.7초쯤)가 조용했다. 「🎤」를 누르고 말을 시작하기까지가 녹음에 담긴다. 그래서 「늦게 들린다」는 주로 녹음 앞의 침묵이다.
- 맥에 있는 녹음 파일은 재생에 필요한 머리 정보(moov)가 파일 끝에 있다. 폰은 앞부분을 받은 뒤 끝을 다시 받아야 틀 수 있어, 느린 망(집 밖)에서는 이것도 늦어진다.

## 목표

사용자가 할 수 있어야 하는 것:

1. 소리를 트는 버튼을 누르는 순간, 그 버튼의 🔊가 울리는 것을 본다. 소리를 받아 오는 동안에도 울리고, 소리가 끝나면 멈춘다.
2. 울리는 버튼을 다시 누르면 소리가 멈춘다.
3. 내 녹음은 누르면 바로 내 목소리가 들린다. 앞의 침묵을 기다리지 않는다.
4. 소리를 트는 버튼은 어디서나 같게 움직인다.

## 하지 않을 것

- **버튼 글자 바꾸기:** 「불러오는 중…」, 「■ 멈추기」 같은 글자로 바꾸지 않는다(사용자).
- **녹음을 폰에 두기:** 녹음은 지금처럼 폰에 남기지 않는다(말하기 스펙 「녹음과 기록」). 폰에 둬도 앞의 침묵은 그대로라 늦게 들리는 것이 풀리지 않고, 줄어드는 것은 받아 오는 0.1~0.3초뿐이다(AI 추천을 사용자가 받아들임).
- **원본 녹음 고치기:** 맥의 원본 녹음은 그대로 둔다. 받아쓰기, 처음 녹음, 나중의 비교는 원본을 쓴다.
- **라이언이 스스로 말할 때 움직이기:** 라이언의 대사, 평가, 선생님 라이언의 답처럼 앱이 저절로 트는 소리에는 🔊가 움직이지 않는다. 내가 누른 버튼만 움직인다(AI 판단).

## 실패로 볼 것

PRD 「실패로 볼 것」에 더해, 이 기능에서는 아래가 실패다(AI 판단).

1. 소리가 끝났는데(또는 다른 소리로 바뀌었는데) 🔊가 계속 울린다. 또는 누른 버튼이 아닌 다른 버튼이 울린다.
2. 듣기용 사본이 내 말의 첫소리를 잘라 먹는다.
3. 듣기용 사본을 만들다 실패해서 녹음을 아예 못 듣는다.
4. 빠르게 두 번 누른 것이 「틀자마자 멈춤」이 되어 아무것도 들리지 않는다.
5. 듣기용 사본이 시도 번호를 차지하거나, 맥이 그것을 녹음 하나로 센다.

## 제약

- 새로 설치하는 것이 없다. 움직임은 React Native의 `Animated`로, 사본은 맥에 있는 ffmpeg로 만든다.
- 녹음은 맥의 앱 데이터 폴더에만 둔다(ADR-0001, 말하기 스펙 「녹음과 기록」). 듣기용 사본도 그 역할극의 같은 녹음 폴더(`rec/`)에 둔다. 그래서 ADR과 「녹음과 기록」은 고치지 않는다.
- 맥 서버의 API 모양은 바꾸지 않는다. 앱은 지금처럼 녹음 주소를 부르고, 맥이 듣기용 사본을 내준다.

## 정한 것

### 1. 🔊가 울리는 모양 (초안 A, 사용자)

- 🔊만 움직인다. 글자는 그대로다.
- 움직임: 0.36초마다 한 번, 커졌다(1.35배) 작아지며 살짝 흔들린다(-6도에서 4도). 「꽝꽝 울리는」 느낌이다. 둘레를 덮는 물결은 두지 않는다.
- 누르는 순간 시작해, 소리를 받아 오는 동안에도 울리고, 소리가 끝나거나 멈추면 멈춘다.
- 처음 녹음처럼 소리 둘을 이어 트는 버튼은 둘이 다 끝날 때까지 울린다(사이의 쉼 포함).

### 2. 어느 버튼 (AI 판단)

🔊가 붙은 것 모두 같게 한다(듣기 스펙 6 「🔊 표시」).

| 화면 | 버튼 |
|---|---|
| 대화 화면 | 지나간 말풍선의 「🔊 듣기」, 「🔊 내 녹음」, 평가 자리의 「🔊 내 녹음」, 아래 줄의 「🔊 다시 듣기」, 앞 대사와 제이크 추천 말풍선의 「🔊 눌러서 (다시) 듣기」, 통역 줄의 🔊(「통역」 이름표 바로 뒤, 폰 확인에서 옮김) |
| 끝 화면 | 「🔊 듣기」, 「🔊 처음 녹음」, 시도마다의 「🔊 내 녹음」, 통역 줄의 🔊(「통역」 이름표 바로 뒤, 폰 확인에서 옮김) |

- 아래 줄의 빠르기 버튼(「0.6배」 등)은 🔊가 없어, 그것으로 튼 본보기는 「🔊 다시 듣기」의 🔊가 울린다. 같은 본보기다.
- 통역 줄은 열 때 소희 목소리가 저절로 나온다. 연 것도 내가 누른 것이라, 그 소리가 실제로 대기열에 들어가면 그 줄의 🔊가 울린다. 통역 글이 먼저 오고 소리가 아직 만들어지는 동안, 또는 다른 소리가 나고 있어 소희 목소리를 틀지 않으면(`mayAutoPlay`) 울리지 않는다(AI 판단, 스펙 검토에서 물음). 「통역 접기」가 소리를 멈추는지는 지금 그대로다.
- **울림은 소리가 대기열에 들어갈 때 시작한다.** 누르는 순간 곧바로 대기열에 넣으므로, 받아 오는 동안에도 울린다. 「이 줄 다시 ›」, 「따라 말하기 ›」처럼 화면이 바뀌며 본보기가 저절로 나오는 것은 버튼이 튼 소리가 아니라 울리지 않는다(AI 판단, 스펙 검토에서 물음).

### 3. 누르기 (AI 판단, 사용자가 맡김)

- **울리는 동안 그 버튼을 다시 누르면 멈춘다.** 소리와 움직임 둘 다.
- **다만 누른 뒤 0.4초 안에 다시 누른 것은 받지 않는다.** 빠르게 두 번 누른 것이 「틀자마자 멈춤」이 되지 않게 한다(실패로 볼 것 4).
- **다른 듣기 버튼을 누르면** 앞 소리를 멈추고 새 소리를 튼다(지금과 같다). 울림도 새 버튼으로 옮겨 간다.
- 흐릴 때(듣기 스펙 5, 라이언이 대답하는 동안 등)는 지금처럼 누름을 받지 않고, 울리지도 않는다.

### 4. 녹음의 듣기용 사본 (AI 추천을 사용자가 받아들임)

- 맥이 녹음을 내줄 때(`GET /roleplays/{id}/lines/{idx}/attempts/{n}/recording`) 원본 대신 듣기용 사본을 내준다.
- **사본:** 원본에서 첫 말소리 0.2초 앞부터 마지막 말소리 0.4초 뒤까지를 다시 인코딩 없이 잘라 낸 것이다. 머리 정보는 파일 앞에 둔다(ffmpeg `-c copy -movflags +faststart`).
  - **말소리:** 50ms마다의 평균 크기가 -45 dBFS 이상인 자리다. 맥의 `has_speech`와 같은 창으로 재되, 기준은 그보다 너그럽다(AI 판단). 맥의 녹음 19개를 재 보니 `has_speech`의 기준(-35 dBFS)으로는 둘이 0.75~1.1초 늦게 시작해, 작게 말한 첫마디를 자를 수 있었다. -45 dBFS로는 나머지와 0.1초 안에서 같았다(2026-11-08, 크기만 재고 내용은 듣지 않음). 말소리를 자르는 것(실패로 볼 것 2)보다 침묵이 조금 남는 편이 낫다.
  - **끝도 자른다(AI 판단, 스펙 검토에서 물음):** 말하다 8초 쉬면 저절로 끝나는 녹음(record-feedback 스펙 4)은 끝에 8초쯤 침묵이 남는다. 그대로 두면 목소리가 끝난 뒤에도 8초 동안 🔊가 울려(실패로 볼 것 1), 처음 녹음 둘 사이에도 긴 침묵이 생긴다. 잰 녹음들의 끝 침묵은 대개 0.5초 안이었고, 1초와 2.3초인 것도 있었다.
  - 그런 자리가 없으면 자르지 않고 머리 정보만 앞으로 옮긴다. 시작이 0.2초보다 앞이면 처음부터, 끝이 0.4초보다 뒤면 원본 끝까지다.
  - 처음 녹음 둘 사이의 쉼(`PAIR_GAP_MS`, 0.6초)은 그대로 둔다. 앞뒤 침묵을 잘라도 둘 사이에는 0.6초에 앞뒤 여유(0.2초, 0.4초)가 더해져 1초 남짓 남는다(AI 판단).
- **어디에:** 원본과 같은 녹음 폴더(`rec/`)에 `{idx}-{n}.play.m4a`로 둔다. 시도 번호를 세는 곳(`next_rec`, `find_rec`)은 `{idx}-{n}.m4a`만 보므로 사본은 시도가 아니다(실패로 볼 것 5).
- **언제 만드나:** 처음 들으러 올 때 만들고, 그다음부터는 만든 것을 내준다. 옛 녹음도 같다. 같은 사본을 동시에 두 번 만들지 않는다(같은 소리의 빠르기 사본 `rate_file`과 같은 방식). 처음 한 번은 0.2초쯤 더 들지만, 그동안 🔊가 울린다.
  - 구현하며 바꿈(2026-11-08): 처음에는 평가를 마친 뒤 곁에서 미리 만들었다. 그러자 서버 시험 전체가 세 번에 한 번꼴로 끝나지 않았다. 시험이 끝나 이벤트 루프를 닫을 때, 아무도 기다리지 않는 곁 작업(ffmpeg 하위 프로세스)을 취소하다 멈췄다. 맥 서버를 다시 띄울 때도 같은 일이 생길 수 있어, 미리 만들기를 뺐다(AI 판단). 뺀 뒤 서버 시험 전체를 열 번 돌려 모두 13초 안에 끝났다.
- **실패하면** 원본을 그대로 내준다(실패로 볼 것 3). 로그에는 실패한 것만 남기고 경로와 받아쓴 글은 남기지 않는다(REVIEW.md 「녹음 처리」).
- 사본은 원본을 지울 때 함께 지운다. 지금은 녹음을 지우지 않는다(PRD 열린 질문 4).

### 5. 고칠 문서

- PRD 「사용자 차례(역할극)」의 듣기 줄에 한 줄: 누르면 🔊가 울리고, 다시 누르면 멈추고, 녹음은 첫 말소리 앞부터 들린다. 이 스펙 경로를 적는다.
- 말하기 스펙 「녹음과 기록」에 듣기용 사본이 같은 폴더에 생긴다는 것을 한 줄 적는다.
- `docs/guide/`: 듣기 버튼(울림과 누르기)과, 녹음 앞의 침묵을 잰 방법과 값. 겪은 문제가 있으면 함께 쓴다(빌더).
- ADR은 쓰지 않는다(AI 판단). 녹음을 두는 곳이 바뀌지 않는다.

## 확인 방법

- 맥 서버(pytest): 지어낸 소리(조용함 1초 + 사인파 1초 + 조용함 3초)로 만든 m4a에서 사본이 0.8초쯤부터 시작해 길이가 1.6초쯤이고 머리 정보가 앞에 있다. 소리가 없는 녹음은 자르지 않는다. 작은 소리(-40 dBFS쯤)로 시작하는 녹음은 그 작은 소리부터 남는다. ffmpeg가 실패하면 원본을 내준다. 같은 사본을 동시에 두 번 부르면 한 번만 만든다. 사본이 생겨도 다음 시도 번호는 그대로다. 녹음 주소가 사본을 내준다.
- 앱(jest): 지금 울릴 버튼을 정하는 순수 함수(누른 버튼, 받아 오는 동안, 끝, 다른 버튼, 멈춤, 이어 트는 둘). 누르기 규칙(울리는 동안 다시 누르면 멈춤, 0.4초 안의 두 번째 누름은 무시).
- 폰: 「🔊 내 녹음」을 누르면 바로 울리고 앞 침묵 없이 들리는지, 다시 누르면 멈추는지, 다른 🔊로 옮겨 가는지, 끝나면 멈추는지. 「🔊 내 녹음」을 누르는 몇 초를 `adb shell screenrecord`로 찍어 맥에 남기고 경로를 main 세션에 보낸다(사용자가 그 영상으로 움직임을 본다).
- 머지 뒤 맥 서버를 다시 띄운다(서버가 바뀐다).

## 빌더에게 맡기는 것

- 지금 울리는 버튼을 앱 안에서 어떻게 알릴지(소리 대기열에 이름표를 붙이는 것 등)와 이름표의 꼴.
- 🔊만 움직이게 버튼을 어떻게 나눌지(🔊와 글자를 따로 그리기).
- 사본을 만드는 함수의 이름과 자리, 시험에 쓸 지어낸 소리.
