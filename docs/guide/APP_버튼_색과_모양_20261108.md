# APP 버튼의 색과 모양

> 작성: 2026-11-08 (first-screen-buttons 카드)
> 스펙: `docs/superpowers/specs/2026-11-08-button-colors-design.md`

앱의 버튼을 어떤 색과 모양으로 그리는지 정한 기준이다. 새 화면에 버튼을 더할 때 이 문서를 따른다.

## 정한 것

### 버튼 세 모양

| 모양 | 언제 | 그리는 법 |
|---|---|---|
| 주된 버튼 (`kind="primary"`, 기본) | 그 화면이나 그 줄에서 먼저 할 일 | 파랑(`colors.primary`)으로 꽉 채우고 흰 글자 |
| 덜 주된 버튼 (`kind="secondary"`) | 그 밖에 누를 수 있는 것 | 흰 바탕에 파란 테두리(두께 2)와 파란 글자 |
| 누를 수 없는 버튼 (`disabled`) | 지금 누를 수 없는 것. 주된 것이든 덜 주된 것이든 | 회색 바탕(`colors.off`)에 회색 글자(`colors.offText`), 테두리 없음 |

- **한 줄에 주된 버튼은 하나다.** 둘을 나란히 둘 때는 덜 주된 버튼을 왼쪽, 주된 버튼을 오른쪽에 둔다(「건너뛰기 | 🎤 말하기」, 「다시 해 보기 | 다음」). 녹음 버튼 줄은 덜 주된 버튼을 글자만큼 넓게, 주된 버튼을 남은 너비로 둔다(`grow`, 취소 스펙 4). 「다시 해 보기 | 다음」은 두 버튼 모두 글자만큼 넓고 가운데에 모인다. 고르는 목록처럼 버튼이 세로로 하나씩 놓이면 같은 무게의 선택지는 모두 주된 버튼일 수 있다(상황 정하기의 주제).
- **누를 수 없는 버튼은 반투명이 아니라 정해진 회색으로 그린다.** 반투명은 바탕색에 따라 연한 파랑이나 연회색이 되어 덜 주된 버튼과 헷갈린다. 회색 하나만 「지금 누를 수 없음」이다.
  - 글자는 읽혀야 한다. 「평가하고 있어요」, 「준비하고 있어요」처럼 누를 수 없는 버튼이 지금 무엇을 하는지 알리는 일이 많다.
- **누르는 동안은 조금 흐리게만 한다**(투명도 0.7). 누를 수 없는 모양과 다르다.
- **하는 일마다 다른 색은 첫 화면 카드에만 쓴다.** 「대화 연습하기」 파랑, 「복습하기」 청록(`colors.review`). 다른 화면의 버튼은 파랑 하나다. 한 화면의 색이 늘면 문장이 한눈에 들어오지 않는다(PRD 「실패로 볼 것」 6). 다시 하기와 복습을 청록으로 칠한 초안은 끝 화면 버튼이 모두 청록이 되었다.
- **녹음하는 동안의 「● 말하기 끝」은 주된 버튼 파랑 그대로다 (2026-11-08 record-feedback).** 글자 앞의 빨간 동그라미(흰 원 위에서 천천히 깜빡임)와 글자 아래 얇은 하늘색 목소리 줄은 버튼 색이 아니라 「녹음 중」이라는 상태 표시다. 버튼을 빨갛게 칠하거나 버튼 줄 위에 빨간 띠를 두는 초안은 사용자가 「너무 강렬하다, 너무 튄다」며 고르지 않았다. 동그라미와 「■」을 함께 둔 초안은 「두 개 있으니까 별로다」라고 해 동그라미 하나만 남겼다. 스펙 `docs/superpowers/specs/2026-11-08-record-feedback-design.md` 2.
- **두 줄짜리 덜 주된 버튼:** 주제 고르기 단계 맨 아래의 「하던 대화 이어 하기」(`ResumeRow`)는 덜 주된 버튼처럼 흰 바탕에 파란 테두리(두께 `BUTTON_BORDER`)이고, 윗줄은 파란 굵은 글자, 아랫줄은 상황 제목을 회색 작은 글자로 쓴다. 주제 버튼(주된 버튼)보다 가볍고, 목록 카드(연회색)처럼 고를 상황 하나로 보이지 않는다(2026-11-08 초안 셋에서 사용자가 고름, `docs/superpowers/specs/2026-11-08-resume-roleplay-design.md`).
- **버튼이 아닌 것은 이 규칙 밖이다.** 목록 카드(`ListCard`, 연회색 줄에 「›」), 탭(`Tabs`), 줄 안의 글자 버튼(`InRowButton`, 「🔊 듣기」, 「☆ 모아 두기」), 「‹ 뒤로」. 목록 카드는 진한 글자의 내용과 「›」로, 글자 버튼은 파란 글자로 누를 수 있다는 것을 보인다.

### 까닭

사용자가 첫 화면 초안을 보며 말했다(2026-11-07).

- 연회색 「복습하기」 초안을 보고: 「연회색이면 disable 된줄 착각할수도 있어....」
- 「같은 기능을 하는 버튼 기능이긴 하지만, 동작은 다르니까 색상도 달라도 되지 않을까?」
- 「다른 화면에서도 버튼이 여러개 표시되는 곳이 있을거잖아」

그 전에는 덜 주된 버튼이 라이언 말풍선과 같은 연회색(`colors.ryan`)으로 꽉 차 있었고, 누를 수 없는 버튼은 제 모양의 반투명이었다. 2026-11-08 맥에서 여는 HTML 초안으로 「지금, 파란 테두리, 연한 파랑 칠, 하는 일마다 색」을 첫 화면, 상황 정하기, 대화 화면 아래 버튼 줄, 끝 화면, 복습하기마다 나란히 보였고, 사용자가 파란 테두리와 「색은 첫 화면 카드에만」을 골랐다. 연한 파랑 칠은 대화 화면의 내 말풍선(연한 파랑)과 가까웠다.

## 코드

- 어떤 모양으로 그릴지는 `app/src/ui/buttonLook.ts`의 `buttonLook(kind, { disabled, pressed })` 하나가 정한다. `Button`(`app/src/ui/Button.tsx`)은 그 값만 쓴다.
- 색 이름은 `app/src/ui/theme.ts`에 있다(`primary`, `bg`, `off`, `offText`).
- 두 kind 모두 테두리 2를 둔다(주된 버튼은 바탕과 같은 색). 그래서 나란한 두 버튼의 높이가 같다. 안쪽 여백은 테두리만큼 줄여, 테두리를 더하기 전과 바깥 크기가 같다.

## 확인 방법

- `cd app && npx jest src/ui/buttonLook.test.ts`: 세 모양이 서로 다른지, 누를 수 없는 모양이 kind와 상관없이 같은지, 누르는 동안이 누를 수 없는 모양과 다른지 본다.
- 화면: 상황 정하기의 주제와 직접 쓰기(말하는 동안 「시작」), 대화 화면 아래 버튼 줄(말하기 전, 녹음하는 동안, 평가하는 동안, 평가를 받은 뒤), 끝 화면, 복습하기 모아 둔 문장을 스크린샷으로 본다. 폰은 `docs/guide/DEVENV_폰을_adb로_시험하기_20261108.md`.
