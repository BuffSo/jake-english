# 폰을 adb로 직접 시험하기

> 작성: 2026-11-08 (three-line-listen 카드)
> 폰의 일련번호와 이 맥의 경로는 공개 파일에 쓰지 않는다.

PR을 머지하기 전에 폰 화면까지 에이전트가 직접 본다. 사용자는 머지만 정한다(`AGENTS.md` 「시험은 에이전트가 다 마친다」). 이 문서는 USB로 꽂힌 폰을 맥에서 adb로 다루는 명령과 겪은 것을 담는다. 녹음을 서버에 보내는 시험은 `DEVENV_폰없이_녹음_시험하기_20261108.md`에 있다.

## 정한 기준

- **사용자에게 시험 목록을 넘기지 않는다.** 화면을 띄우고, 누르고, 글과 스크린샷으로 확인하는 것은 에이전트가 한다. 사람이 직접 말해야 하는 것과 보고 골라야 하는 것(화면 초안)만 사용자에게 묶어 부탁한다.
- **폰의 앱은 하나다.** APK를 깔면 다른 카드가 깐 것을 덮는다. 깔 때 어느 브랜치의 앱인지 사용자에게 알린다.
- **폰 앱은 원래 폴더의 맥 서버에 붙는다.** 서버도 바뀐 PR이면 `DEVENV_맥서버_저절로_띄우기_20261107.md` 「카드가 서버를 시험할 때」대로 서버를 그 브랜치로 바꿔 띄워야 그 PR을 시험한 것이다. 앱만 바뀐 PR은 서버를 건드리지 않는다.
- **사용자 기록에 시험을 섞지 않는다.** 역할극은 「이 상황 다시 하기」로 만든 복사본으로 시험하고, 끝나면 지운다. 사용자가 직접 만든 기록은 남긴다.
- **스크린샷은 저장소 밖 임시 폴더에 두고 공개 파일에 넣지 않는다.** 지난 역할극의 실제 문장과 사용자가 말한 글이 보인다.
- **누르기 전에 앞에 떠 있는 앱이 이 앱인지 본다 (2026-11-08 first-screen-buttons).** 폰은 사용자의 것이라, 시험하는 동안에도 사용자가 집어 들어 다른 앱을 쓸 수 있다. 누르기와 화면 읽기마다 바로 전에 `adb shell dumpsys window | grep mCurrentFocus`에 앱 고유 ID(`dev.jakeso.english`)가 있는지 보고, 없으면 누르지 말고 멈춘다. 명령 하나로 묶어 두면 빠뜨리지 않는다(아래 「겪은 것」의 스크립트). 다른 앱이 앞에 있으면 사용자가 폰을 쓰는 것으로 보고 main 세션에 알린 뒤 에뮬레이터로 옮긴다.
- **시험을 정리하며 지우는 명령은 빈 변수 경로로 쓰지 않는다 (2026-11-08).** 스크린샷, 화면 덤프, 시험 녹음을 지울 때 `rm -rf $SP/*.png`가 아니라 `"${SP:?}"/*.png`나 글자 그대로의 경로로 쓴다. 변수가 비면 엉뚱한 곳을 지울 수 있고, Claude Code는 그런 경로에 사용자 확인 창을 띄워 시험이 멈춘다(`CLAUDE.md`).
- **폰이 없으면 이 앱 전용 에뮬레이터로 본다.** 창을 띄워 사용자가 볼 수 있게 한다. 한 번에 한 세션만 띄우고 다 쓰면 끈다. 맥에 다른 프로젝트의 에뮬레이터가 떠 있을 수 있으니 이름을 보고 고른다.

## 명령

adb는 안드로이드 SDK의 `platform-tools/adb`다(SDK 기본 위치는 `~/Library/Android/sdk`). PATH에 없을 수 있다.

1. **기기를 고른다.** `adb devices -l`에서 USB 폰은 일련번호에 `:`이 없고 `emulator-`로 시작하지 않는 것이다. 이후 명령은 모두 `adb -s <일련번호>`로 그 기기를 정해 부른다. 에뮬레이터가 함께 떠 있으면 `-s` 없이 부를 때 오류가 난다.
2. **화면이 꺼지지 않게 한다.** `adb shell svc power stayon usb`. 꽂혀 있는 동안 화면이 켜져 있다. 잠금 화면이면 누르기가 앱에 닿지 않는다. 지금 상태는 `adb shell dumpsys window | grep -E "mCurrentFocus|isKeyguardShowing"`로 본다.
3. **앱을 깐다.** `adb install -r app/android/app/build/outputs/apk/release/app-release.apk`. 빌드는 `app/README.md`.
4. **앱을 띄운다.** `adb shell monkey -p dev.jakeso.english -c android.intent.category.LAUNCHER 1`. 3에서 앱이 앞에 떠 있었으면 깐 뒤 폰이 저절로 다시 띄운다. 그때는 부르지 않는다(아래 「겪은 것」의 「깐 뒤 곧바로 띄우면 앱이 두 번 떠 소리가 겹친다」).
5. **화면 글과 자리를 읽는다.**

   ```sh
   adb shell uiautomator dump /sdcard/je-ui.xml
   adb exec-out cat /sdcard/je-ui.xml > ui.xml
   adb shell rm /sdcard/je-ui.xml
   ```

   `ui.xml`의 노드마다 `text`와 `bounds="[왼,위][오른,아래]"`가 있다. 글과 자리만 뽑아 보려면:

   ```python
   import re
   x = open("ui.xml", encoding="utf-8").read()
   for t, b in re.findall(r'text="([^"]*)"[^>]*?bounds="([^"]*)"', x):
       if t:
           print(t.replace("⁠", ""), b)
   ```

6. **누른다.** `adb shell input tap <x> <y>`. 누를 곳은 5의 `bounds` 가운데로 정한다. 뒤로는 `adb shell input keyevent KEYCODE_BACK`.
7. **스크린샷을 찍는다.** `adb exec-out screencap -p > shot.png`. 에이전트는 이 그림을 읽어 모양과 색을 본다.
8. **소리가 끝까지 났는지 센다.** 귀로 듣지 않아도 `adb logcat`의 `AudioTrack stop(...) called with N frames delivered`를 소리 파일의 샘플 수와 맞대면 끝까지 틀었는지 안다.

## 겪은 것

- **한국어 글로 찾으면 빗나간다.** 이 앱은 안드로이드가 한국어를 낱말 가운데서 줄 바꾸지 않게 한글 사이에 단어 이음 문자(U+2060)를 넣는다(`app/src/ui/keepWords.ts`). 화면에는 보이지 않지만 `uiautomator dump`의 `text`에는 들어 있다. 글로 찾을 때는 이 문자를 빼고 맞추거나 `bounds`로 찾는다.
- **그림 글자는 숫자 문자 참조로 나온다.** `uiautomator dump`는 🎤, 💬 같은 그림 글자를 `&#127908;`, `&#128172;`처럼 적는다. 그림 글자가 붙은 버튼은 그림 글자를 빼고 뒤의 글로 찾거나, 참조를 풀어 맞춘다(Python `html.unescape`).
- **잠깐 보이는 상태는 기다렸다가 바로 누른다.** 몇 초만 보이는 화면은 `uiautomator dump`를 짧게 되풀이하다가 원하는 버튼이 나오자마자 누르고 캡처한다. dump 한 번에 1초 안팎이 들어, 이렇게 잰 시간은 실제보다 길다. 걸린 시간은 서버 로그로 따로 잰다.
- **에뮬레이터 마이크에 녹음 넣기 (2026-11-08 three-line-listen):** 폰이 없을 때 앱의 녹음 흐름까지 보려면 `adb -s <에뮬레이터> emu avd hostmicon`으로 에뮬레이터 마이크가 맥 마이크를 쓰게 하고, 앱이 녹음하는 동안 학습자 목소리 녹음을 `afplay`로 맥 스피커에 튼다.
  - 녹음마다 다시 켠다. 켜 둔 것이 몇 분 뒤 꺼져, 그 사이 녹음 둘이 조용한 소리로 들어가 「잘 안 들렸어요」가 나왔다.
  - 스피커에서 마이크로 넘어가며 소리가 흐려진다. 같은 문장이 두 번은 잘 들렸고, 두 번은 엉뚱한 한국어로 받아써져 선생님 라이언(글쓰기 모델, 녹음 하나에 0.7센트쯤)이 답했다. 녹음을 많이 넣을 시험은 폰이나 서버로 바로 보내는 시험(`DEVENV_폰없이_녹음_시험하기_20261108.md`)으로 한다.
  - 소리 없는 시도도 맥에 녹음 번호를 하나 쓴다.
  - 맥 마이크는 주변 소리도 받는다. 머지 뒤 확인에서 튼 녹음 대신 맥 둘레의 다른 말소리가 녹음되어 받아써졌다. 사용자의 공간에서 난 소리일 수 있으니, 녹음이 끝나면 바로 `emu avd hostmicoff`로 끄고, 그 녹음이 든 시험 복사본은 바로 지운다. 받아쓴 글은 어디에도 옮기지 않는다.
- **시험하던 사이 사용자가 폰을 집어 다른 앱을 열었다 (2026-11-08 first-screen-buttons).**
  - 증상: 화면 읽기 사이 1분쯤 지나 「대화 연습하기」 자리를 눌렀는데, 그사이 앞에 떠 있던 것은 다른 앱이었다. 누르기 두 번이 그 앱에 닿았을 수 있고, 다음 화면 읽기에서 다른 앱의 화면이 찍혔다. 몇 초 뒤 폰이 USB에서 빠졌다. 사용자는 그때 폰으로 이 앱 화면을 찍어 보고 있었다.
  - 원인: 누르기 전에 앞에 떠 있는 앱을 보지 않았다. `adb shell input tap`은 지금 앞에 있는 화면 어디든 누른다. 전에 읽은 자리로 누르면 그사이 바뀐 화면의 다른 것이 눌린다.
  - 고친 것: 누르기와 화면 읽기를 앞의 앱을 보는 작은 스크립트로만 했다. 다른 앱의 화면을 찍은 스크린샷은 바로 지웠다. 그 화면의 내용은 어디에도 옮기지 않는다. 남은 확인은 에뮬레이터로 했다.

    ```sh
    f=$(adb -s "$DEV" shell dumpsys window | grep -m1 mCurrentFocus)
    case "$f" in *dev.jakeso.english*) adb -s "$DEV" shell input tap "$1" "$2";; *) echo "STOP: not jake-english in front"; exit 3;; esac
    ```

  - 같은 실수를 막는 방법: 위 「정한 기준」의 「누르기 전에 앞에 떠 있는 앱이 이 앱인지 본다」. 앱을 깔기 전에 main 세션에 알리는 것은 그대로 하고, 폰을 쓰는 동안 사용자가 폰을 집을 수 있다는 것도 함께 알린다.
- **글로 누를 때는 같은 글이 든 다른 곳을 조심한다.** 「다음」 버튼을 글로 찾아 눌렀더니, 라이언의 평가 「…다음 대사로 넘어가요」 말풍선이 먼저 걸려 그것이 눌렸다. 버튼은 글 전체가 같은 노드로 찾거나 `bounds`로 누른다.
- **스크롤이 끝난 뒤의 자리로 누른다.** 이 앱은 새 말풍선이 생기면 조금 뒤 끝으로 스크롤한다. 그 전에 읽은 `bounds`로 누르면 다른 말풍선이 눌린다. 누르기 바로 전에 다시 읽는다.
- **어느 소리가 났는지 프레임 수로 가린다.** 같은 문장의 녹음도 길이가 조금씩 다르다. `logcat`의 `frames delivered`는 그 파일의 길이 × 표본 빈도라, 맥의 녹음 파일을 `ffprobe`로 재어 맞대면 말풍선마다 자기 녹음이 났는지 가릴 수 있다(예: 44.1kHz 8.45초 → 372,736 프레임).
- **에뮬레이터에서 괜찮아도 폰에서 다를 수 있다.** 아래 버튼 줄의 높이(세 버튼과 제스처)와 상태 줄 높이가 달랐다. 폰이 꽂혀 있으면 폰을 먼저 본다.
- **두 버튼을 빠르게 이어 누르기 (2026-11-08 record-cancel-skip):** `adb shell "input tap x1 y1; input tap x2 y2"`처럼 한 셸 안에서 이어 부르면 두 누름이 사람의 두 번 누름만큼 가깝게 들어간다. adb를 두 번 부르면 사이가 벌어져 다시 그린 뒤의 화면을 누르게 된다.
- **폰 폭(360dp)을 에뮬레이터로 보기 (2026-11-08):** 이 앱 에뮬레이터는 1080×2400, 밀도 420이라 폭이 411dp쯤이다. `adb shell wm density 480`으로 바꾸면 360dp가 된다. 밀도를 바꾸면 앱이 처음 화면으로 다시 뜬다. 끝나면 `wm density reset`으로 되돌린다.
- **맥 스피커 소리가 마이크에 작게 들어갈 때 (2026-11-08):** 맥의 소리 크기를 바꾸지 않고 `afplay -v 4 x.m4a`로 그 파일만 크게 튼다. 그대로 틀었더니 녹음이 작아 「잘 안 들렸어요」로 끝났다. 그 녹음은 방 소리가 들었을 수 있어 바로 지웠다.
- **녹음 뒤에만 보이는 화면을 마이크 없이 보기 (2026-11-08 heard-line):**
  - 증상: 방금 녹음한 내 말 줄(평가 자리의 들린 말)을 보려고 에뮬레이터 마이크를 켜고 학습자 목소리 녹음을 `afplay -v 4`로 틀었다. 들린 말에는 튼 녹음이 아니라 맥 둘레의 다른 말소리만 받아써졌다. 맥 소리가 마이크에 닿지 않은 까닭은 확인하지 않았다.
  - 고친 것: 마이크를 바로 끄고(`hostmicoff`), 그 녹음이 든 시험 복사본과 화면 덤프를 지웠다. 받아쓴 글은 어디에도 옮기지 않았다. 마이크로 다시 하지 않고, 지어낸 글을 그 자리에 넣는 임시 코드로 APK를 빌드해 모양과 누르기만 봤다. 빌드가 끝나면 바로 `git checkout -- <파일>`로 되돌리고 `git status`가 깨끗한지 본 뒤 깔았다. 시험이 끝나면 깨끗한 코드로 다시 빌드해 깔아, 임시 코드가 든 앱을 남기지 않는다.
  - 같은 실수를 막는 방법: 녹음 뒤의 화면 모양과 누르기만 볼 때는 마이크보다 임시 빌드를 먼저 쓴다. 녹음 흐름 자체를 봐야 할 때만 마이크를 쓰고, 첫 녹음의 들린 말이 튼 문장인지부터 본다. 아니면 거기서 멈춘다.
- **깐 뒤 곧바로 띄우면 앱이 두 번 떠 소리가 겹친다 (2026-11-08 noisy-room).**
  - 증상: 사용자가 「라이언 목소리가 에코 되어 나온다」고 했다. 폰 기록(`adb logcat`의 `APM_AudioPolicyManager` startOutput/stopOutput)을 보니, 첫 화면 인사 두 줄이 서로 다른 재생 세션에서 0.6초 차이로 두 번씩 났다.
  - 원인: 앱이 앞에 떠 있을 때 `adb install -r`로 깔면, 삼성 폰이 업데이트 뒤 앱을 저절로 다시 띄운다(systemui `PackageUpdateActivity`, 기록에 `CorePackageUpdate`). 그 사이 `monkey`로 또 띄우자 앱 화면이 두 번 그려졌다. 먼저 뜬 화면은 닫혔지만, 그 화면의 소리 대기열이 넣어 둔 인사를 끝까지 틀었다. 앱 쪽 정리는 할 일 `20261108_42_todo_sound_queue_after_remount.md`.
  - 고친 것: 깐 뒤 5초 기다려 앞의 앱을 보고, 이 앱이 떠 있으면 띄우지 않는다. 런처나 업데이트 화면이면 한 번만 띄운다. 그 뒤로는 겹치지 않았다.
  - 막는 방법: 위 「명령」 4. 소리가 겹쳤다는 말을 들으면, 먼저 폰 기록에서 같은 길이의 재생이 겹쳐 시작했는지와 그 세션 번호를 본다. 폰 기록은 오래 남지 않으니 바로 받아 둔다.
- **zsh에서 adb 경로를 변수에 담을 때 (2026-11-08):** `E="$A -s emulator-5556"; $E shell …`은 zsh가 낱말을 나누지 않아 「그런 파일이 없다」로 실패한다. 그사이 `hostmicon`이 빠진 채 녹음이 무음으로 갔다. `"$A" -s emulator-5556 …`처럼 매번 쓴다.
- **소리를 내는 것과 여는 것을 가린다 (2026-11-08 leftover-minors):** 대화 화면과 끝 화면의 말풍선은 누르면 열기만 한다. 소리는 그 안의 「🔊 듣기」, 「🔊 내 녹음」과 아래 「🔊 다시 듣기」가 낸다. 실패하는 소리 뒤에 말풍선을 눌러 「두 번째 소리가 나는지」를 보려다, 두 번째 소리가 처음부터 없어 시험이 헛돌았다. 두 소리를 이어 누르는 시험은 먼저 하나씩 눌러 `logcat`에 그 소리(`frames delivered`나 `Source error`)가 잡히는지 대조부터 본다.
- **받을 수 없는 소리는 3초 뒤에 오류가 난다 (2026-11-08 leftover-minors):** 앱의 플레이어는 맥이 404를 주어도 3초쯤 다시 받아 본 뒤 `logcat`에 `Source error`와 `Response code: 404`를 남긴다. 녹음을 뺀 데이터 복사본에서는 「🔊 내 녹음」이 모두 이렇게 실패한다. 다른 소리의 실패를 시험할 때는 복사본의 `audio/`에서 그 소리 파일만 잠깐 빼고, 끝나면 되돌린다.
- **마이크 입력을 꺼 둔 에뮬레이터에서도 녹음은 켜진다 (2026-11-08 leftover-minors):** `hw.audioInput=no`여도 「🎤 말하기」를 누르면 시작 소리, 빨간 동그라미, 「● 말하기 끝」이 나오고 조용한 녹음이 맥에 간다. 녹음 중 화면과 평가를 기다리는 화면, 권한 거절은 에뮬레이터로 본다. 권한 거절은 `adb -s <에뮬레이터> shell pm revoke dev.jakeso.english android.permission.RECORD_AUDIO`로 회수한 뒤 앱이 묻는 창에서 「Don't allow」를 누르고, 끝나면 `pm grant`로 되돌린다. 회수하면 앱이 다시 뜬다. 폰에서는 사용자의 권한이라 하지 않는다.
