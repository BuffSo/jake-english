# SPEECH 자유 대화의 기다림과 한국어 가르기

> 작성: 2026-11-08 (자유 대화 PR 1, free-talk)
> 스펙: `docs/superpowers/specs/2026-11-08-free-talk-design.md`

대본 없이 AI 대화 상대와 말로 주고받는 화면을 만들 때 따를 기준과, 만들며 겪은 문제다. 사용자가 말을 마치고 상대의 첫 소리가 나기까지 얼마나 걸리는지, 영어로 말했는데 한국어로 알아듣는 문제를 어떻게 다뤘는지가 중심이다. 이 문서만 읽고 다른 프로젝트에서 같은 방식을 쓸 수 있게 썼다. 받아쓴 글과 상대의 답은 옮기지 않고 숫자와 지어낸 예만 쓴다.

## 기준

### 1. 「말하기」는 영어로만 받아쓰고, 한글이 섞이면 한국어로 다시 받아쓴다

- 받아쓰기(whisper)의 자동 언어 판별은 영어를 한국어로 잘못 알아듣는다. 영어로 말한 녹음 54개를 자동 언어로 넣었더니 14개(26%)를 한국어로 알아들었다. 한국어 확률이 0.96인 것도 있었다. 한국어로 말한 녹음 5개의 한국어 확률은 0.73~1.00이라 숫자로 깔끔하게 갈리지 않았다.
- 영어 받아쓰기와 한국어 받아쓰기의 확신도(토큰 로그 확률 평균)를 견주는 방법도 봤다. 영어 54개 중 7개가 한국어 쪽이 높았고, 한국어 12개 중 4개가 영어 쪽이 높아 이것도 갈리지 않았다.
- 그래서 기본 버튼 「🎤 말하기」는 영어로 고정해 받아쓴다. 자동 언어를 쓰지 않으니 차례마다 0.85초 빠르다(영어 고정 0.39초, 자동 언어 0.85초).
- 영어로 고정한 받아쓰기에 한글이 한 글자라도 있으면 한국어로 말한 것이다. 한국어로 고정해 다시 받아쓰고, 그 글을 화면에 보이고, 대화 상대(Claude)에는 보내지 않은 채 정해진 말로 「영어로 말해 볼까요?」라고 답한다. 한국어 받아쓰기가 실패해도 화면이 멈추지 않고 같은 정해진 말로 답한다.
- 한국어로 말했는데 영어로 번역되어 나오는 경우는 맥이 가를 수 없다. 지어낸 한국어 녹음 7개를 영어로 고정해 받아쓰면 3개는 한글이 섞이고 4개는 영어로 번역됐다. 번역된 것은 대개 「How do you say …?」 같은 영어였다. 그래서 대화 상대 지시문에 「어떻게 말하는지 물으면 짧은 영어 문장 하나로 알려 주고 이어 간다」를 넣고, 고쳐 주기는 그런 차례를 고치지 않는다.

### 2. 첫 소리까지의 시간을 줄이는 순서

한 차례에서 사용자가 말을 마친 뒤 상대의 첫 소리까지, 지어낸 학습자 목소리 녹음으로 맥 안에서 쟀다(받아쓰기, 모델, 목소리 합성 모두 로컬 또는 실제 호출).

| 단계 | 시간(중앙값) |
|---|---|
| 녹음을 WAV로 바꾸고 소리 크기 보기 | 0.05초 |
| 받아쓰기(영어 고정) | 0.39초 |
| 상대 답(Sonnet) 첫 글자 / 첫 문장 / 다 만듦 | 0.74 / 1.46 / 1.54초 |
| 영어 목소리: 첫 문장(6낱말쯤) / 답 전체(24낱말쯤) | 1.2 / 3.9초 |

- **답을 다 받고 한 번에 목소리를 만들면 6.7초, 첫 문장이 나오는 대로 만들면 3.9초**였다(자동 언어 받아쓰기 포함). 줄어드는 2.8초는 거의 다 목소리다. 답이 짧아 모델 쪽은 거의 같다. 그래서 문장마다 목소리를 만들어 먼저 나온 것부터 보낸다.
- **첫 문장을 짧은 맞장구(2~5낱말)로 하게 한다.** 첫 문장 목소리가 짧아져 첫 소리가 빨라진다. 같은 맞장구가 되풀이되지 않게 같은 대화에서 쓴 것으로 시작하지 않게 한다.
- **끊은 답의 남은 소리는 새 답 뒤로 미룬다.** 목소리를 만드는 작업 프로세스가 하나라, 미루지 않으면 사용자가 끊은 답의 남은 문장(1~3초)이 새 답의 첫 문장 앞에 끼어 든다. 남은 소리는 나중에 다시 듣는 데 쓰므로 버리지 않고 대기열 뒤에 둔다. 확인: 들은 문장 수를 1로 두고 끊은 두 번째부터의 첫 소리가 2.23 / 2.73 / 1.82초로, 끊지 않은 때(2.33~2.92초)와 같았다.
- **첫 질문의 소리는 서버가 켜질 때 미리 만든다.** 질문 열 개쯤을 미리 써 두고 돌려 쓰므로, 카드를 누르면 기다리지 않고 말한다.

### 3. 대화 상대 모델은 일마다 견준다

지어낸 대화 열 경우(첫 대답, 한 낱말 대답, 문법 실수, 받아쓰기가 잘못 적은 낱말, 되묻기, 「모르겠어요」, 긴 대답, 대화 후반, 갑자기 바꾼 화제, 알아들을 수 없는 말)를 세 번씩 두 모델에 번갈아 물었다. 지시문을 다듬은 뒤의 값이다. 견주는 방법의 일반 기준은 `PROMPT_일마다_모델_견주기_20261108.md`다.

| 모델 | 첫 글자 / 첫 문장 | 규칙에 걸린 답 | 한 번 값 |
|---|---|---|---|
| Sonnet 5.5(생각 끔, effort low) | 0.79초 / 1.50초 | 30번 중 2번 | 0.13센트 |
| Haiku 5.5(생각 끔) | 0.61초 / 0.89초 | 30번 중 10번(첫 문장이 7~12낱말) | 0.007센트 |

- Haiku는 첫 글자가 빠르지만 첫 문장이 길어 첫 문장 목소리가 길어진다. 첫 소리까지는 둘이 비슷하고, Sonnet의 말이 더 자연스러웠다. 그래서 기본은 Sonnet이고 설정(`JE_CLAUDE_TALK`)으로 바꿀 수 있다.
- 구현 뒤에 같은 견주기를 다시 돌렸다(11경우 × 3번, 모델마다 33번). 규칙에 걸린 답은 Sonnet 6, Haiku 13이었다. Sonnet의 6 중 3은 「어떻게 말해요」 답에 큰따옴표가 든 것(서버가 지운다), 3은 문장을 넷 쓴 것이라 지시문은 그대로 뒀다.

### 4. 시간 숫자

| 구간 | 값 |
|---|---|
| 맥 안, 영어 차례의 첫 소리(16차례, 지시문 확정 뒤) | 중앙값 2.69초(범위 1.82~6.78). 켠 지 얼마 안 된 서버 첫 실행 3.64초, 데워진 뒤 2.17과 2.49초 |
| 폰 끝(누름 → 라이언 첫 소리, 3차례) | 3.31 / 4.03 / 4.10초, 중앙값 4.03초 |
| 폰이 더하는 시간(올리기, 받기, 재생 시작) | 0.22~0.23초로 고르다 |
| 대화 끝내기 → 돌아보기의 첫 소리 | 고칠 곳이 없을 때 1.45초. 고칠 곳이 있을 때 첫 고침의 설명과 본보기 소리는 6.3~13.1초 |

- 목표는 맥 안 3초, 폰 5초였다. 폰 값은 목표 안이다. 맥 안은 데워진 서버에서는 안이고, 켠 직후 첫 실행은 넘는다(목소리 모델이 처음 불리는 값이 6초대).
- 늦어지는 몫은 거의 다 「첫 글자 → 첫 소리」, 즉 첫 문장의 목소리 만들기(1.7~2.7초)다.
- 고칠 곳이 있을 때의 6.3~13.1초는 목표 밖이다. 고쳐 주기 한 번이 Claude 호출과 설명·본보기 목소리를 다 거치기 때문이다.

## 겪은 문제와 해결

### 맞는 영어를 다듬어 고친 문제

- **증상:** 고쳐 주기가 맞고 뜻이 통하는 문장을 더 자연스럽게 바꿔 「고친 곳」으로 냈다. 지어낸 예로 「I ate lunch」를 「I had lunch」로, 「I am」을 「I'm」으로. 설명에 「문법은 맞아요」라고 써 놓고도 고쳤다.
- **원인:** 모델이 「더 나은 문장」을 내는 쪽으로 기운다. 고칠 것이 없으면 비워 두라는 말만으로는 부족했다.
- **고친 것:** 고쳐 주기 지시문에 「맞고 자연스러운 문장은 다듬느라 고치지 않는다, 쉼표나 더 흔한 낱말만으로는 고친 곳이 아니다, 확신이 없으면 목록을 비운다」를 넣었다. Sonnet이 분명히 잘못 고친 것이 21번 중 5번에서 14번 중 2번으로 줄었다. 「I am」→「I'm」은 사라졌다.
- **남은 것:** 「ate lunch」→「had lunch」 같은 낱말 바꿈은 지시문에 안 고칠 것으로 이름을 적어도 남았다(3번 중 3번). 맥 쪽 검사로도 가를 수 없어 받아들였다.
- **막는 법:** 고쳐 주기를 바꿀 때마다 맞는 문장을 섞은 지어낸 입력으로 `compare_fix_models.py`를 돌려 틀린 고침을 읽어서 센다. 지시문 규칙을 더한 뒤에는 같은 입력으로 다시 돌려 틀린 고침이 줄었는지 센다.

### 지시문 안의 틀을 그대로 베낀 문제

- **증상:** Haiku가 발음 짐작 문장을 채우지 않고 지시문의 틀(「meant가 heard처럼 들렸어요.」)을 그대로 냈다. 두 번 돌린 3번 중 2번.
- **원인:** 서버의 검사가 한글이 있는지와 「처럼 들렸」만 봤다. 틀이 그 둘을 다 갖췄다.
- **고친 것:** `say_ko`에 짐작한 낱말 둘이 모두 들어 있어야 통과하게 했다. 틀을 베낀 것은 버린다. Sonnet은 3번 중 3번 채워 냈다.
- **막는 법:** 모델이 채우는 자리에는 채웠는지(두 낱말이 실제로 든 것)를 검사한다. 모양이 맞는지만 보지 않는다.

### 첫 화면 세 번째 카드가 폰에서 잘린 문제

- **증상:** 카드를 둘에서 셋으로 늘리자, 폭 360dp 폰에서 세 번째 「복습하기」 카드의 설명이 화면 밖으로 밀리고 제스처 막대가 카드 위에 겹쳤다. 에뮬레이터에서도 같았다.
- **원인:** 라이언 그림이 고정 높이라 카드가 늘어난 만큼 아래로 밀렸다.
- **고친 것:** 그림만 줄어들게 했다(`flexShrink: 1`, 최소 높이 120). 4:5 비율을 지키며 좁아지고 가운데에 남는다. 폭 360×780dp, 360×800dp, 411×914dp에서 카드 셋이 다 보이고 맨 아래가 제스처 막대 위로 20dp 남는다. 다 들어갈 때는 원래 크기다.
- **막는 법:** 첫 화면에 요소를 더하면 폰 크기(360dp 폭)의 에뮬레이터에서 맨 아래까지 보이는지 본다. 단위 시험으로는 잡히지 않는다.

### 마이크가 꺼진 에뮬레이터에서 말하는 차례를 시험하기

- **증상:** 에뮬레이터의 마이크 입력이 꺼져 있어 앱이 보낸 녹음이 무음이다. 서버의 소리 크기 검사가 무음 녹음을 받아쓰기 전에 버려 말하는 차례를 시험할 수 없다.
- **해결:** 시험 서버만 PATH 앞쪽에 시험용 `ffmpeg` 감싸기를 두었다. 서버가 녹음을 WAV로 바꿀 때 큐에 문장이 있으면 녹음 대신 지어낸 문장(맥 `say`로 만든 것)을 바꿔 넣는다. 저장소는 건드리지 않는다. 앱의 녹음과 올리기, 받아쓰기, 실제 모델, 목소리, 화면은 그대로 진짜다. 이 방법으로는 「내 녹음 들어 보기」가 무음을 튼다.
- **막는 법:** 폰이 쓰이는 중이거나 마이크를 못 쓰면 이 방법으로 하고, 시험 기록에 어떤 부분이 진짜가 아니었는지 적는다. 방법의 다른 부분은 `DEVENV_폰없이_녹음_시험하기_20261108.md`.

### 앱의 서버 주소를 바꿔 다시 빌드했는데 옛 주소가 남은 문제

- **증상:** `.env`의 서버 주소만 바꿔 release 빌드했는데 앱이 옛 주소에 붙었다.
- **원인:** Gradle이 `.env`만 바뀐 것은 JS 번들 변화로 보지 않고 번들을 다시 만들지 않았다.
- **고친 것:** `app/build/generated` 아래 release 번들(`index.android.bundle*`)을 지우고 다시 빌드했다.
- **막는 법:** 깐 뒤가 아니라 깔기 전에 APK 안에서 주소를 찾아 본다(`unzip -p … | grep`).

## 닿지 못한 길

- **영어 받아쓰기에 한글이 섞이는 길(한국어로 다시 받아쓰기)과 발음 짐작 문장:** 학습자 목소리를 합성한 녹음으로는 닿지 못했다. 합성한 한국어 녹음은 영어 고정 받아쓰기에서 영어 번역이나 로마자로 나왔고 한글이 안 나왔다. 발음 짐작은 합성 목소리가 틀리게 발음하지 못해 짐작할 일이 없었다. 두 길은 단위 시험으로만 확인했다. 사람이 직접 말해 확인할 수 있을 때 한다.
- 합성 녹음 시험은 영어 차례와 끝내기를 확인했다. 한국어 녹음이 영어로 번역된 길은 「How do you say …?」 질문으로 이어져, 상대가 짧은 영어 문장 하나를 알려 주고 이어 갔다.

## 확인 방법

모두 `server/`에서 돌린다. 실제 Claude를 부르므로 돈이 든다(구독 밖 API 크레딧). 이 PR에서 쓴 값은 대화 상대 견주기 0.08달러쯤, 고쳐 주기 견주기 0.16달러쯤, 녹음 시험 0.05달러쯤이다. 시험 서버는 launchd 서버와 다른 포트에 따로 띄운다(`DEVENV_맥서버_저절로_띄우기_20261107.md`).

```
uv run python scripts/compare_talk_models.py [--runs 3] [--only N]
uv run python scripts/compare_fix_models.py [--runs 3] [--only N] [--models sonnet haiku]
uv run python scripts/try_talk.py --port 8791 a.m4a b.m4a [--heard 1] [--end] [--show]
```

- `compare_talk_models.py`: 지어낸 대화 경우를 두 모델에 번갈아 물어 시간과 규칙에 걸린 답을 센다.
- `compare_fix_models.py`: 지어낸 대화의 고쳐 주기를 모델마다 돌려 남긴 고침 수와 맞는 문장을 고친 것을 센다. 틀린 고침은 출력을 읽어 직접 센다.
- `try_talk.py`: 시험 서버에 녹음을 앱처럼 보내 차례마다 받아쓰기, 첫 글자, 첫 소리, 끝까지의 시간을 찍는다. `--heard 1`은 두 번째 차례부터 앞 답을 첫 문장까지 들은 것으로 쳐서 끊은 때의 첫 소리를 잰다. `--end`는 대화를 끝내 고침 수를 센다. 받아쓴 글과 상대의 답은 `--show`를 줘야 터미널에만 나오고 파일에는 남지 않는다.
- 폰 구간은 `DEVENV_폰을_adb로_시험하기_20261108.md`의 방법으로 잰다. 한 가지 더: 화면 녹화(`screenrecord`)는 끝난 뒤에 받는다. 끝나기 전에 받으면 mp4가 깨진다.
