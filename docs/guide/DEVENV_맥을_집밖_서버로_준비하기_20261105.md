# 맥을 집 밖에서 쓰는 서버로 준비하기

> 작성: 2026-11-05
> 관련 결정: ADR-0007(집 밖에서는 Tailscale), ADR-0002(맥에서 빌드해 APK 직접 설치)
> 개인 값(맥과 폰의 주소, 기기 이름, 망 이름)은 비공개 메모에만 둔다.

폰 앱이 집 밖에서도 집의 맥 서버에 붙게 하려고 세 가지를 준비했다. Tailscale로 맥과 폰을 한 망에 묶고, 맥이 잠들지 않게 하고, 안드로이드 빌드에 쓸 JDK 17을 깔았다. 이 문서는 그때 정한 기준과 겪은 문제를 담는다. 다른 프로젝트에서 같은 준비를 할 때 이 문서만 읽으면 되게 썼다.

## 정한 기준

### Tailscale은 Standalone 판을 공식 설치 파일로 깐다

macOS용 Tailscale은 세 가지 판이 있다.

| 판 | 어떻게 까나 | 판단 |
|---|---|---|
| Standalone | 공식 사이트의 pkg, 또는 homebrew cask `tailscale-app`(같은 pkg) | 공식 문서가 권한다. 이것을 쓴다 |
| Mac App Store | 앱 스토어 | Standalone을 못 쓸 때만 쓰라고 한다. 스크린 타임 웹 필터가 켜져 있으면 제대로 돌지 않는다 |
| tailscaled | homebrew formula `tailscale`(오픈소스, CLI만) | 화면이 없고, 공식 문서가 일반 사용을 권하지 않는다 |

- Standalone과 앱 스토어 판을 함께 깔지 않는다. 둘이 같이 있으면 확장이 제대로 뜨지 않을 수 있다.
- 에이전트가 깔 때는 pkg를 직접 받는다. homebrew cask도 pkg를 돌리는데, 관리자 암호를 터미널에서 넣어야 해서 에이전트가 끝낼 수 없다.
  1. 최신 파일 이름은 `https://pkgs.tailscale.com/stable/`에서 찾는다(`Tailscale-<버전>-macos.pkg`).
  2. 같은 주소에 `.sha256`을 붙인 파일과 체크섬을 견준다.
  3. `pkgutil --check-signature <pkg>`로 서명자가 Tailscale Inc.이고 애플 공증을 받았는지 본다.
  4. `open <pkg>`로 설치 창을 띄운다. 「계속」, 「설치」, 암호 입력은 사용자가 한다.
- 계정 로그인도 사용자가 한다. 폰 앱은 사용자가 Play 스토어에서 깔고 같은 계정으로 로그인한다.
- 맥 서버를 인터넷에 여는 기능(Funnel, 포트 전달, 공개 터널)은 쓰지 않는다(ADR-0007).

### 연결 시험은 Tailscale 주소에만 연 임시 서버로 한다

```sh
mkdir -p <임시 폴더> && cd <임시 폴더>
printf '<h1>Tailscale OK</h1>\n' > index.html
python3 -m http.server 8765 --bind <맥의 Tailscale 주소>
```

- `--bind`로 Tailscale 주소에만 연다. 그러면 같은 와이파이의 다른 기기에서는 보이지 않는다.
- 폰은 와이파이를 끄고 모바일 데이터로만 연결한 채 `http://<맥의 Tailscale 주소>:8765`를 연다. 집 밖과 같은 조건이다.
- 폰 화면만 보지 말고 서버 기록도 본다. 폰의 Tailscale 주소에서 온 요청이 남아야 한다.
- 시험이 끝나면 서버를 끄고, `lsof -nP -iTCP:8765 -sTCP:LISTEN`이 비었는지 본다.

### 맥 잠자기는 전원에 꽂혀 있을 때만 끈다

```sh
pmset -g custom          # 바꾸기 전 값을 적어 둔다
sudo pmset -c sleep 0    # -c는 전원 연결(AC)일 때만
```

- 배터리일 때 설정은 그대로 둔다. 화면은 꺼져도 된다(`displaysleep`은 그대로).
- 노트북은 뚜껑을 닫으면 이 설정과 관계없이 잠든다. 뚜껑은 열어 둔다. 예외는 외부 모니터를 꽂고 뚜껑을 닫아 쓰는 경우(클램셸 모드)다.
- 뚜껑을 닫아도 안 잠들게 하는 `sudo pmset -a disablesleep 1`도 있다. `man pmset`에 나오지 않는 숨은 옵션이다. 가방에 넣으면 뜨거워질 수 있어서 쓰지 않았다.
- 되돌릴 때는 적어 둔 값으로 `sudo pmset -c sleep <값>`을 실행한다.
- 관리자 명령은 에이전트가 실행할 수 없다. `sudo -n`은 `sudo: a password is required`로 멈춘다. 명령을 보여 주고 사용자가 터미널 앱에서 실행한다.

### JDK 17은 사용자 Java 폴더에 풀어 두고, 빌드할 때 고른다

React Native 공식 문서는 JDK 17을 권하고, 더 높은 버전은 문제가 생길 수 있다고 적는다. 이미 더 높은 JDK가 있으면 그것을 지우거나 기본값을 바꾸지 않고 17을 옆에 둔다.

1. Adoptium API로 최신 17의 파일 주소와 체크섬을 얻는다.

   ```sh
   curl -fsSL 'https://api.adoptium.net/v3/assets/latest/17/hotspot?architecture=aarch64&image_type=jdk&os=mac&vendor=eclipse'
   ```

   답은 배열이다. `[0].binary.package`에 `link`(tar.gz 주소)와 `checksum`(SHA-256)이 있다.
2. 받아서 `shasum -a 256`으로 체크섬을 견준다.
3. 빈 폴더에 풀고, `codesign -dvv <풀린 폴더>/Contents/Home/bin/java`로 서명자가 Eclipse Foundation인지 본다.
4. `~/Library/Java/JavaVirtualMachines/temurin-17.jdk`로 옮긴다. 사용자 폴더라 관리자 권한이 필요 없다.
5. `/usr/libexec/java_home -V`에 17이 보이는지, 기본 `java -version`이 그대로인지 본다.

빌드할 때 고른다. 명령 앞에 붙이면 그 명령에만 쓰인다.

```sh
JAVA_HOME="$(/usr/libexec/java_home -v 17)" npx expo run:android
```

- `export JAVA_HOME=...`으로 쓰면 그 터미널 창을 닫을 때까지 남는다. 다른 창과 다른 프로젝트에는 영향이 없다.
- 셸 설정에 넣지 않는다. 다른 프로젝트의 Java까지 바뀐다.
- `gradle.properties`의 `org.gradle.java.home`에 경로를 적지 않는다. 공개 저장소에 홈 폴더 경로가 들어간다.
- Gradle은 Java 위치가 다른 데몬을 다시 쓰지 않고 새로 띄운다. 그래도 빌드가 다른 JDK를 쓰면 `./gradlew --stop` 뒤 다시 빌드한다.
- 자동 업데이트는 없다. 새 17 패치가 필요하면 같은 방법으로 받아 폴더를 바꾼다.

### 서버로 쓰는 맥은 Tailscale 키 만료를 끈다 (2026-11-05 결정)

Tailscale은 기기 키를 기본 180일마다 만료시킨다. 만료되면 그 기기는 다시 로그인해야 망에 붙는다. 집 밖에서 쓰다가 맥이 갑자기 망에서 빠지면 앱이 쓸 수 없게 된다.

- **정한 것:** 맥만 키 만료를 껐다. 폰은 기본(180일)대로 둔다.
- **이유:** 망에는 사용자 본인의 기기만 있어 위험이 작다. 맥은 늘 붙어 있어야 하는 서버 역할이다. Tailscale도 서버로 쓰는 기기는 키 만료를 끄라고 안내한다.
- **방법:** 관리 콘솔 → Machines → 맥 줄의 「…」 → 「Disable key expiry」.
- **확인:** 같은 메뉴가 「Enable key expiry」로 바뀌면 꺼진 것이다. 되돌릴 때도 이 메뉴를 쓴다.

## 겪은 문제와 해결

### homebrew `openjdk@17`이 이미 깔린 다른 패키지까지 올린다

- **증상:** 관리자 권한이 필요 없어서 homebrew `openjdk@17`을 추천하며 「다른 패키지는 건드리지 않는다」고 했다. 깔기 전에 확인해 보니, 의존 패키지 30개 중 이미 깔린 12개(cairo, glib, harfbuzz 등)가 낡아서 함께 올려야 했다.
- **원인:** `brew install`은 낡은 의존 패키지를 함께 올린다. bottle(homebrew가 미리 빌드해 둔 파일)은 최신 의존 패키지에 맞춰 빌드되어 있어서 건너뛸 수도 없다. 그 라이브러리를 쓰는 다른 도구도 같이 바뀐다.
- **고친 것:** 추천을 바로잡고 다시 고르게 했다. 공식 tar.gz를 사용자 폴더에 푸는 방법으로 바꿨다(위 기준).
- **막는 방법:** homebrew 설치를 권하기 전에 무엇이 함께 올라가는지 미리 본다. 확인하기 전에는 「다른 것은 건드리지 않는다」고 말하지 않는다.

  ```sh
  HOMEBREW_NO_AUTO_UPDATE=1 brew install --dry-run <formula>   # "Would upgrade N dependencies"가 나오면 함께 바뀐다
  ```

### 시스템 확장을 승인해도 Tailscale 창이 한동안 모른다

- **증상:** 시스템 설정 → 일반 → 로그인 항목 및 확장 프로그램 → Tailscale의 (i)에서 「네트워크 확장 프로그램」을 켜고 암호를 넣었다. 그 뒤에도 Tailscale 창은 「System Extension Approval Required」를 보이고 「Next」가 꺼져 있었다. 같은 내용의 안내 창도 다시 떴다.
- **확인:** `systemextensionsctl list`에서 Tailscale 확장이 `[activated enabled]`면 승인된 것이다.
- **해결:** 기다렸다. 몇 분 뒤 창이 「Granted」로 바뀌었다.
- **하지 않을 것:** AppleScript로 앱을 끄는 것은 `사용자가 취소함. (-128)`로 거절된다. 확장을 승인하기 전에는 Standalone 판의 CLI(`/Applications/Tailscale.app/Contents/MacOS/Tailscale status`)도 답 없이 멈춘다. 승인 여부는 `systemextensionsctl`로, 상태는 창으로 본다.

### 첫 설정의 「Start at login」 스위치가 켜지지 않는다

- **증상:** 첫 설정 화면의 「Start at login」 스위치가 사용자가 눌러도 켜지지 않았다.
- **고친 것:** 건너뛰고, 로그인 항목에 직접 넣었다. 결과에 `login item UNKNOWN`이 찍혀도 정상이다.

  ```sh
  osascript -e 'tell application "System Events" to make login item at end with properties {path:"/Applications/Tailscale.app", hidden:false}'
  osascript -e 'tell application "System Events" to get the name of every login item'   # 확인
  ```

- **왜 필요한가:** 맥을 다시 켰을 때 Tailscale이 켜지지 않으면 폰이 맥에 붙지 못한다.
- **한계:** 로그인 항목은 사용자가 로그인한 뒤에야 돈다. Standalone 판은 로그인 전에는 돌지 않는다(공식 문서의 판 비교표 「Run before login」). 업데이트나 정전으로 맥이 다시 켜지면, 누가 로그인할 때까지 집 밖에서 붙지 못한다.
- **정한 것 (2026-11-05):** 이 한계를 그대로 둔다. 맥 서버, 받아쓰기, 음성 합성도 사용자 로그인 뒤에 돈다. 그래서 Tailscale만 로그인 전에 켜도 앱은 쓸 수 없다. 로그인하지 않은 맥은 쓸 수 없는 것이 맞다(사용자 판단). 자동 로그인과 로그인 전에도 도는 tailscaled 판은 쓰지 않는다. macOS 업데이트 자동 설치도 끄지 않았다. 업데이트는 주로 밤에 설치되기 때문이다(사용자 판단).

### 잠자기 설정이 1분인데 맥이 잠들지 않는다

- **증상:** `pmset -g`의 `sleep`이 1(분)인데 맥이 잠들지 않았다. 그래서 이미 잠자기를 꺼 둔 것처럼 보였다.
- **원인:** 다른 앱이 잠자기를 막고 있었다(power assertion). 예를 들어 Claude Code 세션은 일하는 동안 `caffeinate -i -t 300`을 띄운다. 그런 앱이 모두 끝나면, 1분 동안 입력이 없을 때 잠든다.
- **확인:** `pmset -g assertions`에서 누가 막는지 본다. `pmset -g`의 `sleep` 줄 옆 괄호에도 막는 앱 이름이 나온다.
- **막는 방법:** 다른 앱에 기대지 않고 위 `pmset -c sleep 0`으로 정한다. 바꾼 뒤에는 `pmset -g custom`의 「AC Power」 아래 `sleep 0`을 확인한다.

### 밤사이 폰의 Tailscale이 꺼져 앱이 맥에 붙지 못한다

- **증상:** 아침에 폰에서 앱을 여니 하얀 화면 뒤에 「맥에 연결할 수 없어요」가 떴다(2026-11-06). 맥 서버는 잘 돌았다. 맥에서 같은 주소로 부르면 바로 응답했고, 앱 설정의 주소와 토큰도 서버와 맞았다.
- **원인:** 폰의 Tailscale이 새벽에 끊긴 뒤 다시 켜지지 않았다. 맥에서 본 폰의 마지막 연결 시각에, 폰의 LTE 연결도 새로 잡혔다. 네트워크가 바뀌는 순간 VPN이 끊긴 것으로 보인다. 다시 켜지지 않은 이유는 두 가지다.
  - 안드로이드의 「상시 VPN」이 꺼져 있었다. 이게 켜져 있으면 끊긴 VPN을 안드로이드가 다시 켠다.
  - Tailscale이 배터리 최적화 예외에 없었다. 갤럭시는 뒤에서 도는 앱을 밤사이 재우는 일이 잦다.
- **고친 것:** 폰에서 두 가지를 바꿨다. 상시 VPN을 켜자 Tailscale이 바로 다시 붙었다.
  1. 설정 → 연결 → 기타 연결 설정 → VPN → Tailscale 옆 톱니 → 「상시 VPN」 켜기.
  2. 설정 → 애플리케이션 → Tailscale → 배터리 → 「제한 없음」.
- **확인:** 맥에서 폰이 망에 붙어 있는지, 언제 끊겼는지 본다. 폰이 USB로 꽂혀 있으면 adb로 상시 VPN 설정도 볼 수 있다.

  ```sh
  /Applications/Tailscale.app/Contents/MacOS/Tailscale status            # 폰 줄에 offline이 보이면 끊긴 것
  /Applications/Tailscale.app/Contents/MacOS/Tailscale status --json     # 폰의 Online, LastSeen(끊긴 시각, UTC)
  adb shell settings get secure always_on_vpn_app                        # null이면 상시 VPN이 꺼져 있다
  ```

- **막는 방법:** 폰에 Tailscale을 처음 깔 때 위 두 설정을 같이 한다. 「맥에 연결할 수 없어요」가 뜨면 서버를 의심하기 전에 폰의 Tailscale 상태부터 본다.
