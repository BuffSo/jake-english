# PROMPT 주제를 넓히고 목록 대본을 쓰기

> 2026-11-08 korea-topic 카드에서 정하고 겪은 것

상황 역할극의 주제(라이언과 나의 역할, 장면)를 넓히거나 목록에 정해 둔 대본을 더할 때의 기준이다. 주제와 목록은 맥 서버의 `server/je_server/topics.py`에 있다. 주제의 영어 설명은 대본을 쓰는 모델과 제이크 추천에 그대로 들어간다.

## 정한 기준

### 목록 대본

- **쉬운 일상 낱말로 쓴다 (2026-11-08 사용자).** 이 앱의 학습자 수준은 일상 회화다. 어려운 고유 이름과 전문 낱말은 빼거나 쉬운 말로 가리킨다(「the two statues」). 박물관 초안의 「Pensive Bodhisattvas」, 「national treasures」를 보고 사용자가 「너무 어렵다」고 했고, 앞으로 새 대본은 모두 이렇게 쓰라고 했다. 장소의 이름난 것을 넣고 싶어도 그 이름이 어려우면 장면을 바꾼다.
- **쉬운 낱말이 다르게 읽히지 않는지 본다.** 「noodles」만 쓰면 국수로 읽힌다. 당면은 「glass noodles」다(사용자가 짚음). 한국 음식은 원어민이 그 낱말로 무엇을 떠올리는지 보고 고른다.
- **장소는 외국인을 실제로 만날 만한 곳으로 한다.** 사용자는 헬스장 초안을 「별로」라고 하고 「요즘 핫플레이스」를 원했다. 고궁과 박물관을 거쳐 남대문시장으로 정했다. 목록은 간접 체험이기도 해서 실제로 가 볼 만한 곳이 낫다.
- **사실은 확인한 것만 쓰고, 무엇을 확인했는지 적는다.** 대본이 말하는 사실(줄이 길다, 안에 무엇이 들었다)은 웹에서 확인하고, 그 목록 줄의 설명, 주석, 스펙에 적는다. 가게 이름과 값은 쓰지 않는다. 값은 글마다 다르고 자주 오른다. 바뀌고 있는 제도(예: 고궁의 한복 무료 입장은 다시 본다는 글이 있었다)는 대본에 넣지 않는다.
- **지어낸 작은 값도 설명에 적는다.** 이사 온 때, 머무는 날 수 같은 것이다. 대본이 설명에 없는 것을 말하면 리뷰가 짚는다(`REVIEW.md` 「목록 대본의 사실」). 시험(`test_small_talk_values_are_in_the_description`)으로 묶는다.
- **사용자 기록과 맞대 본다.** 넣을 영어와 한국어 줄을 앱 데이터 폴더의 모든 기록(대사, 통역, 들린 말, 상황)과 맞대고 개수만 찍는다. 같은 문장, 낱말 넷·다섯·여섯이 이어진 것, 지명과 값 낱말을 센다. 걸리면 내 초안 쪽 글만 찍어 어디인지 본다. 기록 쪽 글은 찍지 않는다. 세 낱말 대답(「Yes, it is.」)처럼 흔한 것은 그대로 둔다.
- **화면에 보일 글은 처음부터 대본 전부를 보낸다.** 카드 이름만 보내지 않는다. 이번에 사용자는 대본을 읽고 장소(헬스장)와 낱말 수준(반가사유상)을 짚었다.

### 주제

- **주제가 첫 사람을 정하지 않는다.** 「한국에서 영어 쓰기」는 늘 라이언이 먼저 묻다가(`first="ryan"`), 2026-11-08부터 장면이 정한다(`first=None`). 외국인이 도움을 청하면 라이언, 내가 인사하거나 도와주겠다고 하면 내가 먼저다. 대본 규칙의 「도움을 청하는 사람이 말을 시작한다」가 이것을 지킨다. 주제 설명에 「내가 먼저 말을 걸 수 있다」를 쓰고, 목록에도 내가 먼저인 상황을 하나 이상 둔다.
- **주제를 넓히면 「그 밖의 상황」 설명도 고친다.** 「그 밖의 상황」은 두 주제가 아닌 것이다. 한쪽을 넓히고 그대로 두면 같은 장면이 두 주제에 다 든다.
- **주제 ID는 바꾸지 않는다.** 지난 기록의 `topic`에 남아 있다. 이름만 바꾼다.

## 겪은 문제와 해결

### 이름과 설명을 넓혀도 제이크 추천은 예를 따라간다

- 증상: 설명(`scenes_en`)에 인사와 가벼운 이야기를 넣었다. 그런데 예(`example_ko`)가 도움 요청(「인사동에서 … 한복 빌리는 곳을 묻는 상황」)이면, 추천 14개 가운데 인사·이야기는 2개뿐이었다.
- 원인: 추천 메시지에 예가 하나 들어가고, 모델은 그 예와 같은 갈래로 쏠린다. 반대로 최근 상황은 그 갈래에서 밀어낸다. 지금 사용자 기록은 도움 요청뿐이다.
- 고친 것: 예를 넓힌 쪽 장면(「한강공원에서 아침 운동하다 마주친 외국인과 인사를 나누는 상황」)으로 바꿨다. 같은 조건에서 인사·이야기가 5개, 도움 요청이 9개로 섞였다.
- 같은 실수를 막는 법: 주제를 넓히면 예도 다시 고른다. 최근 상황을 지금 기록과 같은 쪽으로 채운 경우와 빈 경우를 함께 센다. 최근 상황이 비면 예를 바꿔도 도움 요청 쪽으로 쏠렸다(7개 가운데 인사·이야기 1~2개). 쓰기 시작한 뒤 기록이 쌓이면 섞임이 달라질 수 있다.

### 추천 문장 앞에 이상한 말이 붙었다

- 증상: 추천 한 사슬(7개)에서 「제이가 제안해요, 서울숲에서 …」처럼 문장 앞에 말이 붙은 것이 3번 나왔다. 다른 두 사슬(14개)에서는 0번이었다. 제이크 목소리로 들으면 이상하다.
- 원인: 확인하지 못했다. 할 일 27(「제가 …」로 시작하는 추천)과 같은 갈래로 보인다. 그때는 105번에 0번이라 지시문을 고치지 않았다.
- 고친 것: 이 카드에서는 세 주제가 같이 쓰는 지시문을 고치지 않았다. 처리는 main 세션에서 사용자에게 묻고 있다(devlog에 결과를 적는다).
- 같은 실수를 막는 법: 추천을 셀 때 문장 맨 앞을 읽는다. `check_jake_recommend.py`의 `odd_start`는 「제가」, 「제이크」만 찾아서 「제이가」를 놓친다.

## 확인 방법

- 시험: `cd server && uv run pytest -q tests/test_topics.py`. 이름과 ID, 장면 낱말, 목록 순서와 첫 사람, 대본과 통역이 지키는 사실, 설명에 든 지어낸 값을 본다.
- 실제 모델(돈이 든다): `cd server && uv run python scripts/check_topic_scenes.py [--runs 2] [--presses 7] [--recent filled|empty] [--example 글] [--scripts]`
  - 추천을 「다른 걸로요」처럼 사슬로 받고, `--scripts`면 지어낸 직접 쓰기 상황과 추천으로 대본을 쓴다.
  - 줄마다 아는 사람(`KNOWN`), 한국 밖(`ABROAD`), 긴 낱말(`hard:`)을 표시한다. 장면의 갈래(도움 요청, 인사)와 첫 사람이 맞는지는 읽어서 센다.
  - Sonnet으로 추천 하나 약 0.004달러, 대본 하나 약 0.005~0.01달러다. 2026-11-08 세 번 돌려 추천 35개, 대본 9개에 0.19달러였다.
