# PROMPT 모델이 쓰는 문장에 정해진 말투를 섞기

> 2026-11-08 jake-recommend-endings(PR #38)에서 정하고 겪은 것

모델(Claude)이 쓰는 문장 끝을 몇 가지 정해진 꼴 가운데 하나로 섞고 싶을 때의 기준이다. 예: 제이크 추천 「…상황을 골라 봤어요.」, 「…상황을 추천해요.」, 「…상황으로 연습해 볼까요?」를 무게 2, 2, 1로 섞는다.

## 정한 기준

- **고르는 것은 서버가 한다.** 지시문에 꼴을 다 늘어놓고 모델이 고르게 하면 한쪽으로 쏠리고, 「이것은 가장 드물게」 같은 비율을 지킬 수 없다. 서버가 무게를 두고 하나 골라(`random.choices`) 메시지에 넘기면 비율이 코드로 정해지고 시험으로 지킬 수 있다. 호출 수는 같다.
- **바로 되풀이하지 않기:** 사용자가 「다른 걸로요」로 다시 받을 때 같은 꼴이 이어지면 섞은 느낌이 나지 않는다. 방금 거절한 문장의 꼴을 빼고 고른다. 이렇게 하면 가장 드문 꼴의 몫이 조금 오른다(무게 2, 2, 1이면 오래 이어질 때 25%).
- **지시문에는 고를 꼴을 하나도 넣지 않는다.** 꼴을 보여 주는 예도 넣지 않는다. 짜임을 설명할 때는 꼴이 없는 말로 한다(「상황 앞의 말은 묻는, 주문하는 같은 낱말로 끝난다」).
- **주제의 예문에서도 꼴을 뺀다.** 예문이 한 꼴로 끝나면 그 꼴로 끌린다. 예문은 「…상황」까지만 쓴다.
- **어긴 답은 다시 부르지 않고 고친다.** 꼴 앞의 말이 어느 꼴에도 맞게 짜여 있으면(여기서는 「…묻는 상황」 + 끝말), 답 끝의 꼴을 모두 걷어 내고 고른 꼴 하나를 붙인다. 꼴은 정해 둔 글자로 찾지 않고 짜임으로 찾는다. 여기서는 마지막 「상황」 뒤의 짧은 꼬리(「상황」이 다시 없고, 「요」로 끝나고, 띄어쓰기와 끝 부호를 빼고 열 글자 이하)다. 알 수 없는 끝은 그대로 쓰고 로그에 남긴다. 로그에는 문장을 쓰지 않는다.
- **거절한 문장의 꼴도 같은 방법으로 알아본다.** 갈아 끼우는 쪽과 「바로 되풀이하지 않기」가 꼴을 다르게 알아보면, 한쪽이 놓친 꼴이 다른 쪽에서도 새어 같은 소리가 이어진다. 들리는 것은 마지막 낱말이니, 꼬리가 어느 꼴의 마지막 낱말로 끝나는지로 본다.

## 겪은 문제와 해결

### 꼴을 넘겨도 모델이 다른 꼴로 썼다

- **증상:** 하이쿠에 「끝말: 상황을 골라 봤어요.」를 넘겼는데 스물한 번 가운데 네 번 「…상황을 추천해요.」로 끝났다. 한 번은 「상황으로연습해 볼까요?」처럼 띄어쓰기를 뺐다.
- **원인:** 네 번 모두 「…추천해요.」로 끝난 거절 문장들 뒤였다. 메시지에 함께 넘긴 문장들의 꼴을 따라갔다. 지시문의 짜임 예도 「…상황을 추천해요.」로 끝났다.
- **고친 것:** 서버가 알려진 꼴을 고른 꼴로 갈아 끼운다(그때는 `server/je_server/claude.py`의 `swap_ending`, 지금은 `strip_endings`).

### 지시문의 예를 쓰고 꼴을 또 붙였다

- **증상:** 갈아 끼우기를 넣은 뒤 다시 돌리니 끝은 모두 맞았지만, 네 번은 「…상황을 추천해요. 상황으로 연습해 볼까요?」처럼 꼴이 둘 붙었다.
- **원인:** 지시문의 짜임 예 「"…묻는"과 "상황을 추천해요."가 "…묻는 상황을 추천해요."가 된다」를 그대로 쓰고, 넘긴 꼴을 뒤에 또 붙인 것으로 보았다.
- **고친 것:** 지시문에서 꼴이 든 예를 빼고 「상황 앞의 말은 제 끝말이 없다」, 「끝말은 맨 끝에 한 번」, 「넘긴 문장들의 끝말을 따라 쓰지 않는다」를 적었다. 갈아 끼우기는 끝의 알려진 꼴을 하나가 아니라 모두 걷어 낸다. 세 번째 시험은 스물한 번 모두 모델이 그대로 지켰다.

### 정해 둔 꼴만 알아봐서 섞인 꼴이 새어 나갔다 (2026-11-08, PR #38 머지 뒤)

- **증상:** 머지 뒤 원래 폴더 서버에 추천을 두 번 받았다. 첫째가 「…볼까요?」로 끝나서 서버는 둘째에 다른 꼴을 넘겼는데, 둘째는 「…상황을 연습해 볼까요?」로 끝나 「볼까요」가 연달아 들렸다. 세 번의 스크립트 시험(예순세 번)에서는 나오지 않았다.
- **원인:** 모델이 「상황을」과 「연습해 볼까요?」를 섞었다. 서버는 꼴 셋과 옛 꼴을 글자 그대로(띄어쓰기만 느슨하게) 찾아서, 이 꼴을 몰라 그대로 넘겼다. 「바로 되풀이하지 않기」도 `endswith`로 꼴을 찾아서, 끝 부호가 없거나 다른 거절 문장(「…추천해요」, 「…추천해요!」)을 알아보지 못했다.
- **고친 것:** 꼴을 짜임으로 찾는다. 마지막 「상황」 뒤가 「상황」 없이 「요」로 끝나고 띄어쓰기와 끝 부호를 빼고 열 글자 이하면 꼴로 보고 걷어 낸다(`strip_endings`). 열 글자는 서버가 알던 가장 긴 꼴(옛 「으로 연습해 보면 어때요」)의 길이고, 「…상황에서 주문하는 연습을 해 볼까요?」(열세 글자)처럼 상황이 앞에만 있는 문장은 걸리지 않는다. 꼴 앞에 「상황」이 한 번 더 남은 것(「…묻는 상황 상황을 골라 봤어요.」)도 걷는다. 거절한 문장은 꼬리가 어느 꼴의 마지막 낱말로 끝나는지로 알아본다(`heard_ending`). 끝말만 온 답은 로그에 「상황이 없음」으로 따로 적는다.
- **같은 실수를 막는 법:** 모델이 정해진 꼴을 어길 때는 글자 하나만 다른 꼴이 아니라 둘을 섞은 꼴도 나온다. 꼴 목록을 늘리지 말고, 꼴이 놓이는 자리와 길이로 찾는다. 걸리면 안 되는 문장(꼴 자리가 아닌데 같은 낱말이 든 것)을 시험에 함께 둔다.

### 시험 스크립트가 어김을 지킨 것으로 셌다

- **증상:** 스크립트가 「모델이 쓴 글과 서버가 말한 글이 같으면 지킴」으로 셌다. 서버는 알 수 없는 끝을 그대로 말하므로, 어긴 답도 지킴으로 세어졌다(마지막 리뷰가 찾음).
- **고친 것:** 말한 글이 고른 꼴로 끝나는지를 먼저 보고, 그다음에 모델 글과 같은지 본다(`label`, 시험 `server/tests/test_check_jake_recommend.py`).

## 같은 실수를 막는 방법

- 지시문에 예를 넣을 때는 그 예의 낱말까지 모델이 따라 쓴다고 본다. 모델이 고르면 안 되는 것(꼴, 장면)은 예에도 넣지 않는다. 장면도 같은 이유로 지시문에 두지 않고 주제의 예문에서만 온다(상황 주제 스펙 4).
- 메시지에 함께 넘기는 문장(최근 상황, 거절한 상황)도 모델을 끈다. 그 문장들의 꼴을 따르지 말라고 적고, 서버 쪽 고치기로 막는다.
- 실제 모델 시험의 셈은 결과(말한 글) 기준으로 먼저 센다. 서버가 그대로 넘기는 경우가 있으면 「모델 글 == 말한 글」은 지킴의 증거가 아니다.

## 확인 방법

- `cd server && uv run pytest -q tests/test_claude.py -k "ending or recommend"`: 무게(씨앗을 둔 5000번), 거절한 꼴 빼기(끝 부호가 없거나 다른 것, 섞인 꼴), 옛 꼴, 갈아 끼우기(다른 꼴, 띄어쓰기, 겹친 꼴, 섞인 꼴, 끝 부호, 겹친 「상황」), 걸리면 안 되는 긴 꼬리, 끝말만 온 답의 로그, 지시문에 꼴이 없는지.
- 실제 모델: `cd server && uv run python scripts/check_jake_recommend.py [--model haiku|sonnet]`. 주제 셋마다 「다른 걸로요」를 일곱 번 누르듯 스물한 번 부르고, 줄마다 고른 꼴과 「model kept / swapped / MISSED」를, 끝에 끝말별 수, 연달아 같은 끝말, 비용을 낸다. 서버처럼 지어낸 최근 상황 열 개를 함께 보낸다(2026-11-08 더함). 문장 맨 앞이 상황이 아니라 말하는 사람이면(「제가 …」, 「제이크가 …」) 줄에 `odd start`를 표시하고 끝에 수를 낸다. 제이크 목소리로 들으면 제이크가 그 일을 하는 것처럼 들린다. 상황 안의 학습자(「카페에서 제가 시킨 …」)는 세지 않는다. 2026-11-08 Sonnet으로 지어낸 입력 63번, 실제 최근 상황 42번(맥 안에서만 돌림)에서 0번이라 지시문은 고치지 않았다. 다시 보이면 지시문에 「상황으로 바로 시작한다」를 넣는 쪽이 낫다. 서버가 맨 앞 「제가」를 걷으면 상황 안의 학습자(「제가 묵는 호텔에서 …」)까지 지운다. 모델은 추천 모델(`JE_CLAUDE_RECOMMEND`, 기본 Sonnet)이고, 스물한 번에 Sonnet은 6.5센트쯤, Haiku는 0.3센트쯤이다. 돌리기 전에 사용자에게 횟수와 비용을 알린다.
