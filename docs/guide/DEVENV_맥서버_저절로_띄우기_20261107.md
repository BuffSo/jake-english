# 맥 서버를 저절로 띄우기 (launchd)

> 작성: 2026-11-07
> 관련 결정: ADR-0012(launchd 사용자 에이전트), ADR-0007(Tailscale 주소에만 붙기)
> 개인 값(홈 폴더 경로, Tailscale 주소)은 비공개 메모에만 둔다.

맥을 다시 켜거나 서버가 죽어도 맥 서버가 저절로 뜨게 했다. macOS에 들어 있는 launchd 사용자 에이전트를 쓴다. 로그인하면 서버를 띄우고, 죽으면 다시 띄운다. 이 문서는 그때 정한 기준, 카드가 서버를 시험할 때 쓰는 명령, 겪은 문제를 담는다. 다른 프로젝트에서 같은 일을 할 때 이 문서만 읽으면 되게 썼다.

## 정한 기준

### launchd 사용자 에이전트로 띄운다

- 에이전트 파일: `~/Library/LaunchAgents/dev.jakeso.english.server.plist`. 이름은 앱 고유 ID(ADR-0008)를 따른다.
- 설치: 원래 폴더나 worktree 어디서든 `server/scripts/autostart.sh install`을 실행한다. 에이전트는 언제나 원래 폴더(`git worktree list`의 첫 줄)의 `server/`를 띄운다.
- 설치하기 전에 원래 폴더에 `server/.env`가 있어야 하고, `uv`, `ffmpeg`, `whisper-server`를 셸에서 찾을 수 있어야 한다. 하나라도 없으면 아무것도 쓰지 않고 멈춘다.
- 홈 폴더 경로는 설치할 때 채운다. 에이전트 파일은 저장소에 넣지 않는다(공개 저장소). 이 맥의 실제 값은 비공개 메모에 적는다.
- 에이전트 파일에 넣는 것과 이유:

| 키 | 값 | 이유 |
|---|---|---|
| `ProgramArguments` | `<uv 위치> run python -m je_server` | 손으로 띄울 때와 같은 명령. 머지로 의존 패키지가 바뀌면 `uv run`이 잠금 파일대로 맞춘다 |
| `WorkingDirectory` | 원래 폴더의 `server/` | worktree가 지워져도 상관없게 |
| `EnvironmentVariables` → `PATH` | `uv`, `ffmpeg`, `whisper-server`가 있는 폴더 + `/usr/bin:/bin:/usr/sbin:/sbin` | launchd는 셸 설정을 읽지 않는다(아래 「겪은 문제」) |
| `RunAtLoad` | true | 로그인할 때 띄운다 |
| `KeepAlive` | true | 어떤 이유로 끝나든 다시 띄운다 |
| `ProcessType` | `Interactive` | 비우면 CPU와 디스크 읽기를 조금 줄인다(아래 「겪은 문제」) |
| `StandardOutPath`, `StandardErrorPath` | `~/Library/Logs/jake-english/server.log` | 손으로 띄울 때와 같은 곳 |

- 다시 띄우는 간격(`ThrottleInterval`)은 기본값을 둔다. launchd는 같은 작업을 10초에 한 번보다 자주 띄우지 않는다. 서버가 10초 넘게 돌다 죽으면 바로 다시 뜬다. 시작하자마자 죽는 경우(예: `.env`가 틀림)에만 10초 간격이 걸린다.
- 설치하면 맥이 「백그라운드 항목이 추가됨」을 알릴 수 있다. 시스템 설정 → 일반 → 로그인 항목 및 확장 프로그램의 「백그라운드에서 허용」에서 이 항목을 끄면 서버가 뜨지 않는다. 켜 둔다.

### 명령

| 명령 | 하는 일 |
|---|---|
| `server/scripts/autostart.sh install` | 에이전트 파일을 쓰고 서버를 띄운다. 이미 있으면 바꿔 쓴다 |
| `server/scripts/autostart.sh stop` | 서버를 멈춘다. `start`를 하거나 다음에 로그인할 때까지 멈춰 있다. 서버가 다 끝날 때까지 기다렸다 돌아온다 |
| `server/scripts/autostart.sh start` | `stop`으로 멈춘 서버를 다시 띄운다 |
| `server/scripts/autostart.sh restart` | 도는 서버를 끄고 새로 띄운다. 머지한 뒤 새 코드를 띄울 때 쓴다 |
| `server/scripts/autostart.sh status` | 도는지(`state`), 프로세스 번호(`pid`), 띄운 횟수(`runs`), 마지막 종료 코드(`last exit code`) |
| `server/scripts/autostart.sh uninstall` | 서버를 멈추고 에이전트 파일을 지운다 |
| `server/scripts/autostart.sh plist` | 설치할 에이전트 파일을 화면에만 보여 준다 |

- 안에서는 `launchctl bootout`(stop), `bootstrap`(start), `kickstart -k`(restart), `print`(status)를 부른다. 대상은 `gui/<사용자 번호>/dev.jakeso.english.server`다.
- 스크립트 없이 되돌리기: `launchctl bootout gui/$(id -u)/dev.jakeso.english.server && rm ~/Library/LaunchAgents/dev.jakeso.english.server.plist`

### 카드가 서버를 시험할 때

원래 폴더 서버를 `kill`로 끄면 launchd가 곧바로 다시 띄워 포트를 잡는다. `nohup`으로 원래 폴더에서 따로 띄우면 launchd 서버와 포트를 두고 다툰다. 그래서 아래 순서로만 끄고 켠다.

1. 사용자가 폰으로 쓰는 중인지, 다른 카드가 서버를 시험하는 중인지 사용자에게 알리고 묻는다.
   - 폰이 USB에 꽂혀 있지 않아도 사용자는 Tailscale로 앱을 쓸 수 있다. 2026-11-08 서버를 바꿔 둔 20분 사이 사용자가 폰으로 새 대화를 하나 하고 녹음도 보냈다(three-line-listen). 바꾼 서버가 main과 같게 돌아 문제는 없었지만, 서버 쪽 동작을 크게 바꾼 브랜치라면 사용자의 기록이 그 코드로 남는다. 다른 카드가 시험 중인지만 묻지 말고, 사용자가 폰을 쓰는지도 묻는다. 바꾸는 동안 생긴 기록 중 내가 만든 것만 치운다. 폰 녹음이 든 시험 기록은 지우지 않고 옮겨 둔다(아래 4).
2. `server/scripts/autostart.sh stop`으로 원래 폴더 서버를 멈춘다. 서버가 받아쓰기와 목소리 프로세스까지 다 끝낸 뒤에 돌아온다.
3. 원래 폴더의 `server/.env`를 worktree의 `server/`에 복사하고, worktree의 `server/`에서 서버를 띄운다.

   ```sh
   nohup uv run python -m je_server >> ~/Library/Logs/jake-english/server.log 2>&1 &
   ```

4. 시험이 끝나면 worktree 서버를 끈다(그 `uv` 프로세스에 `kill`). 그리고 `server/scripts/autostart.sh start`로 원래 폴더 서버를 되돌린다.
   - worktree 서버는 실제 앱 데이터 폴더에 쓴다. 폰으로 녹음한 시험 대화는 지우지 말고, 앱 데이터 폴더 밖의 임시 폴더로 옮겨 사용자가 넘어갈 때까지 둔다. 녹음이 없는 시험 대화는 지운다(`DEVENV_폰을_adb로_시험하기_20261108.md` 「폰 시험 녹음은 사용자가 넘어간 뒤 지운다」).
5. 머지한 뒤에는 원래 폴더의 main을 fast-forward하고 `server/scripts/autostart.sh restart`로 새 코드를 띄운다. `status`의 `state = running`과 로그 끝의 `Uvicorn running on`을 본다.

- worktree 서버에 폰 없이 녹음을 보내 시험하는 방법은 `DEVENV_폰없이_녹음_시험하기_20261108.md`.
- `start`를 잊으면 다음에 로그인할 때 다시 뜬다. 하지만 그때까지 폰이 붙지 못하니 꼭 되돌린다.
- worktree 서버가 아직 포트를 쥔 채 `start`해도 된다. launchd 서버는 모델을 불러오지 않고 포트가 빌 때까지 기다린다(아래 「Tailscale보다 먼저 떠도 기다린다」). 5분마다 오류 한 줄을 남기고 다시 뜨며 기다리다가, worktree 서버를 끄면 곧 뜬다.

#### launchd 서버를 멈추지 않고 시험하기 (2026-11-08 더함)

폰으로 확인할 것이 없고 서버 요청으로만 시험할 때는 원래 폴더 서버를 멈추지 않아도 된다. 폰과 다른 카드는 그대로 원래 폴더 서버를 쓴다. 위 1의 「사용자에게 묻기」도 필요 없다.

1. 띄우기 전에 `lsof -nP -iTCP -sTCP:LISTEN`으로 빈 포트 둘을 고른다. 원래 폴더 서버가 8787(서버)과 8788(받아쓰기)을 쓴다. **8790은 피한다.** 다른 도구가 쓰는 포트다. 2026-11-08 시험 서버를 `127.0.0.1:8790`에 띄웠다가, 그 포트로 가는 요청을 시험 서버가 받을 수 있다는 것을 다른 카드가 알려 줬다. 8791과 8792를 썼다.
2. 앱 데이터 폴더(`~/Library/Application Support/jake-english`의 `roleplays/`, `audio/`, `saved.json`)를 임시 폴더에 복사한다. 시험 역할극이 사용자의 「지난 상황」에 남지 않고, 소리 저장소가 있어 같은 글의 소리는 바로 나온다. **녹음은 빼고 세 항목만 복사한다.** 녹음은 사용자 목소리라 정한 곳 밖에 두지 않는다(`REVIEW.md` 「녹음 처리」). 시간을 재는 데는 필요 없다. 녹음은 두 곳에 있다. 역할극마다의 `roleplays/*/rec/`, 그리고 서버가 받아쓰는 동안 잠깐 두는 `tmp/`다. 데이터 폴더를 통째로 복사하면 `tmp/`가 따라온다(PR #34 리뷰가 짚음). `audio/`는 서버가 만든 소리(라이언, 제이크, 소희의 목소리)라 맥 안에서만 쓰고 5에서 지운다.

   ```sh
   D="$HOME/Library/Application Support/jake-english"
   rsync -a --exclude 'rec/' "$D/roleplays" "$D/audio" "$D/saved.json" <임시 폴더>/data/
   ```

   복사하기 전에 `rsync -anv`(복사하지 않고 목록만 보기)로 `/rec/`와 `tmp/`가 없는지 볼 수 있다.
3. worktree의 `server/`에서 환경 변수로 `server/.env`의 값을 덮어 띄운다. 서버는 `server/.env`보다 환경 변수를 앞세운다(`config.load_settings`).

   ```sh
   JE_HOST=127.0.0.1 JE_PORT=8791 JE_WHISPER_PORT=8792 JE_DATA_DIR=<복사한 폴더> \
     uv run python -m je_server >> <임시 폴더>/server.log 2>&1
   ```

   받아쓰기와 목소리 프로세스를 하나씩 더 띄우므로 메모리가 넉넉할 때 쓴다(받아쓰기 모델이 3GB 남짓).
4. 앱과 같은 요청을 `http://127.0.0.1:8791`로 보낸다. 토큰은 `server/.env`의 값을 읽어 쓰고 출력에 남기지 않는다.
   - 앱처럼 `/home?tip=1`로 물으면 그 서버의 기록 폴더에서 그날 섀도잉 한마디가 쓰인다(2026-11-08). 서버가 떴는지만 볼 때는 원래 폴더 서버든 시험 서버든 `tip` 없이 `/home`을 부른다.
5. 끝나면 그 서버를 끄고(띄운 프로세스에 `kill`), 두 포트가 비었는지 다시 본다. 복사한 폴더는 지운다.
   - 폰을 이 서버에 붙여(`adb reverse`) 폰으로 녹음했으면 폰 시험 녹음이 복사한 폴더에 들어 있다. 서버만 끄고 복사한 폴더는 사용자가 넘어갈 때까지 남긴다(`DEVENV_폰을_adb로_시험하기_20261108.md` 「폰 시험 녹음은 사용자가 넘어간 뒤 지운다」).


### Tailscale보다 먼저 떠도 기다린다

- 서버는 맥의 Tailscale 주소에만 붙는다(ADR-0007). 로그인하자마자 launchd가 서버를 띄우면 Tailscale이 아직 주소를 받지 못했을 수 있다.
- 서버는 설정을 읽은 바로 뒤, 받아쓰기와 목소리를 불러오기 전에 그 주소와 포트에 붙어 본다(`server/je_server/listen.py`의 `wait_for_address`).
  - 주소가 아직 없거나(`EADDRNOTAVAIL`) 포트를 누가 쓰고 있으면(`EADDRINUSE`) 2초마다 다시 본다.
  - 5분 동안 붙지 못하면 오류를 남기고 끝난다(종료 코드 1). launchd가 곧 다시 띄우고, 다시 기다린다. 모델을 불러오기 전이라 이 반복은 가볍다.
  - 주소가 IPv4 형식조차 아니면(예: 글자가 섞임) 기다리지 않고 uvicorn이 오류로 알리게 둔다.
- **왜 5분에 끝내나:** 형식은 맞지만 맥에 없는 주소(예: `server/.env`의 숫자 하나를 잘못 적음, Tailscale 주소가 바뀜)는 늦게 뜬 Tailscale과 똑같이 `EADDRNOTAVAIL`로 실패한다. 붙어 보는 것만으로는 둘을 가를 수 없다. 끝없이 기다리면 `status`는 `state = running`인데 아무도 8787을 듣지 않는 서버가 된다(PR #26 리뷰가 짚음). 5분마다 끝내면 `status`의 `last exit code = 1`과 늘어나는 `runs`, 로그의 오류 줄로 드러난다. Tailscale은 로그인하고 몇십 초 안에 뜨니 5분이면 넉넉하다.
- 로그에는 기다리기 시작할 때 `waiting to bind JE_HOST:JE_PORT (address not on this Mac yet)` 또는 `(port in use)`, 붙을 수 있게 되면 `JE_HOST:JE_PORT free after Ns`가 남는다. 5분에 끝날 때는 `could not bind JE_HOST:JE_PORT for 300s (…); check JE_HOST in server/.env and that Tailscale is on`이 남는다. 주소 값은 남기지 않는다.
- **이 오류가 되풀이되면:** Tailscale이 켜져 있는지, `server/.env`의 `JE_HOST`가 맥의 Tailscale 주소와 같은지 본다. 고친 뒤 `server/scripts/autostart.sh restart`.

### 로그인하기 전에는 뜨지 않는다

- 사용자 에이전트는 사용자가 로그인한 뒤에만 돈다. Tailscale 맥 앱도 로그인한 뒤에만 돈다(`DEVENV_맥을_집밖_서버로_준비하기_20261105.md` 「첫 설정의 「Start at login」 스위치가 켜지지 않는다」).
- 그래서 맥이 업데이트나 정전으로 다시 켜지면, 누가 로그인할 때까지 집 밖에서 붙지 못한다. 2026-11-05에 그대로 두기로 정했다(사용자 판단). 로그인하면 Tailscale과 서버가 함께 뜨고, 서버는 Tailscale을 기다린다.

## 겪은 문제와 해결

### launchd는 셸의 PATH를 쓰지 않는다

- **문제:** launchd가 띄운 프로그램의 PATH는 `/usr/bin:/bin:/usr/sbin:/sbin`뿐이다. 셸 설정(`.zshrc` 등)을 읽지 않는다. homebrew로 깐 `ffmpeg`와 `whisper-server`는 `/opt/homebrew/bin`에 있어서, 그대로 두면 서버가 받아쓰기를 띄우지 못하고 소리를 바꾸지 못한다. 서버의 `server/.env`도 `JE_WHISPER_SERVER=whisper-server`처럼 이름만 적어 PATH에 기댄다.
- **고친 것:** 설치할 때 셸에서 `command -v`로 세 도구의 위치를 찾아, 그 폴더들을 에이전트의 PATH 앞에 넣는다. 서버가 띄우는 받아쓰기와 목소리 프로세스도 이 PATH를 물려받는다.
- **확인:** 목소리 프로세스의 PATH를 본다.

  ```sh
  ps eww -p "$(pgrep -f tts_worker.py)" | tr ' ' '\n' | grep '^PATH='
  ```

  받아쓰기는 지어낸 문장으로 시험한다. 녹음이 아니라 `say`가 만든 소리라 남겨도 되지만, 다 쓰면 지운다.

  ```sh
  say -o probe.aiff "Could we move the meeting to Friday afternoon?"
  afconvert -f m4af -d aac probe.aiff probe.m4a
  curl -s -H "Authorization: Bearer <토큰>" --data-binary @probe.m4a "http://<맥의 Tailscale 주소>:8787/transcribe"
  rm probe.aiff probe.m4a
  ```

### 서버가 주소에 붙기 전에 모델부터 불러온다

- **문제:** uvicorn은 앱의 시작 단계(lifespan)를 마친 뒤에 주소에 붙는다. 이 서버는 시작 단계에서 받아쓰기(whisper-server, large-v3 모델)와 목소리 프로세스를 띄운다. 그래서 Tailscale 주소가 아직 없으면, 둘을 다 불러온 뒤에야 주소에 붙지 못해 끝난다. launchd는 그것을 10초마다 다시 띄운다. Tailscale이 꺼져 있는 동안 내내 큰 모델을 불렀다 내리기를 되풀이한다.
- **고친 것:** 위 「Tailscale보다 먼저 떠도 기다린다」. 설정을 읽은 바로 뒤에 붙을 수 있는지 먼저 본다.
- **확인:** 맥에 없는 주소(문서용 주소 `192.0.2.1`)로 띄우면 기다린다는 줄만 남고 whisper-server가 뜨지 않는다. 시험은 `server/tests/test_listen.py`(5분에 끝나는 것도 시험한다).

### `launchctl bootout`은 서버가 다 끝나기 전에 돌아온다

- **증상:** `bootout` 바로 뒤에 `launchctl print`는 `state = SIGTERMed`를 보였다. 서버 포트(8787)는 이미 비었지만, `uv`, 파이썬, whisper-server, 목소리 프로세스가 아직 끝나는 중이었다. 이때 카드가 worktree 서버를 띄우면, 옛 whisper-server가 받아쓰기 포트(8788)를 쥐고 있어 새 whisper-server가 `whisper-server exited`로 실패할 수 있다.
- **고친 것:** `stop`(그리고 `install`, `uninstall`)은 `bootout` 뒤에 `launchctl print`가 실패할 때까지, 곧 launchd가 작업을 놓을 때까지 0.5초마다 기다린다. 30초를 넘기면 멈추고 알린다. launchd는 20초(`ExitTimeOut` 기본값) 안에 끝나지 않으면 강제로 끝낸다.
- **확인:** `stop`이 돌아온 바로 뒤 `lsof -nP -iTCP:8787,8788 -sTCP:LISTEN`이 비어 있고, `pgrep -fl "je_server|whisper-server|tts_worker"`에 아무것도 없어야 한다. 2026-11-07에는 0.5초 만에 돌아왔고 둘 다 비어 있었다.

### `ProcessType`을 비우면 CPU와 디스크 읽기를 줄인다

- **문제:** `man launchd.plist`의 `ProcessType`: 「If left unspecified, the system will apply light resource limits to the job, throttling its CPU usage and I/O bandwidth.」 터미널에서 띄울 때보다 받아쓰기와 목소리가 느려질 수 있다. 학습자가 기다리는 대답이다.
- **고친 것:** `Interactive`로 둔다. 「앱과 같은 제한, 곧 제한 없음」이다.

### 서버가 죽거나 다시 뜰 때 받아쓰기와 목소리 프로세스가 남지 않는다

- **확인한 것:** 서버 파이썬을 `kill -KILL`로 죽이자 4초 뒤 새 서버가 포트에 붙었다. `status`는 `runs = 2`, `last exit code = 137`(강제 종료)이었다. 옛 whisper-server와 목소리 프로세스는 남지 않고 새것만 있었다. launchd는 작업이 끝나면 같은 프로세스 그룹에 남은 것을 정리한다.
- `restart`(`kickstart -k`)와 `stop`에서는 로그에 `Application shutdown complete.`가 남았다. `uv run`이 받은 종료 신호를 파이썬에 넘겨, 서버가 받아쓰기와 목소리를 스스로 끄고 끝난 것이다.

### 시험 서버를 이름으로 끄다 원래 폴더 서버까지 껐다 (2026-11-09)

- **증상:** 카드가 옆 포트에 띄운 시험 서버를 `pkill -f je_server`로 껐다. 원래 폴더 서버도 같은 명령 줄(`python -m je_server`)이라 함께 꺼졌다. launchd가 곧바로 다시 띄워 4초쯤 뒤 다시 받았다(`status`의 `runs`가 하나 늘고 `last exit code = 143`). 그 사이 폰 요청이 있었다면 실패했을 것이다. 같은 때 다른 카드의 시험 서버가 떠 있었다면 그것도 꺼졌다.
- **원인:** 시험 서버와 원래 폴더 서버, 다른 카드의 서버는 모두 같은 명령으로 뜬다. 이름으로 찾는 `pkill -f`, `killall`은 그 셋을 가르지 못한다.
- **막는 법:** 시험 서버는 그 서버가 쥔 포트로 찾아 끈다. `kill "$(lsof -nP -t -iTCP:<시험 포트> -sTCP:LISTEN)"`처럼 한다. 띄울 때 프로세스 번호를 적어 두고 그 번호에만 보내도 된다. 끈 뒤에는 `autostart.sh status`의 `runs`가 그대로인지 본다.

## 확인 방법 모음

- 도는지: `server/scripts/autostart.sh status`, `lsof -nP -iTCP:8787 -sTCP:LISTEN`(Tailscale 주소만 보여야 한다), 로그 끝의 `Uvicorn running on`.
- 죽였을 때: `kill -KILL "$(lsof -nP -t -iTCP:8787 -sTCP:LISTEN)"` 뒤 몇 초 안에 새 프로세스가 포트에 붙고 `runs`가 하나 는다.
- 로그아웃했다가 다시 로그인했을 때: 로그인하고 잠시 뒤 `status`가 `state = running`이고 로그에 새 `Started server process` 줄이 있다.
- 폰: 집 밖(모바일 데이터)에서 앱을 열어 첫 화면이 뜬다.
