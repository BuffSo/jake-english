# 커밋 전 자동 검사

> 작성: 2026-11-04
> 구현: `.githooks/`(git 훅), `scripts/`(검사), `scripts/lib/`(규칙), `scripts/hooks/guard-git.mjs`(Claude Code 훅)
> 규칙 원문: `AGENTS.md` 「커밋 전 자동 검사」

이 저장소는 나중에 공개한다. 그런데 커밋마다 사람이 diff를 보지 않고, 커밋과 push는 에이전트가 묻지 않고 한다. 그래서 「개인 정보, 개인 환경, 녹음, 키를 커밋하지 않는다」는 규칙을 글로만 두지 않고 장치로 막는다. 이 문서는 그 장치를 만들며 정한 기준과 겪은 문제를 담는다. 다른 프로젝트에서 같은 검사를 만들 때 이 문서만 읽으면 되게 썼다.

## 정한 기준

### 네 겹으로 둔다

| 겹 | 언제 도나 | 무엇을 막나 |
|---|---|---|
| git pre-commit | 커밋 직전 | 스테이징한 파일의 비공개 금지어, 홈 폴더 절대 경로, 내부 주소, 키와 토큰 형식, 개인 이메일, 녹음, `docs/private/`와 `.env` 파일. 작성자와 커미터 주소 |
| git commit-msg | 메시지를 쓴 뒤 | AI 서명 줄, Conventional Commits 첫 줄 형식, 메시지 속 공개 금지 값 |
| git pre-push | push 직전 | main으로 가는 「작은 문서 커밋」이 아닌 커밋, force push, 원격 브랜치 지우기 |
| Claude Code PreToolUse 훅 | 명령을 실행하기 직전 | git 훅을 건너뛰는 길(`--no-verify`, `-n`, `git -c core.hooksPath=…`, 훅 폴더가 걸리지 않은 저장소), AI 서명이 든 커밋 명령. 커밋이면 pre-commit과 같은 검사를 미리 돌린다 |

- **git 훅이 중심이다.** 사람이든 서브에이전트든 다른 에이전트든, 누가 커밋해도 걸린다. `core.hooksPath`로 걸어서 worktree에도 같이 걸린다.
- **Claude Code 훅을 더한 이유:** git 훅은 `--no-verify` 한 단어로 건너뛸 수 있다. 막힌 에이전트가 건너뛰려 할 수 있어서, 그 길을 명령 단계에서 막는다. 다른 에이전트에는 이 겹이 없어서 `AGENTS.md`에 글로 적었다.
- **커밋 메시지도 검사한다.** 메시지도 기록으로 공개된다.

### 검사를 끝내지 못하면 막는다

금지어 목록이 없거나 파일을 읽다 오류가 나면 통과시키지 않는다. 통과시키면 검사를 한 번도 하지 않은 커밋이 조용히 생긴다.

### 녹음은 확장자가 아니라 파일 머리로 찾는다

확장자만 보면 이름을 바꾼 녹음이 빠져나간다. 그래서 파일의 첫 몇 바이트를 본다. WAV, AIFF, MP3, FLAC, Ogg, CAF, WebM과 MKV, MP4와 M4A 계열을 알아본다. MP4 계열 머리를 쓰는 이미지 형식(HEIC, AVIF 등)은 뺀다.

### 금지어 목록은 비공개 폴더에 두고, 원래 폴더의 것을 읽는다

- 목록 자체가 민감 정보다. 무엇을 숨기는지가 드러난다. 그래서 `docs/private/sensitive-terms.txt`에 두고 git에서 뺀다.
- worktree에는 이 파일이 없거나 옛 복사본이 있다. `git rev-parse --path-format=absolute --git-common-dir`로 원래 폴더를 찾아 그곳의 목록을 읽는다.
- 한 줄에 하나를 쓴다. 보통 줄은 대소문자를 가리지 않는 부분 일치다.
- 짧은 이름을 부분 일치로 넣으면 그 글자가 든 다른 낱말까지 걸린다. 그런 이름은 `re:`로 시작하는 정규식 줄로 쓰고 낱말 경계를 준다(예: `re:\bXYZ\b`).
- 흔한 영어 낱말과 철자가 같은 이름은 목록에 넣을 수 없다. 그런 노출은 사람이 읽어서 막는다.
- 걸린 값은 화면에 그대로 찍지 않는다. 목록의 몇 번째 줄인지(`private-term#N`)만 보인다.

### 개인 이메일은 전역 git 설정에서 읽는다

전역 git 이메일은 개인 메일인 경우가 많다. 검사가 `git config --global user.email`을 읽어 막으므로 목록에 따로 적지 않아도 된다. 허용하는 주소는 GitHub noreply 주소와 `example.com` 같은 예시 도메인뿐이다.

### noreply 주소는 작성자와 커미터를 둘 다 본다

저장소 설정의 `user.email`만 보면 `--author`나 `GIT_AUTHOR_EMAIL`로 빠져나간다. pre-commit 안에서 `git var GIT_AUTHOR_IDENT`와 `git var GIT_COMMITTER_IDENT`를 읽으면, 이런 덮어쓰기가 반영된 값이 나온다(시험해서 확인했다).

### 걸리면 값을 지운다

규칙을 끄거나 예외를 늘려서 통과시키지 않는다. 형식으로 찾는 검사라 문맥으로 새는 노출은 다 잡지 못한다(아래 마지막 문제). 「공개 저장소」 규칙은 검사와 별개로 지킨다.

## 겪은 문제와 해결

### 검사기가 자기 시험 파일을 막았다

- **증상:** 준비 커밋 전에 전체 파일 검사(`--all`)를 돌리자 시험 파일이 걸렸다.
- **원인:** 시험 파일에 막혀야 할 값을 예시로 그대로 썼다. AI 서명 줄의 이메일 주소, 비공개 금지어와 같은 낱말이었다.
- **고친 것:** 막혀야 할 값은 실행할 때 조립한다(예: `["someone", "private.org"].join("@")`). 비공개 금지어는 예시로도 쓰지 않고 지어낸 낱말을 쓴다.
- **막는 방법:** 훅 통합 시험이 이 저장소의 `scripts/`를 임시 저장소에 복사해 실제로 커밋해 본다. 그래서 시험 파일이 검사를 통과하는지도 함께 드러난다.

### Claude Code 훅은 명령을 실행하기 전의 스테이징을 본다

- **증상:** `git rm --cached <파일> && git commit …`이 막혔다. 막힌 이유는 바로 그 명령으로 빼려던 파일이었다.
- **원인:** PreToolUse 훅은 명령이 실행되기 전에 돈다. 그때 스테이징에는 아직 그 파일이 있다.
- **고친 것:** 스테이징을 바꾸는 명령과 커밋을 따로 실행한다. `CLAUDE.md` 「커밋 가드 훅」에도 적었다.

### 임시 저장소 시험이 바깥 git 설정을 물려받는다 (미리 막은 것)

- **위험:** 시험이 사용자의 전역 git 설정(이메일, 훅 경로)을 읽으면 맥마다 결과가 달라진다. 또 git 훅 안에서 시험을 돌리면, git이 넘긴 `GIT_DIR` 같은 변수 때문에 바깥 저장소를 건드릴 수 있다.
- **한 것:** 시험용 전역 설정 파일을 만들어 `GIT_CONFIG_GLOBAL`로 넘기고, `GIT_CONFIG_NOSYSTEM=1`로 시스템 설정을 끊는다. 물려받은 `GIT_`로 시작하는 변수는 모두 뺀다(`scripts/hooks.test.mjs`의 `gitEnv`).

### 첫 커밋 전에는 훅을 시험할 커밋이 없다

- `git hook run <훅 이름>`은 커밋이 없어도 `core.hooksPath`의 훅을 돌린다. commit-msg는 `-- <메시지 파일>`로, pre-push는 `--to-stdin=<입력 파일> -- <원격 이름> <주소>`로 입력을 준다.
- main 규칙처럼 원격과 커밋 기록이 필요한 시험은, 임시 폴더에 복제하고 bare 저장소를 원격으로 붙여서 했다.
- pre-push 입력은 한 줄에 `<로컬 ref> <로컬 sha> <원격 ref> <원격 sha>`다. 로컬 sha가 0으로만 되어 있으면 원격 브랜치 지우기, 원격 sha가 0이면 새 브랜치다. 원격 sha가 로컬에 없으면 force push인지 판단할 수 없어서, 막고 `git fetch`를 하라고 알린다.

### push 전 검사가 한글 이름의 가이드를 막았다

- **증상:** 이 가이드를 작은 문서 커밋으로 main에 올리기 전에, push 전 검사가 이 파일을 「작은 문서 파일이 아니다」라고 볼 것을 찾았다. 시험으로 재현하니 실제로 막혔다.
- **원인:** git은 파일 이름에 ASCII가 아닌 글자가 있으면, 이름을 따옴표로 감싸고 그 글자를 8진수(`\355\225\234…`)로 바꿔 내놓는다(`core.quotePath`, 기본으로 켜져 있다). push 전 검사는 `git diff-tree --name-only`의 출력을 줄 단위로 읽어 `docs/guide/…md` 규칙과 비교했다. 바뀐 이름은 따옴표로 시작해서 맞지 않았다. 커밋 전 검사는 처음부터 `-z`를 써서 문제가 없었다.
- **고친 것:** `diff-tree`에 `-z`를 붙여 그대로의 이름을 NUL 문자로 나눠 받는다. 한글 이름의 가이드만 고친 커밋이 main에 올라가는지 보는 시험을 더했다. 시험이 먼저 실패하는 것을 본 뒤에 고쳤다.
- **막는 방법:** git이 내놓는 파일 목록을 읽을 때는 언제나 `-z`로 받아 `\0`으로 나눈다. 시험의 파일 이름에는 한글처럼 ASCII 밖의 글자를 하나 이상 넣는다.

### 형식 검사가 못 잡은 노출: 대화를 그대로 옮긴 문서

- **증상:** 2026-11-04 PR #1에서 사용자가 어느 외부 서비스에 가입했는지가 devlog와 커밋 메시지에 들어갔다. 커밋 전 검사는 통과했다.
- **원인:** devlog에 사용자 말을 그대로 옮겼고, 그 말에 계정 이야기가 있었다. 검사는 낱말과 형식만 본다. 계정이 있다, 없다 같은 문장은 어떤 형식에도 걸리지 않는다. 게다가 pr-review는 문서만 바꾼 PR을 건너뛴다(스킬의 고정 동작). 이 PR에서 막을 수 있는 건 사용자가 읽는 것뿐이었고, 사용자가 찾아냈다.
- **고친 것:** 파일과 PR 본문은 요약으로 바꿨다. 이미 올라간 커밋 기록에는 남았다. 지우려면 force push가 필요한데 규칙이 금지하고, 그렇게 해도 GitHub가 PR에 묶인 옛 커밋을 남겨 둘 수 있어서 그대로 두었다.
- **막는 방법:** devlog와 커밋 메시지에는 대화를 옮기지 않고 요약한다(`docs/devlog/README.md` 「쓰지 않는 것」). `REVIEW.md`는 계정 정보를 지적할 개인 환경으로 꼽는다. 문서만 바꾼 PR에는 리뷰어가 없다는 것을 알고 쓴다.

## 확인 방법

- **전체 시험:** `node --test 'scripts/**/*.test.mjs'`(2026-11-04 기준 54개 통과). 임시 저장소를 만들어 훅마다 막히는 것과 통과하는 것을 실제 git으로 돌린다.
- **전체 파일 검사:** `node scripts/check-sensitive.mjs --all`. 추적 중인 파일과 새로 더할 파일 전체를 본다. 공개로 바꾸기 전에 돌린다.
- **훅이 걸려 있는지:** `git config core.hooksPath`가 `.githooks`여야 한다. 새로 클론했으면 `git config core.hooksPath .githooks`부터 한다. 걸려 있지 않으면 Claude Code 훅이 커밋을 막고 이 명령을 알려 준다.
- **일부러 걸리는 커밋:** 금지어가 든 파일, 확장자를 바꾼 녹음, noreply가 아닌 작성자(`--author`), 형식이 틀린 첫 줄, AI 서명 줄, `--no-verify`를 하나씩 시험해 막히는지 본다. 끝나면 스테이징에서 빼고 시험 파일을 지운다.
