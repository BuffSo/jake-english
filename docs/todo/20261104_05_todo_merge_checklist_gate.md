## 왜 하나

PR 1번에서 본문의 테스트 체크리스트가 커밋과 어긋났고, 사용자가 짚어서 고쳤다. 지금은 체크 안 된 항목이 남은 채로도 머지할 수 있다. 사용자가 「모든 체크리스트가 체크되어야 머지할 수 있도록 강제할 수도 있고, 이건 좀 더 검토해 보자」고 했다.

## 같이 정할 것

- **체크 안 된 항목을 어떻게 볼지:** 지금 `AGENTS.md` 「PR과 머지」는 「아직 하지 않은 것(폰에서 확인 등)은 `[ ]`로 남긴다」고 한다. 폰 설치처럼 머지한 뒤에만 할 수 있는 확인도 있다. 강제하려면 이 규칙부터 바꿔야 한다. 예: 체크리스트에는 머지 전에 할 것만 두고, 머지 뒤에 할 것은 「한계」와 `docs/todo/`로 옮긴다.
- **PR 본문을 커밋에 맞추는 규칙:** 「PR에 커밋을 더하거나 계획을 바꾸면 본문의 한계, 테스트 체크리스트, 문서 절도 맞춘다」를 `AGENTS.md`에 넣을지 함께 정한다.

## 막는 방법 후보

1. **GitHub에서 막기:** GitHub Actions로 PR 본문에 `- [ ]`가 있으면 실패하는 검사를 만들고, 그 검사를 통과해야 머지되게(필수 상태 검사) 한다.
   - GitHub 무료 요금제에서는 비공개 저장소에 브랜치 보호와 ruleset을 쓸 수 없다고 알고 있다(공개 저장소에서는 된다). 무료 요금제라면 비공개인 동안은 검사가 실패로 보일 뿐 머지 버튼을 막지 못한다. 만들기 전에 요금제와 GitHub 문서를 다시 확인한다.
   - 비공개 저장소의 Actions는 요금제마다 정해진 월 무료 분량 안에서 돈다.
2. **Claude Code에서 막기:** 커밋 가드 훅처럼 `gh pr merge` 직전에 본문을 보고 `- [ ]`가 있으면 막는다. 에이전트에게 머지를 맡길 때만 걸리고, 사용자가 GitHub 화면에서 누르는 머지는 막지 못한다.
3. **규칙만 두기:** 머지 결정을 물을 때 체크 안 된 항목을 따로 보여 준다.
