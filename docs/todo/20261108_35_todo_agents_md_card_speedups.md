## 할 일

1. **리뷰가 도는 동안 기다리지 않는다:** 브랜치 최종 리뷰와 pr-review가 도는 동안 devlog와 PR 본문을 먼저 쓰고, 리뷰에서 고친 것과 남긴 것은 리뷰가 끝난 뒤 더한다. `AGENTS.md` 「작업 일지: devlog」의 「언제」(지금은 「PR 리뷰로 고친 뒤 … 커밋한다」)를 이에 맞게 고친다.
2. **화면 자리나 모양을 묻는 질문은 처음부터 후보 그림과 함께:** 카드가 사용자에게 화면을 물을 때(main 세션을 거쳐), 자리와 모양 후보를 그린 초안을 첫 질문에 함께 보낸다. `AGENTS.md` 「카드의 질문과 머지는 main 세션을 거친다」의 「사용자가 봐야 하는 화면 초안」 줄에 더한다.
3. **지우는 명령은 빈 변수 경로를 쓰지 않는다:** `rm -rf $SP/*.png`처럼 변수로 쓴 경로는 Claude Code가 「빈 변수일 수 있는 경로」로 보고 사용자 확인 창을 띄운다. 그동안 카드가 멈추고 사용자가 봐야 한다. `"${SP:?}"/x` 꼴이나 글자 그대로의 경로로 쓴다. Claude Code에만 있는 동작이라 `CLAUDE.md`에 두고, 시험 정리 명령이 많은 `docs/guide/DEVENV_폰을_adb로_시험하기_20261108.md`에도 한 줄 넣는다.
4. 규칙 문서라 PR로 올린다.
