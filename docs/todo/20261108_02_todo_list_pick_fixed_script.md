## 왜 하나

2026-11-08 offscript-aside 폰 시험 중에 사용자가 「미국 여행」의 같은 목록 상황(운동화 사이즈)을 여러 번 골랐다. 고를 때마다 소넷이 대본을 새로 써서 시작이 늦고, 쓴 대본은 거의 같았다(첫 대사와 마지막 대사가 세 번 다 같았다). 목록 설명이 자세해서 쓸 내용이 거의 하나로 정해지고, API는 무작위성 설정(temperature)을 받지 않는다.

사용자는 이렇게 말했다. 「목록을 제공한다고 결정했을때는.. 다시 ai 에 대화를 만들어내는게 아니고 대화 내용을 정해두고 그걸 바로 보여주자고 하지 않았나? 그러면 토큰도 아낄수 있고」, 「이건.. 지금 수정해야 할거 같은데」.

기록은 다르다. 상황 주제 스펙(`docs/superpowers/specs/2026-11-07-situation-topics-design.md`)의 「하지 않을 것」에 「대본을 미리 써 두기. 목록에는 상황만 쓰고, 대본은 지금처럼 고를 때마다 Claude가 새로 만든다」가 AI 판단 표시 없이 들어 있다. 그때 남은 사용자 말은 「이런 것들을 미리 작성해 놓으면 어떨까?」뿐이다. 오늘 PRD의 「다르게 말하면 대본을 새로 만든다」처럼, 뜻이 다르게 받아들여진 채 넘어간 것으로 보인다.

## 할 일 (AI 추천, 사용자 확인 필요)

1. 목록의 상황은 대화를 정해 둔다. 처음 고를 때 한 번만 대본, 읽는 법, 본보기 소리를 만들고, 다음부터는 그것을 그대로 꺼낸다. 이미 있는 「이 상황 다시 하기」(`Engine.copy`, ADR-0011)와 같은 방식이면 Claude를 부르지 않고 바로 시작한다.
   - 됨: 사용자가 「ㅇㅋ」로 정했다. `Engine.create_pick`이 저장소의 대본으로 만들고, 같은 목록 줄의 지난 회차에서 원본 ID와 읽는 법, 본보기 소리, 통역을 가져온다.
2. 대본을 손으로 고쳐 저장소에 둘지, 처음 만든 것을 맥에 남겨 쓸지 정한다. 저장소에 두면 실제 가게와 메뉴 같은 사실을 사람이 확인할 수 있다.
   - 됨: 사용자가 「추천대로 해줘」로 저장소에 두기로 정했다(`server/je_server/topics.py`). 읽는 법과 소리는 처음 고를 때 맥이 만들어 기록에 남긴다.
3. 「지난 상황」 목록에서 같은 목록 상황을 한 줄로 묶을지 정한다.
   - 됨: 같은 목록 상황의 회차를 원본 ID로 묶어, 화면을 고치지 않고 한 줄이 된다. 이 변경 전의 목록 기록은 따로 남는다.
4. 상황 주제 스펙의 「하지 않을 것」과 PRD 「목록에서 고르기」를 고친다. 바꾼 이유(위 사용자 말)를 함께 쓴다.
   - 됨: 두 문서를 고치고 새 스펙을 가리켰다.
