# TODO: PR 본문에 「위험」과 「되돌리는 법」 넣기

> 작성: 2026-11-11
> 상태: **완료** (2026-11-11, PR #87. 정할 것 1은 모든 PR에 넣되 문서만 바꾼 PR은 한 줄씩 써도 되게, 2는 넣기로 정했다. PR #87 본문에서 처음 써 봤다)

## 왜

- 「How the Claude Code team does code review」(https://claude.dev/blog/solving-code-review-at-anthropic/, 2026-10-15)에 나오는 방식이다. 그 팀의 PR 서식은 「어떻게 시험했나」와 「어떻게 되돌리나」를 묻는다. 글 끝의 「도입하는 법」은 PR 서식에 「Testing」, 「Risk」, 「How to revert」를 넣으라고 한다.
- 그 팀은 Claude가 이 칸을 채워도, 변경을 요청한 사람이 확인한다.
- 지금 `AGENTS.md` 「PR과 머지」의 PR 본문은 `## 요약`, `## 배경`, `## 한계`, `## 테스트 체크리스트`, `## 문서`다. 「테스트」는 있고 「위험」과 「되돌리는 법」은 없다. 「머지 준비 됨」 알림에도 없다.
- 사용자가 2026-11-11에 같은 글에서 나온 개선 후보 셋(평가 세트, 리뷰 횟수 상한, 이것)을 모두 넘기기로 정했다.

## 할 것 (안)

- PR 본문에 두 절을 더한다.
  - `## 위험`: 이 변경이 잘못되면 무엇이 깨지나. 예를 들어 녹음 처리, 맥 서버 보안, 공개 저장소 노출(`REVIEW.md` 「반드시 지적할 것」의 분야)에 닿는지 적고, 닿지 않으면 「낮음」과 이유를 한 줄로 쓴다.
  - `## 되돌리는 법`: 머지 커밋을 되돌리는 것 말고 할 일이 있는지 쓴다. 예를 들어 맥 서버를 다시 띄워야 하나, 앱을 다시 빌드해 깔아야 하나, 저장된 기록이나 설정이 바뀌어 되돌려도 남는 것이 있나.
- 「머지 준비 됨」 알림에 위험을 한 줄 넣어, 사용자가 머지를 정할 때 본다.

## 정할 것 (사용자에게 물을 것)

1. 두 절을 모든 PR에 넣을지, 문서만 바꾼 PR은 뺄지.
2. 「머지 준비 됨」에 위험을 한 줄 넣을지.

## 끝났다고 보는 기준

- `AGENTS.md` 「PR과 머지」의 PR 본문 목록에 두 절이 있다. 규칙 문서라 PR로 고친다.
- 다음 PR 하나에서 실제로 써 봤다.
