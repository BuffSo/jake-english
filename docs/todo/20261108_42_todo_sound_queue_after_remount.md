## 본 것

- 사용자가 「라이언 목소리가 에코 되어 나온다」고 했다. 폰 기록(logcat의 `APM_AudioPolicyManager` startOutput/stopOutput)을 보니 21:45:08에 라이언 소리(24kHz) 둘이 서로 다른 재생 세션에서 0.6초 차이로 시작했다. 길이는 3.52초와 3.44초로 거의 같았다. 1.7초짜리 다음 줄도 0.55초 차이로 두 번 났다. 첫 화면 인사 두 줄이 두 번씩 난 것이다.
- 그 직전에 카드가 `adb install -r`로 앱을 다시 깔고 곧바로 `monkey`로 띄웠다.
  - 21:45:07.95에 monkey가 MainActivity를 띄웠다.
  - 21:45:08.80에 삼성의 업데이트 뒤 다시 열기(systemui `PackageUpdateActivity`, `CorePackageUpdate`)가 같은 앱을 새로 띄우고 앞의 것을 닫았다(`finish-clear-task`).
  - 같은 프로세스에서 앱 화면이 두 번 그려졌다. 앞 화면의 소리 대기열(`app/src/audio/player.ts`의 플레이어)은 그 화면이 닫힌 뒤에도 이미 넣어 둔 인사 두 줄을 끝까지 틀었다.
  - 그 뒤의 소리(주제 화면 말)는 한 세션에서만 났다.
- 사용자가 처음 에코를 들은 것은 카드가 폰을 쓰기 전, 21:25~21:28에 사용자가 직접 역할극을 할 때였다. 그 시각의 폰 기록은 남아 있지 않아(가장 이른 줄이 21:37) 같은 까닭인지 확인하지 못했다. 그 앞에 카드가 main 판 앱을 `install -r`와 `monkey`로 깔고 띄운 적이 있다.

## 할 것

1. 화면(앱 뿌리)이 사라질 때 그 화면의 소리 대기열을 비우고 플레이어를 멈추는지 본다(`useSounds` 같은 곳의 정리 함수). 없으면 더한다.
   - (2026-11-08 함) 없었다. 앱 뿌리(`App.tsx`)가 사라질 때 `SoundQueue.close()`를 부르게 했다. 대기열을 비우고 폰의 플레이어를 놓으며, 닫은 뒤에 들어온 소리는 버린다. 앞 뿌리가 닫히기 전에 청한 인사가 닫힌 뒤에 와서 울린 경우까지 막는다. React Native는 화면(Activity)이 닫힐 때 앱 뿌리를 내린다(`ReactDelegate.onHostDestroy`의 `unloadApp()`).
2. 앱이 두 번 떠서 뿌리가 둘인 채로 남는 경우가 있는지 본다. 21:25~21:28처럼 역할극 중에도 겹친다면 대기열 정리만으로는 모자란다.
   - (2026-11-08 하지 않기로 함) 사용자가 「내가 들은 에코는 신경 쓰지 마, 개발 과정에서 앱 띄우다 발생한 것 같으니까」라고 했다. 개발 중 앱을 다시 띄울 때만 생기고, 폰 시험 가이드(할 것 3)로 막는다.
3. (PR #60에서 함) 폰 시험 가이드(`docs/guide/DEVENV_폰을_adb로_시험하기_20261108.md`)에 적는다: 삼성 폰은 `install -r` 뒤 앱을 저절로 다시 띄우므로, 깐 뒤 곧바로 `monkey`를 부르지 않는다. 몇 초 기다려 앞의 앱을 보고, 없을 때만 띄운다. 또는 `am force-stop` 뒤 한 번만 띄운다.
