## 왜

- Claude Code 팀은 사고를 낸 지난 PR을 모아 리뷰어의 평가 세트로 쓴다. 리뷰어의 프롬프트, 도구, 모델이 바뀔 때마다 그 세트로 다시 채점한다. 출처는 「How the Claude Code team does code review」(https://claude.dev/blog/solving-code-review-at-anthropic/, 2026-10-15)의 「How we make the reviewer better」 절이다.
- 이 저장소는 리뷰가 놓친 문제를 `REVIEW.md` 「반드시 지적할 것」에 규칙으로 옮긴다(「고치는 방법」). 하지만 그 PR에 리뷰를 다시 돌려서 이제는 잡는지 확인하지는 않는다. 그래서 `pr-review` 스킬이나 `REVIEW.md`를 고친 뒤에도 같은 문제를 정말 잡는지 모른다.
- 사용자가 2026-11-11에 같은 글에서 나온 개선 후보 가운데 이것부터 하기로 정했다.

## 정할 것 (사용자에게 물을 것)

1. **돌리는 방법.** `pr-review`는 1번 단계에서 닫힌 PR을 건너뛰고, 끝나면 PR 코멘트를 자동으로 단다. 머지된 PR에 다시 돌리려면 코멘트를 달지 않고 그 PR의 diff로 리뷰하는 평가 방식이 필요하다. 전역 스킬을 고치는 일이므로 어떻게 고칠지 먼저 사용자 승인을 받는다.
2. **세트를 둘 곳.** 사례를 설명하다 보면 기록이나 받아쓰기에서 온 낱말이 다시 들어갈 수 있다. 사례 본문과 기대 결과의 세부는 `docs/private/`에 두고, 커밋하는 문서에는 PR 번호와 「잡아야 함 / 걸러야 함」만 쓴다.
3. **언제 돌리나.** `pr-review` 스킬이나 `REVIEW.md`를 고칠 때, 리뷰에 쓰는 모델이 바뀔 때.
4. **사용량.** `pr-review` 한 번에 Sonnet 서브에이전트가 15~25개쯤 뜬다(스킬 단계 수로 어림). 사례 6개를 한 바퀴 돌리면 그 여섯 배다. 돈은 들지 않지만(사용 크레딧 꺼짐) 주간 한도를 쓴다. 처음에는 잡아야 하는 것 2개와 걸러야 하는 것 1개로 시작하는 것을 권한다.

## 끝났다고 보는 기준

- 사례마다 「잡아야 함 / 걸러야 함」, 기대 결과, 지금 스킬의 결과(점수, 게시 여부)를 적은 표가 있다.
- 스킬이나 `REVIEW.md`를 고친 뒤 같은 세트로 다시 돌려 전과 비교할 수 있다. 돌리는 방법은 가이드에 적는다.
