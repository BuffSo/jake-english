# TODO: 녹음 중 알리기(PR record-feedback)의 남은 작은 것

> 작성: 2026-11-08
> 상태: **완료** (1~5는 PR #59, 6은 PR #60에서 고침)

브랜치 최종 리뷰(record-feedback 카드)가 Minor로 남긴 것이다. 스펙 `docs/superpowers/specs/2026-11-08-record-feedback-design.md`.

1. **시작 소리가 난 뒤 마이크가 켜지지 않을 때:** `useRecorder.start`에서 `playCue("start")` 뒤 `recorder.record()`가 실패하면, 시작 소리는 났는데 화면은 말없이 「🎤 말하기」로 돌아간다. 취소 소리도 안내도 없다. 준비(`prepareToRecordAsync`)가 먼저 실패하는 일이 대부분이라 드물다. 고칠 것: `record()` 실패에 취소 소리를 내고, 대화 화면의 시작 실패(`"failed"`, 권한 거부 포함)에 「마이크를 쓸 수 없어요…」를 보인다(상황 정하기 화면은 이미 한다). 스펙 1의 「마이크를 켜지 못했을 때(오류 글이 나온다)」는 대화 화면에는 아직 맞지 않는다.
2. **알림 소리 크기:** 가장 큰 값(-6 dBFS)만 맞췄다. 사인파라 평균 크기가 라이언 목소리보다 클 수 있다. 라이언 소리와 평균 크기(RMS)를 견주거나 폰에서 듣고, 크면 0.25~0.3으로 낮춘다(`cueSound.ts`).
3. **저절로 취소가 잠깐 막기에 걸리면 다시 하지 않는다:** `levelPoll`은 한 번 부르면 다시 부르지 않는데, `runThenHold`가 `tapHold` 중이면 아무것도 하지 않는다. 지금은 녹음 중에 막기를 거는 곳이 없어 생기지 않는다. 나중에 막기를 거는 곳이 생기면 문제가 되니 그 자리에 한 줄 주석을 둔다(`RoleplayScreen.tsx`의 `silentCancel`).
4. **「녹음이 곧 끝나요」가 `keepWords`를 거치지 않는다:** 짧아서 줄이 바뀌지 않지만 APP 가이드의 규칙대로 감싼다(`StopButton.tsx`의 `SoonEnds`).
5. **시작이 실패해도 첫 차례 안내가 사라진다:** `recordStart`가 마이크가 켜지기 전에 `micUsed`를 켜고, 권한 거부나 시작 실패 뒤 `recordCancel`이 되돌리지 않는다. 그 대화에서는 「🎤를 누르고 말하세요」가 다시 나오지 않는다(PR #53 pr-review의 보고하지 않은 관찰 N1). 1과 함께 고치면 좋다.
6. **시끄러운 방에서 「8초 쉬면 저절로 끝」이 안 된다 (2026-11-08 main 세션 더함):** play-button-feedback의 폰 확인에서 주변 소리가 계속 말소리 기준을 넘어, 시험 녹음 하나가 8초 쉼에서 끝나지 않고 55초까지 갔다. 말소리로 보는 크기 기준(앱의 마이크 크기 기준값)을 다시 본다. 예: 녹음을 켠 처음 잠깐의 바닥 소리를 재고 그보다 몇 dB 큰 것만 말소리로 본다. 5초 취소가 말소리를 놓쳐 녹음을 버리지 않는 것도 함께 지킨다. 폰에서 맥 스피커로 주변 소리(지어낸 잡음)와 학습자 목소리 녹음을 틀어 잰다.
   - 고친 것(PR #60): 쉼을 깨는 말소리는 -45와 「방의 바닥 소리 + 14 dB」 중 큰 쪽 이상이어야 한다. 바닥 소리는 마이크가 켜지고 0.7초 뒤부터 읽은 값의 아래 20분의 1 자리이고, 1초어치가 모이면 내려가기만 한다. 5초 취소는 -45 그대로다. 폰에서 지어낸 환풍기와 웅성거림 속 녹음이 말 끝 7~8초 뒤에 끝났다. 옆 사람 대화 속에서는 55초까지 간다(스펙 「한계」).
   - **leftover-minors 카드가 읽은 것 (2026-11-08):**
     - 기준은 `app/src/flow/speechWatch.ts`의 `SPEECH_RULE`(`level: -45`, `loudMs: 300`, `waitMs: 5000`, `skipMs: 300`, `endMs: 8000`)과 `createSpeechWatch`다. 크기는 `app/src/audio/levelPoll.ts`가 0.1초마다 읽는다(안드로이드는 지난 읽기 뒤 가장 큰 값, -160은 「못 읽음」으로 버림).
     - 8초 쉼 끝이 안 되는 까닭: `level` 이상인 읽기 하나마다 `lastLoud`가 새로 잡혀 8초를 처음부터 센다. 방 소리가 0.1초 가장 큰 값으로 -45를 자주 넘으면 끝나지 않고 55초까지 간다. 같은 까닭으로 말하지 않아도 방 소리만으로 0.3초가 모이면 「말소리」가 되어 5초 취소도 걸리지 않는다.
     - 가이드 `docs/guide/APP_녹음_중_알리기_20261108.md`에 2026-11-08 폰에서 잰 값이 있다: 조용한 방 -55~-63(가끔 -30까지 튐), 맥 스피커로 튼 학습자 목소리 보통 -18~-40, 작게 -40~-50.
     - 에뮬레이터는 마이크 입력을 꺼 둬도(`hw.audioInput=no`) 녹음이 켜지고 조용한 녹음이 맥에 간다(PR #59에서 확인). 맥 소리가 들어가지 않으니 크기는 폰에서 잰다.
   - **함께 볼 것 (PR #59에서 넘어옴):** 알림 소리(시작·끝·취소)의 진폭을 반으로 낮췄다(맥에서 0.4초 크기로 라이언 대사와 같거나 작음, RMS로는 아직 2~5 dB 큼). 폰 스피커에서 라이언 목소리보다 작게 나는지는 아직 재지 않았다. 폰을 쓸 때 함께 본다(`docs/guide/APP_녹음_중_알리기_20261108.md` 「겪은 것」).
