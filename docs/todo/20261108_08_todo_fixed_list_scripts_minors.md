## 왜 하나

fixed-list-scripts PR의 브랜치 전체 리뷰가 짚었지만, 지금 쓰는 사람에게 생기는 문제가 없어 그 PR에서 고치지 않은 것이다. 스펙은 `docs/superpowers/specs/2026-11-08-fixed-list-scripts-design.md`, 결정은 ADR-0013이다.

## 할 일

1. (고침) `Engine.copy`의 `try/except KeyError`가 `create_pick` 전체를 감싼다. 지금은 저장한 뒤에 `KeyError`가 날 곳이 없지만, 나중에 생기면 목록 회차를 저장하고 복사본도 하나 더 만든다. 목록 줄을 먼저 찾고(`topics.pick`), `create_pick`은 `try` 밖에서 부른다.
2. (고침, 넷) 라이언 대사 셋이 대본 규칙(`prompts.SCRIPT_SYSTEM`)의 「한두 문장」보다 길다. 홍대 삼겹살의 첫 대사, 새우 트럭의 마지막 대사, 호텔 체크인의 마지막 대사(세 문장)다. 다듬을 때는 사실을 바꾸지 않고 `server/tests/test_topics.py`를 함께 본다.
3. (옮김, 20261108_23) `create_pick`은 고를 때마다 이벤트 루프에서 기록을 모두 읽는다(`Store.all`). 묶음이 갈리지 않게 읽기부터 저장까지 `await`를 두지 않았기 때문이다. 지금 크기에서는 0.05초 안이다. 기록이 수백 개로 늘어 고를 때 소리나 평가가 멈칫하면, 목록 줄마다 `asyncio.Lock`을 두고 읽기를 스레드로 옮긴다. ADR-0011 「영향」의 색인 파일과 함께 본다.
4. (고침, 기준 녹음 지문과 함께) PR #34 리뷰 경계선(25점): 목록 회차가 앞선 회차의 소리 키(`audio`, `ko_audio`)를 그대로 가져온다. 소리 키에는 빠르기와 판 번호(`tts.SPEAK_RATE`, `tts.MADE`)가 들어 있어, 그 값을 바꿔 소리를 새로 만들게 해도 목록 회차는 옛 소리를 계속 쓴다. 「이 상황 다시 하기」(`Engine.copy`)도 전부터 같다. 그 값을 바꿀 일이 생기면, 가져올 때 지금 키(`audio_key`)와 같은지 보고 다르면 비워 두게 한다.
5. (고침) PR #34 리뷰 경계선(35점): `u-hotel-checkin`의 주석이 지어낸 값으로 예약 이름과 체크아웃 시간만 적고, 와이파이 비밀번호가 「키 카드 봉투」에 있다는 것은 적지 않았다. 주석에 셋 다 적는다.
