# ADR-0015 앱이 쓰는 인물 그림은 저장소에 넣고, MIT 밖의 개인 사용 안내를 붙인다

- 상태: 채택
- 날짜: 2026-11-11

## 배경

- 앱에 나오는 인물 그림(라이언, 소희, 제이크의 얼굴과 생각하는 얼굴)은 지금까지 비공개 폴더(`docs/private/assets/`)에만 있었다. 맥 서버는 `server/.env`의 `JE_ASSETS_DIR`이 가리키는 폴더에서 그림을 읽어 `/assets/<이름>`으로 내준다.
- 저장소를 새로 받은 사람은 `JE_ASSETS_DIR`이 비어 있어 그림이 모두 404가 된다. 앱은 그림 자리에 라이언 색 빈 사각형과 빈 동그라미를 보여 준다.
- 그림을 비공개로 둔 것은 PRD 「첫 화면」의 결정이었다. 2026-11-04에 「라이언 얼굴 그림은 공개 저장소에 넣지 않고 비공개 폴더에 둔다」로 정했고, 2026-11-09 README에 앱 화면 사진을 넣을 때도 그림 파일 자체는 넣지 않기로 했다. 그 뒤 생각하는 얼굴, 제이크, 소희 그림을 더한 스펙과 계획도 같은 결정을 따랐다. 이 결정을 담은 ADR은 없었다.
- 한 번 push한 파일은 나중에 지워도 git 기록에 남고, 저장소를 공개하면 누구나 받을 수 있다. 되돌리기 어려운 결정이라 ADR로 남긴다.

## 검토한 안

1. **지금처럼 비공개 폴더에만 둔다.** 그림이 없으면 빈 칸 대신 이름 첫 글자(R, S, J)가 든 동그라미를 보여 준다. 그림은 공개되지 않지만, 저장소를 받은 사람이 보는 앱은 실제 앱과 다르다.
2. **앱이 쓰는 그림만 저장소에 넣고, MIT 밖의 쓰임 안내를 붙인다.** 서버가 내주는 그림(`server/je_server/app.py`의 `ASSETS`)만 넣는다. 몸 그림, 후보, 원본은 넣지 않는다.
3. **2안의 그림에 표준 라이선스(CC BY-NC-ND)를 붙인다.** 남이 읽어 바로 아는 조건이지만, 비영리라면 출처를 밝히고 그대로 다른 곳에 다시 퍼뜨리는 것은 허락하게 된다.
4. **비공개 폴더의 그림을 모두 넣는다.** 앱이 쓰지 않는 그림까지 기록에 남는다.

둘 곳과 안내를 적을 곳도 견줬다.

- 둘 곳: 그림을 내주는 서버 옆(`server/assets/`), 저장소 맨 위의 새 폴더. 앱 폴더(`app/assets/`)는 앱에 묶여 빌드되는 파일의 자리라 맞지 않는다.
- 안내: 그림 폴더의 `README.md`와 저장소 `README.md` 「라이선스」에 적는 것, `LICENSE` 파일에 줄을 더하는 것.

## 판단

- main 세션은 처음에 1안을 추천했다. 사용자는 저장소를 받아 설치한 사람도 앱이 제대로 돌고 그림이 다 보여야 한다며 그림을 넣기로 했다. 걱정은 남이 그림을 자기가 만든 것처럼 쓰는 것이었다.
- 그 뒤 main 세션은 2안과, 앱 아이콘을 MIT에서 뺀 것과 같은 틀의 안내를 추천했고 3안은 다른 길로 냈다. 사용자는 2안을 골랐다(「ㅇㅋ」, 2026-11-11). 「이 앱은 각자 자기 맥에 서버를 띄우고 자기 폰에서 쓰는 개인용」이라는 틀은 사용자가 더했다. 세 사람 그림을 모두 넣는다.
- 둘 곳은 `server/assets/`로 했다(AI 판단). 그림을 읽는 것은 서버뿐이고, 서버의 기본값과 시험이 같은 폴더를 가리킨다.
- `LICENSE` 파일은 고치지 않는다(AI 판단, main 세션 동의). GitHub는 파일 글이 표준 원문과 거의 같아야 라이선스를 알아보므로, 줄을 더하면 MIT로 표시하지 못할 수 있다. 앱 아이콘을 뺄 때도 `LICENSE`는 그대로 두고 README에만 적었다.

## 결정

- 서버가 내주는 그림(`ASSETS`)만 `server/assets/`에 넣는다. 넣을 때 PNG 안에 그림 데이터 말고 다른 정보 덩어리(글, 촬영 정보)가 없는지 본다.
- 서버는 `JE_ASSETS_DIR`이 비어 있으면 `server/assets/`를 읽는다. 값을 주면 지금처럼 그 폴더만 읽는다. 새 그림을 커밋하기 전에 맥에서 시험해 볼 때 쓴다.
- 시험(`server/tests/test_assets.py`)이 `ASSETS`의 이름마다 `server/assets/`에 PNG가 있는지, 그 폴더에 목록 밖 파일이 없는지 본다. 그림을 빼먹거나 후보를 잘못 넣으면 GitHub Actions의 서버 시험이 실패한다(ADR-0014).
- 쓰임 안내는 `server/assets/README.md`(한국어와 영어)와 저장소 `README.md` 「라이선스」에 적는다. 원본은 `server/assets/README.md`의 한국어 절이고, 영어 절과 README는 그것을 옮기거나 줄인 것이다. 고칠 때는 원본부터 고치고 나머지를 맞춘다(PR #85 리뷰가 여러 곳에 따로 적힌 안내가 어긋날 수 있다고 짚었다).
  - 이 그림들은 AI로 만들었고 MIT 라이선스에 들어가지 않는다.
  - 이 앱은 각자 자기 맥에 서버를 띄우고 자기 폰에서 쓰는 개인용이다. 그림도 그렇게 이 앱을 자기가 쓸 때만 쓸 수 있다.
  - 다른 앱, 서비스, 글, 영상에 쓰거나 자기가 만든 것이라고 하면 안 된다.
- 몸 그림, 후보, 원본, 말하는 영상은 지금처럼 비공개 폴더에 둔다. 영상을 어디에 둘지는 PRD 열린 질문 8에서 정한다.
- 이 ADR은 PRD 「첫 화면」의 2026-11-04, 2026-11-09 결정을 바꾼다. PRD는 이 ADR에 맞게 고쳤다. 그때의 스펙, 계획, 할 일, devlog는 그 시점의 기록이라 고치지 않는다.

## 영향

- 그림은 git 기록에 남는다. 나중에 지워도 옛 커밋에서 받을 수 있고, 저장소를 공개하면 누구나 받는다.
- 같은 이름으로 그림을 바꿔 넣을 때마다 옛 그림이 기록에 남고 저장소가 그만큼 커진다. 지금 11장이 약 4.7MB다. 그림은 자주 바꾸지 않는다.
- 쓰임 안내는 기술로 막는 장치가 아니다. 또 AI가 혼자 만든 그림은 저작물로 인정되지 않을 수 있어, 이 안내는 법으로 강제하는 조건이라기보다 쓰는 사람에게 알리는 글에 가깝다. 문화체육관광부와 한국저작권위원회의 「생성형 인공지능 활용 저작물의 저작권 등록 안내서」를 소개한 [법률신문 기고](https://www.lawtimes.co.kr/news/articleView.html?idxno=209882)(2025-07-18)는, 저작물은 인간의 사상이나 감정을 표현한 창작물(저작권법 제2조 제1호)이라 AI가 기계적으로 만든 산출물은 저작물의 성립요건을 갖추지 못한다고 설명한다. 이 판단은 법률 자문을 받은 것이 아니다.
- 이 맥의 서버는 `server/.env`의 `JE_ASSETS_DIR`이 아직 비공개 폴더를 가리킨다. 값을 비워 저장소 폴더 하나만 쓰게 할지는 사용자가 정한다. 비우기 전까지는 그림을 바꾸면 두 곳을 함께 바꿔야 한다.
- 폰은 그림 주소에 붙은 파일 수정 시각으로 그림을 새로 받는다. 저장소에서 파일을 받으면 수정 시각이 바뀌어, 폰이 같은 그림을 한 번 더 받을 수 있다. 받는 것뿐이라 화면은 그대로다.
