# ADR-0009 음성 합성은 맥의 기존 음성 환경에서 따로 도는 작업 프로세스로 부른다

- 상태: 채택
- 날짜: 2026-11-05

## 배경

맥 서버(ADR-0006)는 라이언과 제이크 목소리로 소리 파일을 만들어야 한다. 대사의 본보기, 라이언의 평가 말, 제이크가 말하는 추천 상황이다. 목소리는 맥에 이미 있는 로컬 음성 합성(Qwen3-TTS)과 복제 목소리로 만든다(말하기 연습 스펙 「제약」).

- 그 음성 합성은 맥의 다른 곳에 따로 만든 파이썬 가상 환경에서 돈다. 조각 나누기, 목소리 검사, 쉼 고르기 같은 처리 코드도 거기에 있다. 경로는 비공개 메모에 있다.
- 같은 모델로 답을 읽어 주는 데몬이 맥에 따로 돌 수 있다. 데몬이 받는 명령은 말하기, 멈추기, 끝내기, 상태뿐이라 소리를 파일로 만들어 주지 않는다.
- 데몬과 처리 코드는 이 저장소 밖의 전역 파일이다. 이 저장소의 일로 고치지 않기로 했다(2026-11-05 역할극 MVP 세션에 넘긴 글).
- 스펙 「제약」은 처음에 「음성 모델을 메모리에 두 번 올리지 않는다」고 정하고, 방법은 계획에서 정하기로 남겼다.

## 검토한 안

1. **데몬에 부탁한다.** 데몬에 파일로 만드는 명령이 없어, 전역 파일을 고쳐야 한다.
2. **서버의 가상 환경에 음성 라이브러리를 새로 깐다.** 같은 라이브러리가 맥에 두 벌 생기고, 버전이 갈라질 수 있다. 처리 코드는 어차피 기존 파일을 불러야 한다.
3. **작업 프로세스.** 서버가 기존 가상 환경의 파이썬으로 작은 작업 프로세스(`server/je_server/tts_worker.py`)를 띄운다. 작업 프로세스는 기존 처리 코드 파일을 모듈로 불러, 답 읽기와 같은 처리로 소리 파일을 만든다. 서버와는 표준 입출력으로 한 줄짜리 JSON을 주고받는다.

## 판단

AI가 3을 추천했고, 사용자가 계획 검토에서 받아들였다(2026-11-05).

- 3은 전역 파일을 고치지 않고, 새로 깔 것이 없고, 답 읽기와 같은 목소리 처리를 그대로 쓴다.
- 대신 답 읽기 데몬이 떠 있으면 같은 모델이 메모리에 둘 올라간다. 스펙 「제약」과 다르다. 이 맥의 메모리는 둘을 함께 올려도 넉넉하다(사양은 비공개 메모 참고). 그래서 이 차이를 받아들였다.
- 2026-11-05 시험에서 작업 프로세스는 4초 안에 떴고, 영어 한 문장을 1.0초, 한국어 한 문장을 1.6초에 만들었다.

## 결정

- 서버는 기존 음성 환경의 파이썬으로 작업 프로세스 하나를 띄운다. 파이썬과 처리 코드 파일의 경로는 `server/.env`(`JE_TTS_PYTHON`, `JE_TTS_MODULE`)에만 둔다.
- 작업 프로세스는 받은 글을 기록하지 않는다. 표준 출력에는 약속한 JSON만 쓰고, 라이브러리가 찍는 글은 표준 오류로 보낸다.
- 급한 소리(라이언의 평가 말)가 미리 만드는 소리(다음 대사의 본보기)보다 먼저 만들어진다.
- 만든 소리는 데이터 폴더의 `audio/`에 글의 해시 이름으로 두고 다시 쓴다.

## 영향

- 답 읽기가 켜져 있으면 음성 모델이 둘 올라간다. 메모리가 모자라게 되면 데몬에 파일로 만드는 명령을 더하는 안(1)을 다시 본다. 그때는 전역 파일을 고치는 일이라 따로 정한다.
- 기존 처리 코드의 이름(`voice_conf`, `Player`, `lang_chunks`, `voice_score`, `even_pauses` 등)이 바뀌면 작업 프로세스도 고쳐야 한다. 작업 프로세스가 뜨지 않으면 서버가 시작하지 않으므로 바로 드러난다.
- 서버를 클라우드로 옮기면(ADR-0006 「영향」) 이 결정도 다시 정한다.
